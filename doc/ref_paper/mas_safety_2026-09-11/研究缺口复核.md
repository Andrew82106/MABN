# API 多智能体安全：研究缺口复核

检索与核查截止：2026-09-11。状态：选题讨论材料，未定题、未开展新实验。

## 结论先行

**本轮找到的主要是值得验证的实证缺口，还不是已经成立的新算法空白。**“可读状态＋概率网络”“风险随证据升降”“追踪污染并恢复”“缺失日志下推断状态”，都已有直接先行工作。将它们换成贝叶斯网络或迁移到 MAS，不能自动构成创新。

建议只保留两个候选，且优先验证第一个：

1. **局部修复成功，会不会被监测器误当成整个团队已安全？**重点是修复后的剩余危险及解除警报的证据，不是再发明隔离、回滚或恢复。
2. **可读的安全状态，能否被证据正确修订，并真正影响预测？**重点是解释是否有实际用途，不是给隐藏向量命名。

第一个更直接体现多代理特有的分支、共享产物和修复范围问题；第二个更贴近已有 BayesTrace 的可读性—性能困境。二者目前都需要先证明普通方法确实不足，不能先指定新贝叶斯结构再寻找应用。

## 1. 本轮究竟核查了什么

### 1.1 研究边界

研究对象是通过 API 使用模型的多智能体系统。默认不取得目标模型权重、激活或隐藏推理；可使用运行层实际开放的消息、路由、工具调用、返回和权限记录。

“没有模型内部状态”不等于“只有最后一句回复”。如果部署方控制消息网关和工具层，应使用合法可得的执行证据；不能人为删除已有信息制造困难。第三方 Agent 不开放私有记忆、工具服务只返回有限结果，则属于需要明确说明的实际观察限制。

本轮优先核查三类问题：可解释状态、证据缺失与依赖、污染后的纠正与恢复；同时查传统概率监测和概念模型，防止将其他领域已经成熟的方法当作新发现。

### 1.2 证据标准

- 优先使用论文原文、正式会议／期刊页面及作者实现。预印本可以否定“从未有人提出”，但不能替代独立复现。
- “重点核读”表示阅读方法、相关实验和限制，不等于逐页通读。仅取得摘要或索引的资料另列，不据此作细节判断。
- 区分论文已提出的方法、实验实际验证的范围、作者承认的限制，以及本报告提出的推断。
- 不把问答错误、拒答、工具选择、权限违规和真实外传混成同一个“安全结果”。
- 没找到相同评测不等于没人做过；本轮不宣称穷尽全部文献，也没有运行作者代码。

本文件补充[原研究综述](./研究综述.md)，不替换原 67 项书目。本轮新发现的来源以文末外链保存，未批量新增 PDF；原 66 篇 PDF 的归档数量和校验结论不变。

## 2. 先排除容易误判为创新的方向

| 看起来可以做的点 | 已有直接反例 | 本轮判断 |
| --- | --- | --- |
| 分类器提取安全特征，再接概率网络 | R²-Guard、ShieldAgent、PL-Guard。[^1][^2][^3] | 组合本身已有；不能以“我们用 BN”区分。 |
| 给可读概念加不确定性，再用关系图纠错 | ReCBM。[^4] | 连概念关系与纠正也已有；需找到具体未解决问题。 |
| 保留可读分支，再加隐藏分支补性能 | TRACES、概念泄漏研究及 In Defense。[^5][^6][^7] | 已有直接讨论；必须说明预测究竟由哪一部分支撑。 |
| 风险能升也能降，Agent 信任能恢复 | Spark、DynaTrust；BPD 还有有符号关系。[^8][^9][^10] | 双向状态变化不是新机制。 |
| 找到污染来源，修复并重跑下游 | PropGuard、BRA-Audit。[^11][^12] | 修复闭包和局部重跑已经有人做。 |
| 防止污染在共享记忆中潜伏、重新激活 | MAPLE-Guard。[^13] | 记忆生命周期防护不是空白。 |
| 外部记录缺失，仍维护可能状态及概率 | 2022／2026 年概率轨迹表达式工作。[^14][^15] | 不能把“贝叶斯处理缺日志”当新算法。 |
| 安全评分器会错，所以再做风险校准 | Online Safety Monitoring、Noisy but Valid。[^16][^17] | 不完美评分与统计控制已有方法。 |
| 同一消息转述多次不该算独立证据 | Spark、CAGE-Cal；SARA 还处理来源洗白。[^8][^18][^19] | 可作为压力条件，不能独立立题。 |
| 放行前重新核验授权和修复证据 | CommitGuard、Cordon。[^20][^21] | “验证了再放行”也不是新点。 |

这里排除的是过宽的新颖性主张，不是否定整个研究方向。相关工作越接近，越需要在相同条件下比较，而不是只比较“无防御”。

## 3. 最接近的文献，具体把路推进到了哪里

### 3.1 可读性和性能的矛盾，不是我们独有的问题

**PL-Guard 是最直接的新反例。**它让语言模型对安全谓词给出 True/False 软分数，再交给 ProbLog 推理，输出可审查的规则链；还比较了 4、8、16、24 个谓词。作者明确承认这些分数未校准、谓词可能遗漏关键因素。它目前验证的是 XSTest 文本问答，不是工具型 MAS。其不足不能简单用“我们改成多代理”补成创新。[^3]

**TRACES 已直接展示结构特征单独使用时的性能损失。**在同一 ATBench 消融中，仅机制表示的 F1 为 67.2，完整模型为 86.3；完整模型还使用原始观察者表示。这个结果支持“命名机制未涵盖全部预测信息”，不支持“任何可读模型必然不行”。它读的是外部轨迹，不要求目标 API 模型开放激活。[^5]

**JMLR 的概念泄漏研究给出了更基础的解释。**若概念集合本来就不够预测任务，硬性只许使用这些概念会丢性能；允许连续软表示，则可能把名称之外的信息藏进去。原文建议先检查真实概念标签是否足以支持任务，再研究学习结构。这里的“泄漏”是表征夹带额外信息，不是隐私外传。[^6]

也不能简单要求消灭全部隐藏信息：In Defense 讨论概念不完备时保留残余信息与可纠正性的关系；ReCBM 已利用概念关系和不确定性修复概念。因此，新增隐藏支路、概率化、概念干预，分别都不是空白。[^4][^7]

**对原 BayesTrace 经历的推断：**之前失败可能来自概念选得不够、状态测量不准、预测结构受限，或者隐藏信息绕过解释。当前证据不能替我们判断究竟是哪一个；但足以说明问题不是只能靠“把图做得更复杂”解决。

### 3.2 安全状态、来源和授权，也已有成熟近邻

| 近邻 | 已有能力 | 不能越过的证据边界 |
| --- | --- | --- |
| R²-Guard，ICLR 2025。[^1] | 安全分类概率、知识逻辑关系、可学习权重及概率推理。 | 主要为内容安全；不能据此推出工具 MAS 的未来危险已解决。 |
| ShieldAgent，ICML 2025。[^2] | 从政策组织谓词与时序规则，通过工具核查，进行概率逻辑判断。 | 已超过“手工画个图”；规则验证仍依赖事实解释与工具证据。 |
| ProbGuard，ASE 2026。[^22] | 将环境抽象成符号状态，学习转移并预测未来违规概率。 | 状态抽象与观察条件明确；不是自动解决含糊文本的语义测量。 |
| ProvenanceGuard，重点核读 v2。[^23] | 执行前检查工具和参数是否有上下文依据、当前意图是否足够明确。 | §8 排除自由生成的文本／代码参数；依赖 Agent 自己的计划。重点是良性任务误解，不是所有恶意注入。 |
| AgentGuardian。[^24] | 从正常轨迹学习访问规则，包含多代理应用。 | 自动学习可读约束已有；罕见正常行为与自由文本语义仍是限制。 |

因此，“从文本识别授权”“给判断附证据”“学习规则”都只能是研究组件。要产生新增贡献，必须证明现有组件在某个有实际意义的条件下系统性失效，而不是只指出它们都可能犯错。

### 3.3 恢复并不是空白，恢复效果的判断仍需细分

| 近邻 | 已有能力 | 与“修复后剩余危险”的距离 |
| --- | --- | --- |
| DynaTrust。[^9] | Beta 信任更新，累积正负审计证据；隔离旧 Agent，丢弃其记忆，启动干净副本。 | 信任后验不是已经校准的下一次危害概率；不能把本地副本恢复直接当全系统恢复证明。 |
| BPD，核读新版 v2。[^10] | 有符号、时间展开的通信图，计算贡献、剪除污染通信。 | 新版主要每题完成后检测；代码恢复还将检出 Agent 切回 benign mode。不能泛称在线真实危害恢复已验证。 |
| PropGuard。[^11] | 全状态传播图、源头修复、受影响下游依赖闭包重放。 | 默认结果是在三轮交互完成后施加防御；可见消息、记忆、工具观察是重要输入。不是“只看回复也能确认全部清理”。 |
| BRA-Audit。[^12] | 预算内审计、可信检查点、阻断、回滚重跑再审计。 | 已覆盖审计与恢复决策；其暴露分数不是校准的最终危害概率。 |
| MAPLE-Guard。[^13] | 记忆写入、检索、跨 Agent 复用时检查；处理延迟激活。 | 其安全探问指标不等于危险工具已真实执行；来源和状态元数据也属于输入条件。 |
| Cordon。[^21] | 可回滚影子状态、对外效果暂存、来源链及提交前检查。 | 有真实副作用类受控工作流；保障只覆盖可拦截边界，不能撤销已经发送的信息。 |
| CommitGuard。[^20] | 授权／版本失效时阻断，新证据满足条件后重新授权；涉及共享状态和 MAS。 | 依赖可信证据、依赖关系及检查—提交边界；已明确“没观察到”不等于安全。 |
| SARA。[^19] | 保留外部动作诱导来源，后续重述不能自动获得授权。 | 已处理历史洗白；没有因此自动成为修复后剩余危害概率估计器。 |

还需修正一个容易误用的比较：HalluProp 的 Noisy-OR 迭代单调增加，是其运行前传播计算的性质，不是 Agent 真实运行时间上的修复模型。不能由这篇不做恢复，推断领域没有恢复机制。[^25]

### 3.4 概率、不完整证据和主动核验：不能忽视跨领域前作

2026 年概率轨迹表达式工作已经延续 EUMAS 2022 的部分可见 MAS 监测：给定协议和缺口条件，维护可能状态的概率。AISTATS 2026 的缺失模式条件保形预测也研究了不同缺失机制下的覆盖与加权修正。因此，“标记未知状态＋更新信念”“按缺失模式校准”不是独立创新。[^14][^15][^26]

Online Safety Monitoring 已基于外部、不完美的 verifier 校准序列告警阈值，其保证依赖校准与部署分布条件。Noisy but Valid 已利用少量金标估计评分器误差并进行总体安全认证。两者不等同于任意 MAS 的单次风险预测，但足以否定“首次承认安全评分器会错”。[^16][^17]

Post-Hoc Trajectory-Risk Certification 已在模块只暴露有限证书／二值审计时研究依赖感知联合风险界；其实验主要为两阶段 IDS 分类与归因，不是工具外传。它还提醒：错误相关性对风险的作用方向取决于风险定义，不能一概说相关性使风险变高。[^27]

ADR 则已让检测 Agent 主动查询政策、代码和安全上下文。它说明“信息不足就主动取证”已经有实际系统路线；新增可访问来源、延迟和检测成本必须与效果一起比较。[^28]

## 4. 优先候选：局部修复，会不会制造错误的全局安全判断？

以下全部是本报告提出的研究假设，不是作者已证明的结论。

### 4.1 用一个例子讲清楚

某个 Agent 把错误的发送指令放进共享材料。系统发现后，清理了当前消息；协调者报告“已修复”，其他 Agent 继续转述。可是另一条工作分支仍保留旧材料，稍后再次触发外传。

这里至少有三件不同的事：

- 大家都说已经修好；
- 某个当前产物确实经过清理；
- 所有与后续危险有关的分支和产物，已经满足恢复条件。

研究对象不是“Agent 认错了吗”，而是**监测器有没有把局部证据错误推广成全局安全证据**。多个 Agent 同意，不代表它们独立核验；不同核验者检查同一产物，也不等于检查了其他分支。

### 4.2 精确到什么程度才值得做

候选问题是：

> 在明确的消息／工具观察边界内，能否判断一次修复覆盖了哪些危险依赖，保留未核验部分的不确定性，从而减少错误解除警报，同时让真正修好的任务恢复？

“剩余风险”必须对应**给定恢复策略、后续运行范围内的明确危害**，例如模拟环境中的未授权外传；不能混为模糊的 Agent 不可信分数。已发生的不可逆损害另计，不因后续风险下降而消失。

### 4.3 文献真正留给我们的是什么

PropGuard 已有修复闭包，MAPLE-Guard 已有记忆再检查，SARA 已有来源保留，CommitGuard 已有重新授权。因而不能声称首次提出修复范围或恢复条件。[^11][^13][^19][^20]

**本轮未核验到的，是将下列问题放在同一个公平评测中检验的充分证据：**

- 将完整修复、局部修复和口头宣称修复明确区分；
- 在部署上真实存在的部分可见与延迟分支条件下，观察恢复后实际危害；
- 同时衡量错误解除警报与不必要地维持阻断；
- 证明风险估计的新增价值超过来源去重、普通恢复范围规则和现有校准。

这是**有依据的评测／问题缺口**。是否还存在方法缺口，需要结果决定。把上述条件全部堆进题目，并不会自动增加新颖性。

### 4.4 第一轮只证明什么、怎么证明、产出什么

**证明什么：**局部修复成功是否会系统性造成错误的全局降警；这种错误是否需要新的估计方法，而不是补一条规则。

**怎么证明：**对相同污染任务比较完整修复、局部修复与仅口头修复，继续执行并观察实际危害及正常任务恢复。监测器使用相同可见信息；将强全轨迹审计、来源去重与校准、简单修复范围规则及普通时序模型作为竞争解释。

**产出什么：**一份可复现的失效边界和继续／放弃判断；如果缺陷成立，再研究怎样表达修复范围及其不确定性。

### 4.5 否决条件

1. 简单“当前修复是否覆盖相关分支”的规则已经解决：不支持新概率结构，可能只是运行层工程问题。
2. 现有方法的合理组合已经解决：不另造风险网络。
3. 新方法仅多拿了权限或记忆信息：这是输入优势，不是算法优势。
4. 两种真实状态产生完全相同的可见证据：不能保证识别。应说明不可区分、保留不确定性或要求额外证据。
5. 只降低危害而使所有任务永久停摆：没有证明有用的恢复判断。

## 5. 备用候选：可读状态是真正可修订的判断依据，还是标签？

### 5.1 具体问题

例如同一个文件，甲有发送权限，乙没有。监测器原本混淆了它们。提供可靠记录并纠正“甲有权限”后，甲的判断应适当修正，但不应顺便将乙改成有权限，更不应因历史相关性把明确的未授权事实覆盖掉。

这属于**外部监测模型的信息修订**，不是对目标 LLM 内部进行因果干预，也不能证明图就是目标模型的思考过程。

### 5.2 为什么只能当备用

ReCBM 已做概念纠正，ShieldAgent 已做工具核查，PL-Guard 已做软事实推理，概念模型研究已讨论忠实性与干预。仅锁定观测值、加入主体—对象索引、补授权谓词，可能就是已有方法的正常用法。[^2][^3][^4][^6][^7]

潜在新增问题只能是：**在真实多代理安全任务中，同样的证据和纠正机会下，现有可读模型是否出现可重复的错误修订；能否用新的学习约束改善，而不靠隐藏通道补答案。**目前文献支持它值得检查，不足以支持新算法已经有空间。

### 5.3 第一轮证据逻辑

**证明什么：**显示出来的安全状态是否可靠、是否真的被预测使用，以及正确修订是否改善安全判断。

**怎么证明：**先以独立核验的状态检查这些概念是否足够表达任务；再比较学习状态及其纠正。区分“事实没识别对”“概念集合不够”“推理关系不合适”“预测绕过了概念”，不把它们都叫可读性问题。

**产出什么：**原方法失效原因的证据，以及是否值得设计新结构的决定。

若实体区分、固定已知事实或补少数规则已足够，就放弃独立立题；若真实状态本来就不够预测，先补任务定义与概念，不继续堆网络。

## 6. 为什么不建议再单立其他几个候选

**重复安全证据：**SARA、Spark、CAGE-Cal 已覆盖关键基础。更适合放进修复后判断的压力条件；最强替代是来源筛查＋独立安全核验＋已有风险校准。不能靠把共同来源画成父节点宣称新 BN。[^8][^18][^19]

**部分日志的概率监测：**已有 PTE/HMM 与缺失模式校准。若没有发现自然语言识别、缺失和部署变化共同导致普通方法失效的证据，现阶段不建议作为主创新。[^14][^15][^26]

**信息更全就能检测组合攻击：**Local Monitors Miss Compositional Harm 已研究观测不可区分和表示不匹配。在其受控分片代码实验中，拿到全部片段也不等于能识别组合语义；知道编码方式的检测器是带额外信息的上界，不能当公平基线。这既是研究先例，也是“收集全轨迹即可安全”的反例。[^29]

**绝对安全保证：**Alignment Contracts 已明确依赖效果完整可见和完整拦截等条件。若真实危害能绕过监测边界，概率图无法补回这个保证；若已有运行层能直接禁止所选危害，风险预测必须另证新增价值。[^30]

## 7. 与大论文及旧工作的关系

可以继续保留“从运行证据到风险判断，再到多代理场景”的组织逻辑，但目前只是一条叙述线。

| 已有工作 | 在候选问题中的可能作用 | 不能自动算作的贡献 |
| --- | --- | --- |
| 事件图生成 | 整理事件、来源、分支和产物的关系。 | 图可视化不是危险关系已识别。 |
| 贝叶斯风险模型 | 表达明确证据条件下的状态不确定性。 | 可计算概率不等于校准，也不等于因果。 |
| 外部观察者／特征提取 | 从 API 轨迹提取候选安全状态。 | 分类器输出不自动是可信事实。 |
| 内部探针 | 可访问本地模型时提供附加信号。 | 不作为 API 主线的必需条件。 |
| 旧实验室 | 用于可控条件和独立结果核查。 | 基建通过不等于研究假设成立。 |

优先候选对 MAS 的要求不是“多放几个 Agent”，而是证明共享产物、分支和交互使局部修复证据不能直接推出整体结论。应有能排除纯单体复杂任务效应的对照。

现阶段不扩建通用实验平台、不承诺论文篇数、不固定目标会议。先完成研究问题的否决性验证，再决定复用哪些现成基准和旧基建。

## 8. 尚未闭合的查重边界

- **UAI 2026 多代理事实核验论文**：已核实官方摘要中的风险控制与分歧处理；全文获取未成功，尚不能完整排除其证据依赖处理与候选重合。[^31]
- **OCULUS**：原站索引涉及退化日志和多代理配置，但未能完整打开 PDF。其 operational calibration 指行动适当性，不应直接当作概率校准；不以索引片段作方法级结论。[^32]
- **更强的安全续行前作**：AgentSentry 已提出工具返回边界的反事实诊断与上下文净化；本轮此项以摘要／方法概览为主。若转向新恢复算法，需进一步逐项比较。[^33]
- **传统事故恢复与分布式状态验证**：本轮补查了概率运行时验证，但不是对这整个传统领域的穷尽综述。若实际主张退化成一般分布式修复覆盖判定，需要进一步查这一条线，而不能称为 LLM 独有算法。

这些限制不影响“泛泛组合已经有人做”的判断，但会限制任何“我们找到无人做过的新算法”的主张。

## 最后判断

值得继续的不是“终于找到一个没人做过的贝叶斯方向”，而是先检验：**现有安全监测是否把局部可信证据过度推广成全局安全判断。**修复后解除警报是其中一个明确、可检验的场景。如果强现有方法已经处理好，就换问题；如果稳定失败，再研究这种失败为什么需要新的可解释状态或概率结构。
