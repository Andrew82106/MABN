# API 多智能体系统安全：文献地图与选题边界

检索截止：2026-09-11。重点覆盖 2024—2026 年，追踪至 2026 年 9 月的新预印本。

## 先读结论

多智能体安全并没有过时；但“给多 Agent 建图，再做风险监测”已经不是足够具体的新研究问题。现有工作已经涉及传播图、概率推理、轨迹预警、共享记忆防护和权限委派。需要比较的是：在怎样的信息条件下，预测什么风险，较最接近的方法新增什么能力，而不是是否用了贝叶斯网络。[From Spark to Fire](https://arxiv.org/abs/2603.04474)、[Runtime Uncertainty Monitoring](https://arxiv.org/abs/2607.25877)、[MAPLE-Guard](https://arxiv.org/abs/2608.00426)

最重要的区分是：**团队答错问题、运行中违反规则、最终造成损害，是三个不同的结果。** 论文使用 “safety”“risk”“failure”，不代表它已经验证了泄漏、越权或其他现实安全后果。[HarnessAudit](https://arxiv.org/abs/2605.14271)、[AgentLeak](https://arxiv.org/abs/2602.11510)

本报告用于收集证据和排除过宽的新颖性主张，不冻结论文题目，也不宣称已经找到无人研究的空白。共整理 67 项文献，逐篇书目、发表状态、访问条件和资源见[文献索引](./文献索引.md)；本地论文与归档说明见[目录入口](./README.md)。

## 1. 范围与证据标准

核心对象是使用 API 模型协作执行任务的多智能体系统。监测方可利用系统实际开放的消息、工具调用、返回值与运行记录；模型权重和隐藏激活不是默认条件。

检索包括多代理攻击与传播、外部轨迹监测、概率风险与置信度、运行时权限及信息流防护、评测基准，以及与 Harness/Skills 有关的供应链风险。传统机器人多智能体控制、使用 Agent 分析其他行业风险的应用论文，不作为本问题的直接先行研究。白盒解释工作仅作为扩展边界。

主要来源为 arXiv 原文、ACL Anthology、PMLR、NeurIPS、OpenReview、USENIX 和作者公开实现。对直接影响选题判断的论文进一步核对方法、实验和局限；其他条目保留摘要级或书目级标记。不同版本不重复计数，不能把 Workshop、预印本或作者自行声明的录用一律写成已核实的顶会主会论文。

这是一次有范围的广泛检索与重点核读，不是保证穷尽所有数据库的系统性综述。最新论文的公开实现、正式录用和实际可运行性仍可能变化；“没有核验到”不等于“没有”。没有运行这些论文的代码，也没有复现其效果。

## 2. 前沿已经推进到哪里

| 研究线 | 已经开展的工作 | 对选题的约束 |
| --- | --- | --- |
| 跨代理传播 | 感染、错误级联、来源谱系及在线纠错 | “错误会传播”“使用传播图”本身不新。[Spark](https://arxiv.org/abs/2603.04474) |
| 组合性风险 | 局部真实信息组合误导、协同破坏、有状态委派约束 | 不能只提出“个体安全不等于整体安全”。[Lying with Truths](https://aclanthology.org/2026.acl-long.270/)、[Bounded Agents](https://arxiv.org/abs/2608.15888) |
| 过程监测 | 完整轨迹审计、前缀失败预测、提前风险告警 | 不能只与单条文本分类器比较。[AgentForesight](https://arxiv.org/abs/2605.08715)、[Recast](https://arxiv.org/abs/2607.26820) |
| 概率风险 | BN 不确定性传播、可微概率传播、相关性校准 | “用概率图聚合 Agent 信号”已有直接近邻。[BN 监测](https://arxiv.org/abs/2607.25877)、[HalluProp](https://arxiv.org/abs/2607.26836)、[CAGE-Cal](https://arxiv.org/abs/2605.30653) |
| 系统层约束 | 数据来源、工具权限、共享记忆、跨主体委派 | 安全不仅是模型拒答，还取决于可观察和可拦截的位置。[CaMeL](https://arxiv.org/abs/2503.18813)、[MAPLE-Guard](https://arxiv.org/abs/2608.00426) |
| 执行级评测 | 工具目标、角色权限、内部信息流、正常任务效用 | 有真实 MAS 基准可以复用，不必从零做通用实验平台。[HarnessAudit](https://arxiv.org/abs/2605.14271)、[TAMAS](https://arxiv.org/abs/2511.05269)、[A2ASecBench](https://openreview.net/forum?id=LfdFnakqGJ) |

2026 年 9 月的最新 SoK 已整理 197 项工作并审计 44 项评测。其关键提醒是：在 MAS 中观察到失败，不自动证明失败由多代理交互带来。必须设计相应的交互对照，且把观察权限、干预位置与保护目标说清楚。[SoK: When Safe Agents Fail Together](https://arxiv.org/abs/2609.00595)

这里的演进不是“新路线替代旧路线”。分类器、概率预测和权限执行各自解决不同问题；它们可能组合，但组合后的新增价值仍要单独证明。

## 3. 最接近原设想的工作

### 3.1 已经有直接的“贝叶斯网络＋MAS 监测”

**Runtime Uncertainty Monitoring for LLM-Based Multi-Agent Systems Using Bayesian Networks**，Custers 与 Aslansefat，2026-07-28，预印本。它用各阶段输出的 token logprobs 构造置信信号，经任务级映射后输入 BN，监测精算工作流的不确定性。结构由工作流给定，使用各阶段最终接受的结果；未显式建模反复修订和反馈环。它不是正确性证明，实验也不是泄漏或越权评测。[原文 §4—6](https://arxiv.org/html/2607.25877v1)

**Bayesian Uncertainty Propagation for Agentic RAG Pipelines**，Donaldson 等，2026 年 7 月，直接研究 Agentic RAG 的贝叶斯不确定性传播。它说明这条方法线已有可衔接的工作；RAG 多阶段处理不能不加区分地等同于跨权限边界的协作系统。[原文](https://arxiv.org/abs/2607.00972)

**Before Agents Speak / HalluProp**，2026-07-29，预印本。由任务、角色和通信图预测节点风险及边传播概率，再用可微 Noisy-OR 推理系统失败风险。它在执行前就进行预测；主要标签是知识、数学、医学问答的答案对错。概率传播算法与安全执行监测之间仍有任务边界，但不能仅以“换成贝叶斯传播”区分。[原文](https://arxiv.org/abs/2607.26836)

### 3.2 外部图监测已经不只停留在建图

**From Spark to Fire**，2026-03-04，预印本。它从消息路由和输出建立主张谱系，识别重述、矛盾等信号，并进行预算化验证和回退。需要全局消息拦截与可信验证来源。作者明确说明传播谱指标不是经过校准的风险概率；二元、平稳传播假设也有边界。[原文方法与局限](https://arxiv.org/html/2603.04474v1)

**GUARDIAN**，NeurIPS 2025。以每轮 Agent 响应作为图节点、通信作为边，进行时序图异常检测并移除可疑代理。主要实验是辩论与问答，不是带权限的异构工具执行。这是“文本通信图＋异常监测”必须面对的已有方法。[原文](https://arxiv.org/abs/2505.19234)

**Agent-BOM**，2026-05-07，预印本。把静态能力、运行事件和跨代理关系组织为可查询审计图，在 OpenClaw 的四类复合攻击案例中追踪路径。它需要配置、完整提示拼接及运行插桩等证据，定位为审计表示而非独立防御；案例展示不能当作大规模预警准确率实验。[原文 §V—VI](https://arxiv.org/pdf/2605.06812)

### 3.3 “在危险发生前报警”也已有方法

**AgentForesight**，2026 年 5 月，提供 AFTraj-2K 与在线前缀审计器，在决定性错误首次可见时报警并定位责任 Agent，争取在错误扩散或最终任务失败前干预；不是预测尚未发生的决定性错误。其 “unsafe” 主要关联任务失败，不应直接翻译为隐私或授权违规。训练资源与部署推理资源也应分开评估。[原文](https://arxiv.org/abs/2605.08715)

**TRACES**，2026 年 5 月，用另一个观察者模型处理目标 Agent 的外部轨迹，学习前缀风险信号。隐藏表征来自观察者，不是 API 目标模型；因此“目标是 API”不排除这种探针式特征提取。但其解释和离线预测不能自动视为因果发现或闭环减害证据。[原文](https://arxiv.org/abs/2605.27690)

**Recast**，2026-07-29，明确限定只有用户—模型文本，不读目标模型激活或 logits，预测未来首次违规时间分布。实验包含多轮越狱与困难正常样本；不是 MAS。其 “causal temporal encoder” 指遮蔽未来信息的时间编码，不是发现因果关系。它是外部风险预测的重要相邻基线。[原文 §2—4](https://arxiv.org/html/2607.26820v1)

**ProbGuard**，旧称 Pro2Guard，首发 2025 年、2026 年更新。通过专家安全谓词把环境状态抽象为离散状态，从轨迹学习转移概率并计算危险可达概率。它需要环境状态，不是纯文本监测；理论证书依赖抽象与样本条件，不能把概率模型检查直接等同于实验系统已获安全保证。[原文](https://arxiv.org/abs/2508.00500)

### 3.4 可读结构与安全验证已有更强对手

**ShieldAgent: Shielding Agents via Verifiable Safety Policy Reasoning**，ICML 2025。从安全政策提取时序规则，以概率规则结构组织验证，结合轨迹和工具进行检查。因此，“可解释规则／概率结构优于黑盒判别”不能只拿弱分类器证明。这篇与 Agent-SafetyBench 中同名的 ShieldAgent 不是同一工作。[原文](https://arxiv.org/abs/2503.22738)

**CAGE-Cal**，2026 年 5 月，比较通信图与独立 Agent 图，建模相关错误后进行团队置信度校准。不能把它简单描述成“必须额外完整重跑一遍”：某些协议的首轮即可复用独立输出。它还使用答案 log probability，不能不加条件地称为任意纯文本 API 可用。主要任务是回答正确性，不是工具安全。[原文](https://arxiv.org/abs/2605.30653)

## 4. Harness、Skills 和真实安全有什么关系

Harness 在这里指模型外负责工具执行、资源分配、上下文传递和代理协调的运行层。它提供了安全检查位置，也规定了我们究竟能看见什么。Skills 则可能成为被加载的第三方能力与指令来源。二者不是论文标题中的流行修饰词，而是具体的输入面、权限面或传播载体。[HarnessAudit](https://arxiv.org/abs/2605.14271)、[Agent-BOM](https://arxiv.org/abs/2605.06812)

Skills 安全已有正式顶会实证：USENIX Security 2026 的恶意 Skills 研究从大规模注册站语料筛选候选，再做行为核验；Skill-Inject 则提供技能文件攻击与正常任务的联合评测。它们可以提供具体威胁入口，但“Skills 存在恶意供应链风险”本身不能再当作新发现，也未自动回答风险如何跨代理累积。[恶意 Skills 实证](https://www.usenix.org/conference/usenixsecurity26/presentation/liu-yi)、[Skill-Inject](https://arxiv.org/abs/2602.20156)

已有研究分别覆盖：记忆写入到跨代理复用的生命周期监测；跨委派链累计权限与动作限制；对多代理执行的数据流进行策略检查。共同前提通常是可信元数据、已知规则和可拦截执行点。它们不需要神经网络内部信息，但也不等于只需要最终回复文本。[MAPLE-Guard](https://arxiv.org/abs/2608.00426)、[Bounded Agents](https://arxiv.org/abs/2608.15888)、[AgentFlow](https://arxiv.org/abs/2608.22868)

这给研究范围一个重要约束：先说明能获得的消息、路由、工具返回和权限信息，再选择方法。若未来跨组织系统不开放完整日志，不能默认中心监测器拥有全知视角；若部署方能控制网关，也不应人为放弃已经可获得的执行证据。

## 5. 已有工具能替代哪些基建

以下是候选复用层，不是已测试通过的安装建议，也不存在一个基准自动覆盖所有研究目标。

| 工具／数据 | 能直接借用什么 | 不能默认具备什么 |
| --- | --- | --- |
| [HarnessAudit](https://github.com/UCSB-AI/HarnessAudit) | 210 个任务；角色、资源与通信规则；统一执行记录；单／多 Agent 对照 | 原设计是事后审计，不是在线预测器；判分隐藏信息不能泄露给监测器 |
| [TAMAS](https://github.com/microsoft/TAMAS) | 真正多代理的攻击与正常任务、交互配置、安全—效用评价 | 不是所有攻击和角色都与目标课题一致；需核查接口与框架版本 |
| [A2ASecBench](https://github.com/SaFo-Lab/A2ASecBench) | A2A 协议环境、攻击／正常对照、API 后端接口 | 协议安全不覆盖全部语义协作风险 |
| [AgentLeak](https://github.com/Privatris/AgentLeak) | 敏感数据、允许披露集合、内部通信／记忆记录与检测 | 主要衡量超出允许范围的披露，不是每次都已流到外部攻击者 |
| [AgentDojo](https://github.com/ethz-spylab/agentdojo)、[AgentDyn](https://github.com/SaFo-Lab/AgentDyn) | 工具环境、提示注入、正常任务效用及动态任务 | 主要为工具型单 Agent，不能直接贴上 MAS 标签 |
| [MAST](https://arxiv.org/abs/2503.13657)、[Who&When](https://github.com/mingyin1/Agents_Failure_Attribution)、[AFTraj-2K](https://github.com/ZBox1005/AgentForesight) | 已有失败轨迹、分类或关键步骤标注 | 任务失败标签不自动成为泄漏／越权标签 |

HarnessAudit 原文明确把执行和判分分开：执行时不评分，结束后结合隐藏规则及环境证据审计。它可提供评测基础，但把它改为预警实验仍需设计前缀切分、首次危险时刻和合法可见输入。[原文附录 §8](https://arxiv.org/html/2605.14271v2)

AgentLeak 的 “internal channel” 指系统内部消息、共享记忆等，不是大模型内部激活。正式论文版本与同名产品网页的样本数量、通道数量不同；本报告以论文及其指向的 Privatris 仓库为准，不混合统计。[论文 v3](https://arxiv.org/html/2602.11510v3)

现有本地实验室可以保留为小型、可控、便于检查结果的环境。它是否继续扩建，应由具体研究问题和现成基准缺少的能力决定。旧实验只能证明其实际测过的内容；接口打通、格式通过和正常任务完成，不是安全监测有效性的证据。

## 6. 哪些不能再单独当创新

| 过宽的表述 | 已有直接近邻 | 必须进一步回答 |
| --- | --- | --- |
| 多 Agent 的风险会传播 | Agent Smith、NetSafe、Spark | 新的风险机制或可验证能力是什么？ |
| 对通信建图、找异常节点 | GUARDIAN、SentinelAgent | 与现有时序图方法有何实质差异？ |
| 用 BN 聚合各 Agent 的风险 | Custers 等、Agentic RAG BN、HalluProp | 观测误差、依赖建模或推理上新增什么？ |
| 看历史而不只看当前一句 | TRACES、Recast、AgentForesight | 为什么能更早、误报更少或迁移更好？ |
| 每个都正常，组合起来危险 | Lying with Truths、Bounded Agents | 指定什么组合规则或受保护结果？ |
| 最终回复正常，但过程中泄漏 | AgentLeak、HarnessAudit | 相比已有全过程审计改进在哪里？ |
| 给 Agent 外面加安全包 | ShieldAgent、TrinityGuard、CaMeL 等 | 是新算法、新证据，还是工程集成？ |

这些近邻的原文与状态在文献索引中逐项列出。出现相关论文不是否决方向；它意味着必须把比较对象从“没有监测”提升到真正相近的方法。

## 7. 仍值得继续核查的研究问题

以下是从多篇工作边界提出的候选问题，不是已经成立的文献空白，更不是本轮定下的题目。

### A. 证据缺失、出错或重复时，风险概率是否仍可信？

核心不是再画一张图，而是避免把三次转述误当三份独立证据，或把“没观察到”当成“确认安全”。必须同时面对 CAGE-Cal 的相关性处理、Spark 的来源识别、TRACES 的弱监督和现有 BN 监测；仅加去重、缺失值填补或更换概率模型不够。[CAGE-Cal](https://arxiv.org/abs/2605.30653)、[Spark](https://arxiv.org/abs/2603.04474)、[TRACES](https://arxiv.org/abs/2605.27690)

选题前的核查门槛：在一致可见信息和预算下，是否存在明确的校准、漏报或迁移缺陷？新方法能否针对该缺陷提出可检验的解释，而非只提高一个综合分数？

### B. 可读的中间状态，能否帮助预测真实执行风险？

可解释概率结构已有先例；尚需区分“节点有中文名字”和“这些状态能被可靠测量、更新，并帮助判断风险”。可以继续检查弱标注、语义漂移与可读性约束之间的矛盾，但必须与 ShieldAgent、ProbGuard、HalluProp 及直接 BN 工作比较。[ShieldAgent](https://arxiv.org/abs/2503.22738)、[ProbGuard](https://arxiv.org/abs/2508.00500)、[HalluProp](https://arxiv.org/abs/2607.26836)

选题前的核查门槛：是否能用实际泄漏、越权或可用性损失验证，并证明解释质量和预测质量的改进不是换了更容易的标签？

### C. 报警后如何减少损害，同时保留协作收益？

不能把“超过阈值就停机”直接称新贡献；预算审计、验证、局部恢复已有方法。真正要继续核查的是风险预测在具体选择中是否有额外价值，以及干预改变后续轨迹后，原来的风险估计是否仍成立。[BRA-Audit](https://arxiv.org/abs/2608.14668)、[Spark](https://arxiv.org/abs/2603.04474)

选题前的核查门槛：和固定规则、强全轨迹判别器、既有审计策略相比，能否在同样正常任务完成率或审计成本下显著降低实际危害？这只是必要条件，不自动构成方法创新。

## 8. 大论文叙事如何保持连贯

暂时可以保留的研究主线是：**从可获得的执行证据出发，研究可解释的风险评估，并扩展到多代理协作。** 这是一条组织工作的问题线，不是论文题目或新颖性声明。

事件图属于证据整理与关系表示；外部文本特征属于证据提取；目标模型内部探针只在能访问目标内部时作为附加信号，另一个观察者模型的探针则是外部证据提取器；概率网络负责在明确假设下融合证据；多代理工作需要处理跨主体依赖及安全边界。各部分只有在共同风险目标、输入定义和评价方式下衔接，才构成体系。

应避免承诺“揭示原模型真实思考过程”或“保证一切安全”。监测器可解释，不代表原始 LLM 变成白盒；风险概率可计算，也不代表图中的边已经证明为因果。

方法的选择仍应后于问题。如果强文本判别器、状态机或现有图模型已解决所选任务，不能为了保留贝叶斯而强行增加一层。

## 9. 下一轮最有价值的核查顺序

1. 先并排阅读直接 BN 监测、Agentic RAG BN、HalluProp：确认“我们的概率结构究竟比已有方法多做什么”。
2. 再比较 Spark、GUARDIAN、ShieldAgent、TRACES／Recast：确认图表示、证据提取与提前告警的已有能力。
3. 以 HarnessAudit、TAMAS、AgentLeak 选择真实安全结果和可复用评测，而不是先写新平台。
4. 最后才写研究缺口：每个候选必须列出最接近论文、已做／未证实内容、不同假设和可否证实验。

一个候选问题若不能明确写出“在同等条件下，现有方法为什么不足，以及新方法预期新增什么”，目前就不应定题。

## 10. 阅读与引用注意事项

- 本报告不比较不同基准上的 ASR 或 F1 排名；攻击预算、目标、可见信息及判分规则不同，数值不可直接相减。
- 校准后的正确率、规则符合率、数据最小化违规和外部泄漏应分别报告，不能混成同一个“安全概率”。
- 图节点与边可能来自人工规则、运行日志或学习模型。来源可追踪不等于真实因果已被识别；时间模型的 causal mask 也不是因果发现。
- 理论保证必须附带条件：规则覆盖、可信执行层、状态抽象正确性、样本量或分布条件。只引用结论、不列条件会误导选题。
- 预印本可以是最接近的先行研究，但“足够接近”不等于其结论已被独立复现；代码公开也不等于可直接运行。
- 新工作持续出现。本轮证据足以否定若干过宽的新颖性表述，但不足以证明任何狭义候选绝对没有竞争工作。
