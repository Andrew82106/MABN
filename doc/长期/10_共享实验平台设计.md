# 共享实验平台设计（shared_lab）

> 状态：三层设计已由主 Agent 与用户确认（2026-08-17）；`shared_lab/` 基础实现及
> 权限映射返工已于 2026-08-18 独立验收通过。
> 定位：三篇论文共用的“透明实验室”，与任何具体场景解耦。

## 0. 一句话定位

平台负责让“LLM 多智能体图实验”可以被可信地运行、记录、回放和溯源；
平台不负责任何具体任务、角色、人数、图结构或危害定义。

## 1. 三层结构

### 1.1 内核：与场景无关的基础能力

内核只提供五件事，代码中不得出现任何具体场景常量：

1. 调度：谁被唤醒、消息沿图如何传递、一个回合何时结束；
2. 权限：任何动作在执行前由内核强制检查，违反即拒绝并记录；
3. 账本：可观察事实按时间追加记录，只增不改；
4. 状态与回放：状态可快照、可哈希、可回滚；给定账本与初始状态，程序能重建终态并核对一致；
5. 溯源：本次运行使用的配置、提示词、代码、环境全部记录内容哈希，可回答“结果是用什么跑出来的”。

### 1.2 场景配置包：纯数据

一个具体实验场景完全由数据描述，内核读取后运行：

- 人数、角色、社群标签；
- 通信图（谁可以向谁发消息）；
- 每个角色的工具能力与权限；
- 任务提示词、输入材料、正常完成条件；
- 危害终点定义及其程序判定器；
- 模型绑定与解码参数。

8 人供应商审查只是第一份场景配置包，不是平台的形状本身。换人数、角色、图或任务，
只换配置，不改内核。

### 1.3 实验钩子：三篇论文的插入点

- 论文一：在任意指定边、指定时刻注入消息干预（替换 / 删除 / 安全改写）；
- 论文二：对观测注入噪声或缺失（日志缺块、检测器误报漏报）；
- 论文三：防御动作（隔离 Agent、切断边、撤销权限、回滚状态）。

平台提供插口，具体实验决定插什么；平台不为三篇论文各写一套。

## 3. 选型原则（含对现有库的评估）

- 允许参考、甚至直接复用 AutoGen、LangGraph 等现成框架的设计与组件；
- 但本平台的四条审计性质是硬门槛，不得为了用库而牺牲：
  账本只增不改、可确定回放、可溯源、权限由内核强制；
- 若现成库能完整保证上述性质则复用；否则使用薄内核。优先标准库，新增依赖必须写明理由；
- 内核必须能用 stub Agent 全离线测试，不依赖任何模型调用、网络或 GPU。

## 4. 验收性质（非协商）

1. 内核代码不得出现 8 人、供应商审查、假机密等场景常量；
2. 用 stub Agent 即可全量离线测试，不依赖任何真实模型调用；
3. 账本只增不改；回放重建的终态与原始运行一致；
4. 任何动作在执行前都经过内核权限检查；
5. 每次运行可回答“用了哪份配置、哪段代码、哪个环境”；
6. 场景的“正常完成”与“危害”由程序判定器给出，不依赖 LLM Judge 作为唯一判据。

## 5. 边界与历史隔离

- 泛化域是“LLM 多智能体图实验”内部的人数、角色、图、任务、干预、观测与防御；
  不是通用 Agent 框架；
- paperAlpha/ 下的冻结代码、数据与历史 run 一律不动；新平台在 shared_lab/ 净新增；
- 现有 paperAlpha/pre_exp1 的 P0 内核实现可作为参考读，不得直接修改；
- 是否让 paperAlpha 后续切换到共享内核，另立任务决定，不在本任务范围内。
