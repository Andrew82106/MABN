# 任务书：共享实验平台科学实验准入层实施

> 状态：待实施、待主 Agent 验收。
> 实施对象：`shared_lab/`。
> 性质：平台工程准入，不运行论文实验，不产生科学结论。

## 1. 顶层目标

### 证明什么

实现完成后，任何风险或假测试秘密都不能通过“角色直接看见全局状态”或“角色任意修改
实验室状态”到达公开端。可验证泄漏只能经过明确授权的读取工具、显式 Agent 消息和
明确授权的发布工具发生。

同时提供一个可替换的模型入口，使真实模型未来只能看到该角色获准看到的内容，并且只能
提出经过程序严格检查的消息或工具请求。

### 怎么证明

全部使用离线 stub Agent 和 fake model transport：

1. 普通角色观察中不存在私有记录和假测试秘密；
2. 普通角色不能直接读取内部记录、不能发布、不能任意写状态；
3. 只有内部记录角色通过读取工具得到假测试秘密，且结果只返回给该角色；
4. 只有发布角色能通过发布工具改变公开端；
5. 完整的“授权读取 → 显式消息 → 授权发布”可产生程序可验证泄漏；切断必要消息边后
   泄漏必须消失；
6. fake 模型收到的请求不包含未授权私有数据，其合法动作可执行，非法、越权或畸形动作
   必须在任何状态变化前拒绝并记账；
7. 账本和重放仍能重建相同终态，重放不重新执行工具或模型。

### 产出什么

- 场景声明式的逐角色观察策略；
- 通用受控工具注册与执行层；
- 可注入 transport 的模型 Agent 适配层；
- 更新后的 8 角色供应商审查配置包；
- 全离线准入测试、README 与交付说明；
- 唯一的 `ready_for_main_acceptance` 或 `rework` 工程结论。

不产出真实模型能力结论、风险传播效应、P1/P2 Go、贝叶斯结果或论文数据。

## 3. 强制实现 A：逐角色观察隔离

### 3.1 默认拒绝

`Kernel.observation_for(agent_id)` 不得再把 `self._state` 完整复制给 Agent。
完整状态只能在内核、受信任工具执行器、程序判定器、回放与审计内部存在。

场景配置声明每个角色可见的状态路径或命名视图。未明确授权的路径默认不可见。至少支持：

- 角色身份与角色提示；
- 发给该角色的消息；
- 该角色自己的工具结果；
- 场景明确允许的公共任务字段。

配置加载时必须拒绝路径越界、未知角色、重复或格式非法的观察规则。返回给 Agent 的对象
必须是深拷贝，Agent 修改观察不能改变内核状态。

### 3.2 消息和工具结果隔离

- 消息只能被明确接收者看到；
- 工具结果默认只对调用者可见；
- 假测试秘密只允许在内部记录读取工具的结果中首次出现；
- 普通材料、协调、分析和发布角色的初始观察及模型请求中不得出现假测试秘密；
- 实验 hook 可以作为受信任研究者组件访问必要的内部上下文，但不得把全局状态意外
  返回给 Agent。

## 4. 强制实现 B：受控工具层

### 4.1 通用工具注册

实现与场景解耦的工具注册与执行接口。场景配置至少声明：

- 工具名；
- 所需权限；
- 参数契约；
- 场景内处理器；
- 是否产生状态变化；
- 返回结果的可见范围。

工具所需权限由内核从可信工具注册表推导。模型或 Agent 输出不得自行决定 capability。
未知工具、参数缺失、额外参数、错误类型、调用者无权或处理器异常都必须 fail-closed，
在任何状态变化前拒绝并写入清楚的账本事件。

### 4.2 禁止模型任意写状态

模型控制的 Agent 只允许提出：

1. `send_message`；
2. `call_tool`。

不得让模型通过 `set_value`、`append_value`、任意 state path 或伪造工具效果修改内核状态。
如果内核内部保留通用状态转换，它必须是受信任执行路径，不能从模型动作适配器到达。

### 4.3 第一份场景的两个真实边界

在 `supplier_review_8agent` 配置包中实现本地、无网络的 mock 工具：

- 内部记录读取：仅内部记录角色可调用；按参数返回允许字段；假测试秘密只可能由此产生；
- 公开报告发布：仅发布角色可调用；它是改变公开输出和任务终态的唯一入口。

普通角色即使知道工具名、参数或假测试秘密，也不得调用这些工具。任何角色都不得绕过工具
直接写内部记录、公开报告或任务成功状态。

### 4.4 账本与回放

账本记录工具请求、授权结果、结构化安全结果摘要及确定性状态效果。不得依赖重新执行工具完成
重放；重放只应用已记录且通过验证的效果，并保证工具执行计数为零。篡改工具名、调用者、权限、
参数、结果或状态效果并重算哈希链后，使用可信收据的验证与重放仍须拒绝。

## 5. 强制实现 C：模型入口

实现一个与提供方解耦的 Agent 适配层：

1. 输入为角色提示、任务提示、**隔离后的角色观察**和冻结模型配置；
2. transport 通过接口注入；测试使用 fake transport；
3. 输出只接受普通 JSON 动作描述，不接受原生工具调用旁路；
4. 模型 JSON 不包含 capability；适配器依据 `send_message` 或可信工具注册表生成内部 Action；
5. 严格拒绝非 JSON、重复 key、NaN/Infinity、额外或缺失字段、未知动作、未知工具、
   错误参数、越权目标、推理字段、拒答包装和多动作夹带；
6. 请求构造支持 OpenAI-compatible `json_object` 形状，但当前任务不实现会自动读取凭据的
   live CLI，也不得进行真实 HTTP 调用；
7. 不记录隐藏思维链；原始请求/回答的保存策略必须可配置，默认测试工件只保存安全摘要与哈希。

模型入口应能在以后替换为 GPT、Ollama、AutoGen 或 LangGraph 适配器，而不改变权限、账本、
场景和实验 hook 的核心接口。允许参考或复用这些库的设计；如新增第三方依赖，必须先停止并请求
批准，本任务默认依赖为零。

## 6. 第一份场景的离线端到端准入轨迹

至少实现并测试四条确定性轨迹：

1. **正常完成：**没有风险内容，公开报告正确，任务成功，假测试秘密不泄漏；
2. **显式传播：**内部记录角色授权读取假测试秘密，经允许的消息边发送给发布角色，发布角色
   授权发布，程序判定泄漏；
3. **必要边阻断：**在同一显式传播轨迹切断内部记录角色到发布角色的必要消息边，泄漏不能发生；
4. **直接旁路攻击：**普通角色尝试直接看私有状态、直接写公开报告、调用内部读取或发布工具，
   全部失败且状态不变、拒绝被记账。

上述是工程准入轨迹，不是论文样本或因果证据。

## 7. 泛化检查

测试中另建一个与供应商无关、人数不同的极小场景配置（可在临时测试目录动态生成），验证：

- 不改内核即可加载不同人数、角色、图和工具；
- 观察策略、工具权限、消息边和程序判定均来自配置；
- 内核源码继续不包含供应商、8 人、假测试秘密等场景常量。

该极小场景只用于证明平台解耦，不进入论文数据。

## 8. 硬性验收标准

任一项不满足即为 `rework`：

1. 现有 22 项测试继续通过；
2. 普通角色观察和 fake 模型请求中均找不到假测试秘密或完整私有状态；
3. Agent 修改观察对象不能改变内核状态；
4. 模型动作无法到达任意状态写接口；
5. 内部读取和公开发布只能由各自授权角色通过工具完成；
6. 未授权、畸形和未知工具调用在状态变化前拒绝并记账；
7. 正常、显式传播、必要边阻断、直接旁路四条轨迹均符合预期；
8. 重放终态与原运行一致，且重放期间模型调用和工具执行均为零；
9. 对工具事实的协同篡改即使重算事件链，仍被可信收据拒绝；
10. fake transport 覆盖合法、畸形、越权、模型身份错误、超时和基础设施失败；
11. 第二个不同人数与任务的测试场景无需修改内核即可运行；
12. 固定 Python 环境全量测试通过，无新增依赖、无网络、无 `.env` 读取、无缓存；
13. `paperAlpha/`、`doc/`、根文件和既有历史工件均无修改。
