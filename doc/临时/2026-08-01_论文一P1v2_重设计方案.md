# 论文一 P1v2：重设计方案（临时讨论稿）

> 状态：P1v2-A、P1v2-Q0、P1v2-Q1 与 Q2-A 均已通过独立验收；Q1 的 `qwen3:8b` 配置为 `not_qualified`；Q2-B 原始唯一真实批次的整体交付仍为 `rework`；其最终离线证据链修复审计已通过独立验收，但不升级原始模型资格结论；Q2-C 小型 Codex 响应行为探针已完成并验收为 `observed`（仅限一次良性格式兼容性观察）；Q2-D（P1 Agent 动作契约离线准入）首轮离线交付已验收为 `rework`，返工前新的真实 P1 仍未获准  
> 文档性质：下一轮准入的设计草案，不是长期路线变更，不是实验结果

## 顶层结论

旧 P1 不能进入 P2，并不说明论文一的机制不存在。它说明下一轮 P1 必须把三件事分开：

1. 输出与日志系统是否会把错误安全地拒绝；
2. 哪个冻结的模型/接口配置可以稳定满足输出契约；
3. 这个已冻结配置能否在无风险条件下产生可用于 P2 的良性基线。

因此 P1v2 不是“重跑旧 P1”，而是一套新的、顺序固定的独立准入。

## 实验一：P1v2-A 离线输出与证据链准入

### 证明什么

新协议会拒绝不合法回答、内部字段和角色错配，不会把它们伪装成正常公开报告；同时，每次
离线运行都能被 validation、replay 与 provenance 复核。

### 怎么证明

用确定性假 provider 分别送入合法回答和预先列出的坏回答，观察前者能完成 dry-run、后者
都会安全停止且无法到达公开发布端。再用跨文件篡改样本检查验证器是否拒绝伪造的一致性。

### 产出什么

- 一个可审计的离线准入实现；
- 对真实模型调用前的工程 Go/返工判断；
- 不含任何真实 P1、风险传播或 P2 结论的数据。

2026-08-01 的返工已通过主 Agent 独立验收：当前唯一离线工件为
`P1V2-READINESS-DRY-20260801T000002000000Z`；公开 validation 与 replay 均通过，全部模型、
provider、network 调用计数为 0。畸形工件、外部输入和越界路径均会 fail-closed；config、fixture、
schema、prompt、入口脚本和源码均被 provenance 覆盖。详细工程证据见
[P1v2-A 第一轮返工交付](../../paperAlpha/data/pre_exp1/p1v2_benign/readiness_dry/reports/P1V2_A_REWORK1_DELIVERY.md)。

这项通过只表示主 Agent **可以另行设计并批准** P1v2-Q 的模型与输出栈资格验证；它不是模型调用
许可，不是新的 P1，不是 P2 Go，也不是论文一的科学结论。历史 `...000000000000Z` 与
`...000001000000Z` 保留为非 current 的 preliminary/pre-rework 证据。

验收运行注意：为验证 provenance 漂移，P1v2-A 的部分测试会短暂改写其自身的源码、schema 或
fixture 后在 `finally` 中恢复。因此这组测试必须串行运行；每次运行结束后均须复跑 current artifact
的公开 validation/replay，不能将并行互扰产生的失败解释为科学或模型结果。

## 实验二：P1v2-Q 模型与输出栈资格验证

### 证明什么

在不与正式 P1 重叠的良性资格任务上，冻结的模型和结构化输出接口能否稳定产生可验证、
符合契约且权限正确的回答。

### 怎么证明

先完成不调用模型的 Q0：验证资格任务、严格解析、权限检查、公开发布端、数据隔离、
provenance、validation 与 replay 能在确定性假 provider 下闭合。Q0 通过后，才由主 Agent
另行批准 Q1 的真实本地调用。Q1 将冻结模型、资格任务、结构化输出接口、解码参数、预算和
单一判定规则，重点重复检验此前出错的最终公开发布动作；期间不调参、不重试、不切换模型。

### Q2-A：远程候选的离线准入（已通过独立验收）

用户已选择 `gpt-5.3-codex-spark` 作为下一候选，并指定本机 OpenAI-compatible gateway

**证明什么：**在不发送任何真实模型请求的前提下，新的远程资格框架能否安全地构造冻结请求、
严格处理 OpenAI-compatible 响应、隔离凭据，并生成可离线验证和回放的资格工件。

**怎么证明：**使用注入式假 transport 和虚构 key 覆盖完整成功、缺字段、角色或任务值错误、
HTTP/超时/认证错误、响应包络错误、模型名不一致和推理内容泄漏等情况；检查所有失败均
fail-closed，Screen 失败会阻断 Confirmation，且 validation/replay 不读取凭据或访问网络。

**产出什么：**一个独立的 Q2-A 远程资格框架，以及唯一的 `ready_for_q2b` 或 `rework` 工程判断。
它不调用 `gpt-5.3-codex-spark`，不产生 P1 数据，也不解锁 P1/P2。

### Q2-B：分阶段真实远程资格批次（原始批次返工；离线修复审计已验收）

用户已明确授权在本机 gateway 上逐步调用 `gpt-5.3-codex-spark`。本批次仍不是正式 P1：它只验证这
一个冻结的“gateway + 模型 + JSON-schema 输出 profile”能否在真实调用中满足资格契约。

**证明什么：**远程接口实际返回的输出，是否能持续满足四字段、角色、任务值和无推理内容泄漏的严格
契约，而不只是通过离线 mock。

**怎么证明：**先以两次 `GET /v1/models` 记录开始/结束的模型列表身份；再按固定顺序运行 8 张
Screen 进入卡。8 张均通过才继续剩余 24 张 Screen；32 张均通过才运行 96 张 Confirmation。全程
串行、零重试、零模型切换、零 Ollama/讯飞兜底；最多 2 次 metadata 加 128 次 completion 调用。真实
输出契约错误会阻止下游阶段，基础设施、凭据、身份或证据链错误则立即停止并标为返工。

**产出什么：**一个唯一的 `qualified`、`not_qualified` 或 `rework` 配置结论，以及可独立验证的真实
资格工件。即使 `qualified`，也只解锁“设计新的正式 P1”，不直接解锁 P1 或 P2。

2026-08-02，唯一 live run `P1V2Q2B-REMOTE-20260802T033140463464Z` 实际执行了 2 次模型列表查询和
8 次 Screen completion，零重试；8 条响应均含被冻结契约拒绝的 `tool_calls`，因此剩余 24 条 Screen 与
96 条 Confirmation 均未启动。原始 run 的公开 `validation → replay → validation` 可通过，且开始/结束
模型列表一致。这些是**已保存的运行事实**，不等于可以进入 P1 的已验收准入结论。

独立验收发现两个硬性证据链缺口：总墙钟上限没有覆盖阻塞中的模型列表 I/O；而且在隔离副本中篡改失败
record 的 `request_sha256` 并同步 manifest 后，现有 validation 和 replay 仍错误返回通过。失败 completion
也没有持久化其安全的逐次 provider 身份字段。因此，本批次整体交付判为 `rework`，不得把原始的
`not_qualified` 记录升级为官方配置结论、不得据此设计或执行 P1。原始代码和数据保持冻结；后续只可先做
独立、离线的修复与派生审计，任何新的真实模型批次都需要新的任务书和用户授权。详见
[Q2-B 交付记录](../../paperAlpha/data/pre_exp1/p1v2_qualification_q2b/reports/DELIVERY.md)。

首个离线修复审计 `P1V2Q2B-REPAIR-AUDIT-20260802T035603081713Z` 证明了 deadline helper、失败身份
记录和篡改检测的局部规则，但独立验收发现该 helper 尚未接入完整的“开始身份查询 → completion →
结束身份查询”假流程；它不能证明越界后不再发起后续 I/O。因此该审计是 `historical_pre_rework`，不是
工程通过结论。返工只补离线流程集成与新的派生审计，仍不产生新的模型调用或 P1 资格。

替代审计 `P1V2Q2B-REPAIR-AUDIT-20260802T041527196020Z` 随后补齐了完整 fake staged runner，但最终独立
验收又发现协同篡改漏洞：若同时将 transcript 的开始/结束模型列表 hash 与 model count 改成另一份合法
模型列表、同步修改两个 metadata 账本事件、重链 ledger 并同步 manifest hash，validation 与 replay 仍会
通过。原因是它们只检查多个工件是否彼此一致，未把身份事实锚定到冻结模型列表。因此该替代审计也不是
工程通过结论；P1/P2 继续锁定，下一步只补独立的冻结身份 oracle、相应协同篡改负测，以及每个审计
各自不可变的交付报告。后者是必要的，因为两个历史审计共用根级 `DELIVERY.md`；新报告覆盖后，旧审计
manifest 中对该共享文件的 hash 不再可验证。两个历史审计都保留原样，但不能作为当前工程通过依据。

截至 2026-08-02，第三轮离线源码与测试返工已由主 Agent 与独立 Agent 双重验收后，唯一最终派生审计

### Q2-C：Codex 响应行为小型探针（已完成并验收为 `observed`）

**证明什么：**同一 Codex gateway 在最简单、完全良性的四种“请按格式回答”方式下，实际会返回普通内容、
可解析 JSON，还是仍然返回工具调用或其他不适合作为 Agent 通信的结构。

**怎么证明：**固定模型、任务语义和调用顺序，只改变要求结构化回答的方式；先用假接口证明记录、超时和
离线复核没有问题，再在用户授权范围内执行一次模型列表检查和最多四次真实 completion。响应格式不合格
本身会被如实记录，不会触发重试、换模型或进入正式多智能体实验。

**产出什么：**一份关于“这个 gateway 最适合怎样要求结构化回答”的工程观察记录，以及 `observed` 或
`rework` 的探针结论。它不是模型资格结论，不产生论文数据，也不解除 P1/P2 锁定。

用户于 2026-08-02 明确同意开始逐步调用 Codex。离线预检经两次独立验收后，唯一真实 run
`P1V2Q2C-PROBE-20260802T061803504801Z` 使用 `gpt-5.3-codex-spark` 完成了 1 次 `GET /v1/models` 和
4 次串行 completion，零重试、零模型切换、零其他 provider。四种固定 profile 均记录为 `content_match`，
因此本探针结论为 `observed`；公开 `validation → replay → validation` 与最终独立验收均通过。安全摘要见
[Q2-C run-local DELIVERY](../../paperAlpha/data/pre_exp1/p1v2_qualification_q2c_probe/runs/P1V2Q2C-PROBE-20260802T061803504801Z/reports/DELIVERY.md)。

这只说明该 gateway 在这一次、四个最小良性格式请求中产生了符合预定字段的普通内容；它不修复 Q2-B，不构成
模型资格、P1/P2 通行或论文结论。唯一调用授权已经消耗，不得新建第二个 Q2-C run。

### Q2-D：P1 Agent 动作契约离线准入（首轮离线交付验收为 `rework`）

**证明什么：**未来候选输出栈能否在 P1 真正需要的九种单 Agent 动作位置，生成可由程序安全检查的正确
动作；而不只是返回一个形式上合法的 JSON。

**怎么证明：**为 Intake、Dossier Extractor、Independent Verifier、Coordinator、Risk Analyst、Policy
Reviewer、Internal Record Agent（请求工具与汇总工具结果）和 Report Publisher 各冻结一类良性卡片。每张卡只
模拟该 Agent 应看到的输入，只检查其 JSON 动作描述；不连接 Agent、不执行内部读取或公开发布。先用假 transport
完成离线完整流程和篡改检测；真实调用必须等待新的用户授权。

**产出什么：**一个独立的 `ready_for_q2d_live` 或 `rework` 工程结论、九类 P1 动作契约的可复核覆盖表，
以及未来是否值得另行批准一次真实 Q2-D 资格批次的依据。它不是多智能体 P1、不是模型资格结论，也不解锁 P1/P2。

Q2-D 使用全新的代码与数据根，不导入或修改 Q2-B、Q2-C 或历史 P1 的 Python 包。它以 Q2-C 的“严格 JSON
Schema 在极简任务中可用”观察作为设计输入，但不把该观察当作 Q2-D 的通过证据。

2026-08-02 的首轮离线实现未通过独立验收，因此不能产生 `ready_for_q2d_live` 结论。虽然固定环境中的
单元测试和既有 fake run 的公开 validation/replay 可以通过，验收发现：卡片良性事实与运行时 Canary 没有
实际进入请求；schema 直接以 case-specific `const` 预填答案；发布动作只实际覆盖两种而非四种结论；并且在
保留 run ID、重算 artifact hash 的隔离副本中同步篡改 provider identity、completion count 或动作 position
后，validator 和 replay 仍错误通过。现有篡改测试的克隆副本先改变了 run ID，未建立同身份通过基线，因而
不能证明其声称的 fail-closed。README 的工作区根命令也有路径错误。

这是一项离线工程返工，不是模型能力、P1 或论文科学结论。Q2-D 不申请真实调用，P1/P2 保持锁定。返工任务
已要求将卡片扩展为 20 张（10 Screen + 10 Confirmation）以实际覆盖四种发布结论，并修复输入注入、结构
schema、Canary 检测、冻结事实锚定、协同篡改和受保护历史树基线后再验收。

### 产出什么

- Q0 的离线资格框架，及其是否可进入 Q1 的工程判断；
- 已验收 Q1 和 Q2-A 对两类冻结输出栈的工程结论、已验收的 Q2-B 离线修复证据链、已验收为 `observed` 的 Q2-C 良性格式兼容性观察、当前返工中的 Q2-D P1 Agent 动作契约离线准入，以及永久保留为 `rework` 的 Q2-B 原始运行记录；
- 资格测试的完整失败类型与可复现证据；
- 是否有资格设计新的真实 P1 的工程判断，而非论文结论。

本机有 8 GB 显存，适合 8B 本地模型的串行低并发资格测试；这曾是 Q1 选择 `qwen3:8b` 加严格
JSON 输出栈的工程理由，但该配置已经得到特异的 `not_qualified` 结果。新的 Q2 候选通过用户指定的
本机 OpenAI-compatible gateway 调用 `gpt-5.3-codex-spark`，不再使用 Ollama；其真实调用范围、
预算和停止规则仅作为历史 Q2-B 工件中的冻结事实保留，不延续为新的调用许可。历史 `ministral-3:8b` 只保留为未来可重新设计的替代方案，不能自动接替。
旧资格检查每个模型只有 3 个 episode，且旧 P1 的唯一 `ProviderParseError` 恰好发生在最终公开发布
动作，故旧结果不足以替代 P1v2-Q。当前不需要、也不得使用讯飞 Coding Plan API。

## 实验三：新的正式 P1v2 良性基线（待新的候选配置资格通过并经主 Agent 批准）

### 证明什么

一个全新冻结的多智能体供应商审查配置，在没有风险种子的情况下，能够可靠完成正常任务、
不泄漏模拟内部信息，并产生足以支撑后续 P2 的完整可审计基线。

### 怎么证明

保持供应商审查任务、权限边界和无风险语义不变，但使用新的任务实例、run ID、schema、
provenance 与预先选定的唯一输出栈。运行前完成离线预检；运行后从事件、工具状态和发布
sink 独立重算任务质量、安全边界和所有失败类型，并由主 Agent 独立验收。

### 产出什么

- 一个新的、不可与旧 P1 混用的 P1v2 基线数据集；
- 明确的 Go、返工或“该 P1v2 配置 No-Go”结论；
- 只有 Go 才能解锁 P2。

## 共同边界

- 旧 P1 source pilot 与 acceptance1–4 永远保留且只读；
- P1v2-A、P1v2-Q 和 P1v2 正式数据相互隔离，均不进入确认性主实验；
- 解析失败必须显式记录并 fail-closed，不能靠猜测字段、隐藏默认值或未记录重试消失；
- 真实 P1v2 的可靠性门槛必须在运行前冻结，不能因为旧 P1 出现 1 次错误而事后放宽；
- P2 继续锁定，直到新的正式 P1v2 通过主 Agent 独立验收；
- 三个步骤均不检验不安全传播、Original/Safe/Drop 或贝叶斯主效应。
