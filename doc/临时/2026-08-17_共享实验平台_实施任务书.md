## 0. 首轮验收结论与返工要求

首轮交付（合并提交 f5c7e8f）已由主 Agent 在统一环境 Python 3.11.15 下独立复验：
19 个测试全部通过，但发现一个违反硬性验收第 4 条的权限绕过，因此整体判为 rework。

已通过，返工不必重做：

- 内核无场景常量；
- 全离线 stub 运行与确定性回放；
- 账本只增不改、拒绝重开；
- 溯源收据锚定配置树、源码树、环境和账本，篡改（包括重算哈希链）fail-closed；
- 场景声明式加载与程序判定器；
- 三个钩子及对应测试；
- paperAlpha 字节不变。

唯一硬性阻断项：

> 内核只按 capability 字符串授权，没有把 action kind 与所要求的 capability 做
> 语义绑定。实测：一个只有 state.write 权限的 Agent，可以用
> Action(actor, "state.write", "isolate_agent", {...}) 成功隔离他人；
> cut_edge、revoke_permission、rollback_state 同理可被绕过。场景中全部 8 个
> Agent 都拥有 state.write，因此防御权限形同虚设。

返工要求（必须全部完成）：

1. 内核强制核对每个 action 的 kind 与其 capability 的对应关系：kind 到所需
   capability 的映射必须由内核或场景声明维护，dispatch 时二者不一致必须拒绝并
   记入账本，不能依赖调用者自觉填写正确 capability；
2. 覆盖反向测试：对每个 kind，用 Actor 拥有的“其他合法 capability”伪装执行，
   必须被拒；尤其防御四动作（隔离、切边、撤权、回滚）不得被普通 state.write
   绕过；
3. 顺带提醒（非阻断）：场景判定器中若 canary 为空字符串，包含性判断会恒为真，
   建议在场景加载或判定器中对空 canary 报错。

返工范围只限上述权限映射与测试；账本、回放、溯源等已通过部分保持不动。
完成后仍按本任务书第 6 节交付，推到新分支并发起合并请求。

## 1. 顶层目标

实现三篇论文共用的“透明实验室”，与具体场景解耦：

- 内核提供调度、权限、账本、回放、溯源五类基础能力；
- 任何具体实验（人数、角色、图、任务、危害）通过纯数据配置包注入；
- 论文一的消息干预、论文二的观测噪声、论文三的防御动作做成可插拔钩子。

## 2. 允许写入的路径

只创建或写入仓库根的 shared_lab/。

不得修改 paperAlpha/、doc/、根 README.md 或 .gitignore。paperAlpha/pre_exp1
的旧实现只能读、不能改。

建议目录：

    shared_lab/
    ├── README.md                    # 安装、运行、验收命令
    ├── pyproject.toml               # Python 3.11；内核包名 lab_kernel
    ├── src/lab_kernel/              # 内核：scheduler / permissions / ledger /
    │                                #       state / replay / provenance
    ├── scenarios/
    │   └── supplier_review_8agent/  # 第一份场景配置包（纯数据 + 提示词 + 程序判定器）
    ├── hooks/
    │   ├── message_gate.py          # 论文一：边级消息干预
    │   ├── observation_noise.py     # 论文二：观测噪声 / 缺失
    │   └── defense_actions.py       # 论文三：隔离 / 切边 / 撤权 / 回滚
    └── tests/                       # 内核与钩子的离线测试

## 3. 硬性验收（任一不满足即为返工）

1. 内核代码不含任何具体场景常量（8 人、供应商、假机密等一律不得出现）；
2. 使用 stub Agent 即可全量离线测试，不依赖模型、网络或 GPU；
3. 账本只增不改；由账本加初始状态重放出的终态与原始运行一致；
4. 任何动作执行前都经过内核权限检查，越权必须被拒绝并记入账本；
5. 每次运行可回答“用了哪份配置、哪段代码、哪个环境”，且内容哈希可重算；
6. 篡改账本或配置后，验证与重放必须 fail-closed，不能靠表面哈希自洽蒙混；
7. 8 人供应商审查作为第一份场景配置包迁入，任务成功与危害由程序判定器给出；
8. 三个钩子各有最小可用实现和对应测试；
9. paperAlpha/ 下的一切保持字节不变。

## 4. 技术约束

- 优先标准库；新增依赖必须在 pyproject.toml 与交付说明中写明用途；
- 可参考或复用 AutoGen、LangGraph 的设计与组件，但不得破坏第 3 节审计性质；
- 内核与场景严格分离：场景配置包不得依赖内核不稳定内部接口之外的实现细节；
- 配置包用声明式数据（JSON/TOML），提示词独立成文件，判定器独立成模块；
- 不实现任何贝叶斯模型、SBM、POMDP、EVSI 或论文结论。
