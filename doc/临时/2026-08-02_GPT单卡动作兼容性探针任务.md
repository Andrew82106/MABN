# 任务书：GPT 单卡动作兼容性探针（Q2-E）

> 状态：人工 smoke 已完成；未进入任务书规定的工程实施与验收。  
> 用户授权：在 2026-08-02 的渐进式模型调用授权范围内，共进行了 3 次无工具、无真实数据的 completion；没有模型列表请求、重试、模型切换或工具执行。  
> 性质：工程观察，不是 P1、多 Agent 实验、模型资格结论或论文证据。

> **人工 smoke 结果：**第一次使用 `strict_json_schema` 的请求收到 HTTP 400，未进入模型生成；第二次使用 `json_object` 到达正确模型、返回 JSON 且无工具调用，但动作形状不匹配；第三次使用带明确动作字段形状的 `json_object` 提示后，返回 JSON 通过结构和语义检查。三次均未持久化原始请求、原始回答、错误正文或凭据。该结果是“一个良性协调动作可由该模型完成”的有限观察，不产生正式 `observed`、`not_compatible` 或 `rework` 工程结论，因为尚未运行 fake preflight、one-shot guard、模型列表检查、validation 或 replay。不得把它解释为 P1/P2 通行或 Q2-D 资格通过。

## 1. 顶层目标

### 证明什么

用户指定的 `gpt-5.3-codex-spark` 能否在一个**良性、无敏感数据**的 Agent 工作位置中，根据实际输入事实，返回可被程序严格检查的结构化动作。

本任务只检查“协调 Agent 请求内部记录”的一个动作描述。模型不会连接其他 Agent、不会读取内部数据库、不会调用工具，也不会发布任何内容。

### 怎么证明

先在本地 fake transport 上验证同一请求构造、结构检查、语义检查、证据记录和离线复核流程；通过后才使用冻结的 gateway、模型和单张良性卡执行：

1. 最多一次 `GET /v1/models`，确认目标模型在返回列表中；
2. 最多一次 `/v1/chat/completions`；
3. 要求模型只返回一个 JSON 动作对象；
4. 用两层检查判断输出：JSON schema 只限制结构和允许的角色/字段，独立语义检查再核对它是否真的使用了输入中的虚构供应商编号；
5. 只保存安全摘要、长度、哈希和结果类别，绝不保存原始请求、原始回答、Authorization 或密钥；
6. 运行后以纯离线方式执行 `validate → replay → validate`。

### 产出什么

- 一个独立、一次性的真实调用记录，结论只能是 `observed`、`not_compatible` 或 `rework`；
- 对“GPT 是否能完成一个真实 P1 形状动作”的最小工程观察；
- 可由主 Agent 独立验收的安全工件和复现命令。

**不产出：**8-Agent 任务成功率、Canary 泄漏、风险传播、Original/Safe/Drop 效应、P1 Go、P2 Go 或模型总体资格结论。

## 2. 冻结实验对象

唯一输入是虚构供应商 `V-041` 的良性审查事实。协调 Agent 需要向“内部记录查询角色”发出一份结构化请求，仅请求公开报告允许使用的：

- `registration_status`；
- `risk_score`。

期望动作形状为 `kind=message`，并包含接收者、供应商编号和上述两个请求字段。供应商编号必须来自输入事实，不能通过 schema 的 `const` 预填答案；schema 只可验证编号格式、固定角色枚举和字段集合，独立语义 oracle 才比较精确值。

卡片中不得包含 Canary、真实数据、攻击文本、内部分类字段、工具参数或真实凭据。

## 5. 真实调用的冻结边界

本任务的唯一真实提供方配置为：

```text
Base URL：http://127.0.0.1:58661/v1
模型 ID：gpt-5.3-codex-spark
接口：OpenAI-compatible
```

从 `paperAlpha/.env` 仅读取下列变量，并且只能在已写入 one-shot guard、即将发起真实调用时读取：

```text
P1V2_Q2_BASE_URL
P1V2_Q2_API_KEY
P1V2_Q2_MODEL
```

硬性限制：

- 只接受上述精确 endpoint 和模型，否则在联网前 fail-closed；
- 并发 `1`、重试 `0`、不切换模型或 provider；
- `stream: false`；不发送 `tools`、`tool_choice`、`temperature`、`top_p`、`max_tokens` 或 `seed`；
- 使用 OpenAI-compatible `response_format: {type: json_schema}`，schema 为单卡结构 schema；
- 最多 1 次模型列表请求和 1 次 completion；任一错误立即停止；
- 总 wall-clock 上限 90 秒；不得超时后再发起任何 I/O；
- 禁止任何工具执行、公开发布、文件外发、Ollama、讯飞、其他 endpoint 或其他模型；
- `validate` 与 `replay` 永不读取 `.env`、永不联网；
- `.env`、密钥、Authorization、完整请求、完整响应、服务端错误正文、模型推理内容不得写入磁盘、日志、测试输出、report 或交付回复。

真实调用前，必须先用 fake transport 通过下列最小负测：成功输出、非 JSON、结构合法但供应商编号错误、错误模型身份、HTTP/超时、one-shot 已消耗，以及 validation/replay 的零网络/零凭据读取。

## 6. 实现与运行顺序

1. 建立独立、最小的代码和数据根；不得复制历史 runner。
2. 通过 fake transport 完成全部单元测试、fake run 与公开 `validate → replay → validate`。
3. 建立 one-shot guard；guard 必须在读取 `.env` 或建立连接**之前**原子写入。若已有 guard，禁止任何真实 I/O。
4. 若第 2 步的任一测试或 fake 验证失败：停止，报告 `rework`，**绝不调用模型**。
5. 若 preflight 全部通过：严格在第 5 节预算内进行唯一 live run。
6. live run 无论成功、模型输出不合格或基础设施失败，都不得重试；写入安全摘要后清除内存中的 API key 引用。
7. 对 live 工件离线运行公开 `validate → replay → validate`；清理 `__pycache__`、`.pytest_cache` 和临时篡改目录；停止等待主 Agent 验收。

## 7. 判定规则

- `observed`：目标模型在 metadata 中可见，唯一 completion 以正确模型身份返回，输出同时通过结构和语义检查，且离线 validation/replay 全部通过。
- `not_compatible`：真实 completion 返回，但内容、结构、模型身份或动作语义不符合冻结契约。不得重试或改提示。
- `rework`：preflight、one-shot、凭据边界、网络边界、工件完整性、超时控制或离线复核存在任何问题。

三个结论都不解锁 P1 或 P2。正式 Q2-D 仍需完成其独立离线返工并接受主 Agent 验收。
