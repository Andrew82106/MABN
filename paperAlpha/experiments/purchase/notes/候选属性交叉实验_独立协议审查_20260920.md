# 候选属性交叉实验：独立协议审查（2026-09-20）

## 结论

该实验可以支持一个窄结论：在固定的双买方、本地模拟购买协议中，使用冻结模型，可在规划者回复之后、两个买方请求之前，对后续本地执行风险做前瞻预测；24 条运行的预测时序、实际执行标签和重放链路完整。

它不能支持因果偏好、新风险族泛化、真实购买/真实伤害检测、一般多智能体系统优越性或 BN 优于同信息逻辑回归。当前最需收紧的是基线命名、迁移边界和失败运行验证。

## 协议核验

### 1. 未来信息隔离：通过，但条件必须写清

`collect_crossed_purchase.py` 先取得规划者回复并写入 `forecast_prefix`，随后运行冻结评分器、写入 `frozen_forecast`，最后才发出两个买方请求。24 条原始运行均满足连续事件序号，且预测标记先于首个买方请求。

评分器枚举已知的本地调度状态和冻结政策来计算预测风险，没有读取未来买方回复、未来选择或实际结果。因此不存在实际未来标签泄漏。

但这是“已观察规划者回复后的预测”，不是会话开始前的预测；结论应明确条件化于已准备的输入、规划者输出和有效命令协议。

### 2. 实际执行标签：通过，但只代表本地模拟执行

完整运行的标签来自两个买方真实 API 回复经解析后触发的 `SimulatedDispatchSlots` 本地执行记录，再由确定性政策计算违规结果。它不是从模型的行动承诺、解释文本或评分器自身反推的标签。

因此可称为“实际本地模拟调度标签”，不可称为真实购买、真实财务损失或现实伤害标签。

### 3. 冻结来源与参数：主体通过，环境冻结仍有小缺口

- PLAN 中 118 个源文件与当前工作区、冻结 `source/` 均逐项匹配，无缺失或哈希差异。
- 8 个模型与父实验 `choice_attribute_final_20260920` 的模型文件逐项匹配；父 PLAN、REPORT 绑定也匹配。
- 采集固定了模型名、API 参数、请求协议、并发数和 `new_fits=0`；每条运行的报告及文件哈希均匹配。

小缺口：数值评分环境只记录了 Python 可执行文件路径，没有冻结解释器哈希及 NumPy/SciPy 等包版本。现有精确重放结果降低了风险，但跨机器长期复现仍不完全封闭。

### 4. 失败处理：采集排除正确，失败后的部分执行验证不完整

采集器将异常写为失败，不把失败当负例；验证和指标只纳入完整运行，方向正确。现有 24 条运行全部完整，因此当前指标未受失败样本污染。

但 `verify_crossed_purchase.py` 在“已有预测、运行失败”时，验证完前缀和预测后即返回，不再语义核验可能已经发生的买方回复、解析结果或部分本地调度。现有测试覆盖首个买方失败/拒绝/不完整回复，没有覆盖“第一个买方已执行、第二个买方失败”的部分执行路径。

结论：失败不会被错标进指标，但“失败运行均完成执行语义审计”目前不能声称。

### 5. 公平比较：同队列可比，但两类基线解释需修正

**同信息基线数量。** 六个 standalone 变体中，只有两个 `standalone_full_*` 与两个 BN 使用完整的同一组特征；四个 `cost_only` / `warranty_only` 是预声明的特征消融，不是同信息逻辑回归。若把六个都概括为“同信息 logit”，会夸大公平对照数量。

**规则名称。** `lowest_cost` 实际按 `(cost, -warranty, index)` 排序，`longest_warranty` 实际按 `(-warranty, cost, index)` 排序。两者在主属性相同时会使用另一属性，因此是双属性字典序规则，不是纯成本/纯保修规则；其分数不能解释为单属性基线的表现。

完整特征 standalone 与对应 BN 的原始预测几乎相同（最大联合概率差约 `3.3e-12`，另一惩罚下为机器精度量级），本队列没有显示 BN 的结构或预测优势。

### 6. “未见数据/迁移”边界：只能作窄表述

交叉实验新增了 museum/workshop 两个名义域，并重新组合价格、保修、SKU 和展示顺序；SKU 与顺序总体平衡，四个 profile 各有 6 条运行，旧的价格/保修精确混杂被打破。

但 3 条 brief 文本直接复用了基础案例中索引 0、2、4 的文本，而父模型训练队列已包含这些相同 brief。模型不直接读取原始 brief，因此这不是直接特征或标签泄漏；不过它也不是对新需求文本、新政策或新工作流的泛化验证。更准确的说法是“在既有 brief/协议下，对新属性组合和名义域的冻结迁移检查”。

## 可支持与不可支持的结论

可支持：

- 冻结模型在该固定协议中的前瞻、可重放预测。
- 标签锚定于 API 回复驱动的实际本地模拟调度，而非行动宣称。
- 交叉设计打破了旧队列中的价格/保修对比混杂；独立特征与生产特征一致。
- 完整特征逻辑回归可复现 BN 预测；本队列未显示 BN 优势。
- `priority_value` 规则在该小型、定制队列中最好，但这只是队列内结果。

不可支持：

- 价格或保修对买方选择的因果效应。
- 对新 brief、新政策、新工作流或一般风险族的泛化。
- BN、任一规则或该监控方法对一般多智能体系统的优越性。
- 真实购买、真实损失或现实伤害检测。
- 对失败、缺失保修、拒答或分布外输入的校准性能。

`TEST_JUNIT.xml` 中的既有测试结果只能作为实现和协议机制证据，不能作为独立效果证据。
