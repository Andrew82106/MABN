# 共享消息的分组学习与重复实验

本轮推进“知识驱动的系统风险图”中尚缺真实证据的一环：同一上游消息影响多个 Agent 时，现有事件状态能否充分描述其联合行为。现有图已经能够对未来共同审核事件求和；缺的不是再画一个共享节点，而是有真实重复观测、合适训练目标和公平对照来检验它。

本轮没有新 API 生成，没有新增真实训练成绩，不替换默认模型。当前本地接口不可连接，因此先完成分组训练、采集、离线诊断及四折评测实现。完整测试的最终状态以本页验收节为准，不把计划当结果。

## 分组训练为什么必要

设一次上游运行产生审核消息 H，随后对这份真实消息进行两次下游续跑，分别得到两位发布者的结果 A1、B1 与 A2、B2。完整组的似然是：

`P(H | 当前前缀) × P(A1,B1 | H,前缀) × P(A2,B2 | H,前缀)`。

不能把它拆成两条独立全流程后，将同一次 H 计算两遍。共享审核事件只监督一次，每次真正新增的下游调用分别监督；训练损失按上游组数归一化，加既定 L2 正则。它是标准分组联合似然，不是新的潜变量理论。

`grouped_event_learning.py` 已支持祖先完整的前缀、完整审核块和至少一次完整续跑，与现有 25 参数事件概率模型连接。只有一次续跑时退化为原完整轨迹目标；多次续跑与显式展开真实调用的 DAG 目标一致。它不支持部分标签的分组训练、缺失历史或整消息门控因子。未知授权先验未在本入口拟合。

同一响应记录不能冒充多个 Agent 或多个独立回复。前缀与未来标签统一检查记录身份、原文、时刻和生产者；同一消息可标注多个不同字面字段，但不能重复计入同一字段。记录号唯一仍不证明采样独立。

## 固定的开发采集

预定四个虚构任务，每个任务重复六次，比较共享审核者与分别审核两种布局；每次上游运行接两对下游续跑。共 48 个上游组、最多 96 对完整续跑、最多 264 次请求。API 固定为用户指定本地接口上的 gpt-5.5，low；不改变聊天任务的模型或思考设置。

同一基础任务的源文本、追踪编号、任务要求和审核提示跨重复与布局保持相同，不将实验编号或布局名放进 Agent 输入。共享布局将同一条实际审核回复交给两个发布者；分别审核布局各自取得实际回复。因此比较的是“复用一次审核输出”与“重新取得两次审核输出”，不是把同一份已产生的输出重接线后的反事实实验。

任务包括编号对收件人有用途的情形，以及普通通知对照。所有编号均为自编虚构信息；外发禁止由实验政策规定，不表示现实隐私伤害。审核提示与任务用途并未完全交叉，因此不能用不同任务的差异识别审核政策的因果效应。部分通知主题沿用已有开发协议；不得称新领域或新风险族泛化。

保存早期、各次发布调用前的真实前缀及完整请求和可见回复。续跑使用新上下文，不把上一续跑的发布结果传给下一续跑。拒答、截断和传输失败保留为失败，不补成负例、不重试、不按结果补采。响应完成状态的处理参照 [OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode)；本协议使用普通文本输出，不宣称 JSON 模式提供这些任务的语义保证。

采集准备与实际采集分别记录解释器哈希、Python 和相关包版本；不记录凭据或完整环境变量。复验检查提供方响应 ID 与返回模型：缺失、重复响应 ID 或未预声明模型使相关组失去统计资格，但所有原始记录、完成数和失败仍保留。相同文字不作为去重依据。

## 怎样检验共享关系

先按基础任务和布局分别分析，再按实际审核字段出现位进一步分层。统计先在上游组内平均续跑，再对组等权；不把 96 对续跑当成 96 个独立上游实验。

报告四种联合结果的频率、各分支出现率、至少一次出现率，以及描述性的组内和组间协方差。该分解仅是样本恒等式；两次重复不足以把组间变化直接解释成潜在消息倾向。

进一步比较两个交叉乘积：同一上游组中不同续跑的 `A_k B_l`（k 不等于 l），与不同上游组的 A、B 均值交叉乘积。两边都只使用至少两次完整续跑的相同组集合；组不足两组时明确不可估。另报告同续跑乘积与交叉续跑乘积的差。

只有在上游采样分布稳定、不同上游组独立、给定完整实际输入后续跑独立等假设下，交叉差才能对应消息条件响应倾向的协方差。审核位相同后的剩余关联可能来自遗漏措辞、API 漂移、选择偏差或样本噪声，不是措辞因果效应。小样本估计可为负或超出理论协方差范围，不裁剪、不作显著性或校准声明。

同时检查未来标签覆盖及 25 列特征的秩。图里存在某类节点，不等于这次数据监督了那类节点；没有变化的标签和特征不能支持对应的学习结论。

## 预定的公平评测

四个基础任务分别留出一折；同一任务的所有布局、重复和续跑必须同折。它是四折开发交叉验证，不是独立最终测试。正则 0.001 和 0.03 都预先列出，不据结果选新默认。

比较四种方法：

1. 精确联合事件 BN。
2. 保持该模型每个分支的边缘概率，只在推断时去掉分支依赖，不重训。
3. 去掉上游特征后重新训练，其他监督和损失尺度不变。
4. 独立实现的同特征、同中间监督局部 GLM，再按同图计算。理论上应复现基础事件 BN，作为公平性与实现检查，不期待它因名字不同而更差。

分别在审核前和审核后评分；后者只加入本组实际审核回复，不加入任何发布回复。当前图给定所有审核位后，两名发布者条件独立，所以审核后方法 1 与 2 应一致；这个性质需直接核验。分别审核布局的审核前预测在当前结构下也应独立。

报告四状态联合 Brier、联合对数损失、分支 Brier 和至少一次违规的 Brier，保留每组预测及方法间差值。先组内平均，再任务与布局等权汇总。所有方法使用相同可评分集合；一对完整续跑可进入已声明的完整样本评测，但至少两次重复才可进入交叉乘积诊断，分母分开报告。

由于 retain 和 remove 各只在一个基础任务出现，留一任务训练可能没有相应提示特征覆盖。必须报告每折的设计秩、标签分布和训练未见线索，不能把外推失败藏成平均分，也不能事后改划分。

## 旧实验修复与边界

同步补齐两项审计：风险范围证书拒绝 NaN、无穷及维度不符；采购失败流程仍逐条核验失败前已经完成的本地执行，不产生缺失结局标签。这些是计算和协议修复，不是新模型准确率。

旧范围分析的 48 份报告共 240 个查询，其中 144 个恒零；系统总风险与累计预算查询在每份报告里重合，且本批没有未知授权块。因此 480 个上下界不是 480 种独立风险机制。源码一致性只对应各次冻结时刻，不能把修复后的当前源码仍说成与旧快照完全相同。
