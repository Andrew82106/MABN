# 并行发布流程：可见授权对照与分组数据

后续进展：[分支局部状态BN：训练对照与结构失活诊断](分支局部状态BN_训练对照与结构失活诊断_20260920.md)已完成模型训练；[冻结留出API评测](../../../docs/design/分支BN_冻结留出API评测_20260920.md)也已完成原8个测试流程。下文保留采集当时的状态，“测试未运行”不代表当前事实。

## 本轮实际完成

把原先单执行者流程扩成四个独立角色上下文：**planner → {worker-a, worker-b} → publisher**。两个执行者分别取得自己的记录，不能读取另一分支回复；发布者接收两份实际工作单及自己的授权缓存。

冻结了六个相关对账模板、每模板四种授权条件，共 24 个运行配置，按模板固定为 8 训练、8 验证、8 测试。本轮只运行训练和验证：**16 个流程、64 次真实 API 请求全部完成；8 个测试流程尚未生成任何回复。**

32 个被追踪编号中，18 个最终保留、14 个最终省略。补上了此前缺少的“已在内部出现，最终却被过滤”的对照。

这轮没有训练新模型，没有新的测试集成绩。基线诊断还表明，本批行为恰好能被“遵循可见授权”的简单规则解释，**不能宣称复杂 BN 已有优势**。

## 1. 工作流和数据边界

规划者只收到任务和分支标签，没有原始记录或编号。两个执行者收到相同的实际规划文本，但各自只有一行原始记录，独立计算差额。发布者不直接读取原始资料，而是汇总两份实际执行者回复。

四个角色均通过单独的 API 请求上下文实现，使用同一个指定模型；不是四种不同模型，也没有自主工具调用。全部资料为虚构，最终回复保存在本地，不真正发布到外部接收方。

工作流是显式配置的固定 DAG，不是大模型自动发现。全局最多两个 API 请求并发，16 个流程中有 13 个实际发生两个执行者请求时间重叠；其余受到共享并发配额影响，没有因此增加分支间依赖。

测试与开发模板互不重复，但六个模板均为相关的对账任务，不能当作六种高度独立的业务类别。每个模板固定采用共享根或分离根授权，各数据划分内平衡；布局与模板绑定，**不能拿它们做随机化布局效应比较**。

## 2. 四种可见授权条件

| 条件 | 当前授权事实 | 发布者收到的缓存 |
|---|---|---|
| 有效且可见 | 有效 | 完整的有效引用链 |
| 撤销但缓存旧 | 两个执行者回复后撤销 root-a | 撤销前的缓存 |
| 撤销且刷新 | 同样撤销 root-a | 包含真实撤销记录 |
| 有效但缺父链 | 实际仍有效 | 只收到子授权，缺少父链 |

授权服务在两个执行者完成后才变更状态；最终发布窗口内不再修改。条件名称不传给模型，实际缓存记录才进入发布者输入。正常/危险标签由最终真实文本及独立的引用政策检查决定，采集器不强制最终保留或泄漏。

发布者被要求缺证据时使用公开分支标签和允许的数量，不在“说明省略原因”时重新复述受限编号。本规则对全部条件一致，没有看到结果后改单个提示词。

## 3. 数据划分和后续评测规则

划分在第一条 API 请求前固定：

- 训练：采购报价、实验室盘点，两个模板各四条件。
- 验证：排班分钟、发货重量，两个模板各四条件。
- 测试：项目账目、文档登记，两个模板各四条件，**本轮未运行**。

当前采集入口只有 `prepare` 和 `development` 模式，不提供直接运行测试的选项。后续必须先固定数值模型、候选参数范围、选择结果、同信息 baseline 和评测代码，再单独执行这八个已冻结测试配置。当前还没有完成这个训练与测试启动环节。

主目标是至少一项最终引用违规，至少两项为次目标。超参数仅在验证集选择；任务/条件/模板标识不作为评分特征。所有方法都应得到相同的分支消息、字段归属、当前权限和发布者可见线索。

计划保留的强基线包括：当前出现持久性规则、可见授权遵循规则、同字段监督的 Logistic 和小型树模型，以及已有 BN 的显式合并分支版本。**候选数值实现和具体网格仍待冻结**，不能把已列出名称说成已经跑完所有 baseline。

## 4. 接入模型时不丢掉分支

新增 `BranchPrivacyInput` 保存：

- 固定 DAG 和执行者列表；
- 每个追踪值的宿主声明归属；
- 每个值在每个实际执行者回复中是否出现的矩阵；
- 与两份回复逐字绑定的发布者请求、可见授权线索；
- 独立的当前授权证明图及时间边界。

比如本批一个编号只在 worker-a 出现，另一个只在 worker-b 出现，矩阵是两行两列的对角形式，不能只保存“两项都出现过”。测试也覆盖编号在非归属执行者输出中出现的情况，保留实际观察，不按配置强行修正。

兼容旧模型的 `pooled_scope` 仍存在，但明确标记为合并投影。**已有单执行者 U 状态并没有因此自动变成两个执行者各自的状态。**下一步需实现分支局部状态及汇聚，再把合并投影当作消融对照。

新接口按每份实际消息匹配字面值，避免 JSON 容器转义改变带引号/反斜杠的值，导致合并文本匹配漏掉。本批编号均不受影响，16 个新输入与原合并出现指示一致；单元测试另验证这个序列化边界。旧数据和旧评分不回写。

## 5. 实际结果与强规则诊断

| 条件 | 完整流程 | 最终保留编号/总数 | 至少一项违规的流程 |
|---|---:|---:|---:|
| 有效且可见 | 4 | 8/8 | 0 |
| 撤销但缓存旧 | 4 | 8/8 | 4 |
| 撤销且刷新 | 4 | 2/8 | 0 |
| 有效但缺父链 | 4 | 0/8 | 0 |

刷新条件仍保留的两个编号来自分离根布局：root-a 被撤销，但第二个编号来自仍有效的 root-b，不是违反了撤销规则。

逐值的实际观察：

- C0/W1/F1：18 项。
- C0/W1/F0：14 项。
- 可见支持时保留：18 项；可见反对时省略：6 项；缺父链时省略：8 项。

C 表示规划文本，W 为该编号所属执行者的实际回复；另外仍单独保存其他执行者是否也出现该编号。规划者没有私有编号，所以本批 C 均为 0。

对冻结计划要求保留的两个规则，按同一个发布前输入计算，仅作开发诊断：

| 规则 | 训练：至少1项 Brier | 验证：至少1项 Brier | 训练/验证：至少2项 Brier |
|---|---:|---:|---:|
| 当前出现＋共享当前授权 | .25 | .25 | .125 / .125 |
| 当前出现×可见支持＋共享当前授权 | 0 | 0 | 0 / 0 |

分数越低越好。第二项预测“发布者会照可见授权执行”，再用真实当前授权判断预计披露是否违规；它不读取最终答复，当前授权也由前缀证明图重算，不从结局标签取值。

这说明本批有条件差异，但还没有出现偏离该简单规则的发布行为。它适合验证数据接口和开始条件学习，**不够证明复杂结构贡献、攻防泛化或强 MAS 监测性能**。也未独立评价计算结果是否正确或整个任务是否成功。

## 6. 实现、冻结和验收

- 运行定义：`src/paperalpha_runtime/branched_publisher_data.py`。
- 采集：`scripts/collect_branched_publisher_data.py`。
- 独立核验：`scripts/verify_branched_publisher_data.py`。
- 分支输入：`src/paperalpha_monitor/branch_privacy_input.py`。
- 冻结输入复算：`scripts/replay_branch_privacy_inputs.py`。

正式输出：

- `results/branched_publisher_data_20260920/PLAN.json`：全部配置、源代码哈希、划分和后续规则。
- 同目录 `development/`：真实原始请求/回复、服务变更、16 个发布前输入、逐流程结果。
- `results/branched_publisher_data_verified_20260920/`：核验报告、按训练/验证分开的派生材料。
- `results/branch_privacy_inputs_20260920/`：20 份源文件冻结、16 个分支输入重建和两个规则的开发诊断。

核验了 17 个采集产物哈希、全部实际请求与前序回复绑定、分支独立输入、并发上限、授权变更先后、最终标签及测试数据未生成。16 个前缀全部早于发布者 API 请求。失败分支不会被当作安全负例；测试桩已检查一侧失败时另一侧仍被等待和记录，且不继续生成最终答复。

实际调用指定 `gpt-5.5`、`low`、单次输出预算 3,200、60 秒超时、零重试；遵循 [OpenAI Docs 的截断处理说明](https://developers.openai.com/api/docs/guides/reasoning#controlling-costs)，只接纳完整可见回复，不混入 reasoning/commentary。任务本身的模型设置不改。

本轮整套回归 **1,085 项通过，4 条既有警告，110.32 秒**；随后新增的分支输入检查与采集测试共 **36 项通过**。后者多出的 8 项未包含在前一次全量运行中，不能改写成全量 1,093 项通过。测试桩输出仅存在测试临时目录，不混入研究运行。

## 7. 下一步与剩余差距

下一步应利用训练材料实现分支局部状态和汇聚，学习可见支持/反对/缺失条件，并和同样获得这些线索的强基线比较。只有模型及评测代码冻结后，才运行已保留的测试组。

若开发样本仍完全服从简单规则，不应靠调阈值宣布 BN 赢了；要明确它只能提供接口/机制证据，并寻找有独立依据的真实偏离行为与更丰富的系统级风险。

任意职责 DAG、知识模板自动生成、多风险统一学习、跨工作流验证及原版 MAS baseline 仍未完成。本轮是面向这些目标补充分支数据与输入结构，不把整篇工作重新缩小为单一授权分类器。无 Git 提交/推送，旧冻结结果不覆盖。
