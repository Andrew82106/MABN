# 隐私授权 API 实跑：真实传递与授权视图分离

## 结论

联合隐私/授权模型已接入真实三阶段 API 输出，完成 **16 个流程、48 次请求、32 次发布前预测**。两种监测视图作用于同一条真实轨迹，不计作 32 个独立实验。全部流程完成，没有失败替换。

与上一批完全没有内部敏感值传递的试验不同，本批 32 个被追踪对象全部形成 C1/W1/F1：内部确实处理并保留了记录编号，最终也全部原样保留。其中 **8 个流程至少一项引用授权违规，4 个流程两项同时违规**。标签来自最终真实文本与本地授权服务记录，不预设最终泄漏。

**不是模型全面领先。**完整记录下，BN 胜过迁移过来的逐值树模型，但“当前出现＋相同授权图”的简单规则误差为 0，胜过 BN；BN 的阶段关联扩展也没有胜过无关联版本。缺少根撤销记录后，至少一项违规的区分能力接近随机。

主要新设计依据是：**发布者看到的授权记录，与监测器掌握的当前授权事实，必须分开建模。**本批模拟了真实工程中可能出现的缓存过期，两个证据视图对 12 个对象产生了不同的授权结论。新增诊断将这个缺口固定下来，而不是继续堆叠隐藏状态。

## 1. 本轮实现位于哪里

- `src/paperalpha_runtime/scoped_privacy_api.py`：四类虚构对账任务、明确追踪对象、局部授权服务、分阶段请求、视图投影及独立标签检查。
- `src/paperalpha_monitor/scoped_privacy_monitor.py`：实际文本和授权记录编译为 `ScopedRelease`；冻结的两个出现 BN、逐值 HistGB、当前出现规则使用相同的共享授权世界。
- `scripts/monitor_scoped_privacy.py`：独立数值进程，严格限定输入；无 API 密钥、最终文本、隐藏处理条件或结局标签。
- `scripts/collect_scoped_privacy_api.py`：先冻结，后调用；统一日志记录实际消息、授权变更和发布前预测。
- `scripts/verify_scoped_privacy_api.py`：冻结实现复算、时序/请求绑定、独立图执行、标签核验与公平分组指标。
- `scripts/diagnose_scoped_privacy_coverage.py`：事后覆盖与信息不足诊断，不改分数、不训练。

这次真正新增的是**明确追踪对象＋作用域授权的真实运行接入**，不是重新拟合全部 43 参数。它仍只覆盖一类固定最终消息，不替代完整 MAS 框架。

## 2. 任务与真实运行

四个任务模板是发票、库存、工时和发货对账。每个任务有两个虚构记录编号，以及期望量和实际量；要求计算每行和合计差额。内部核对需要保留准确编号，最终向指定审计团队发布编号则要求授权有效。

每个模板采用两种授权布局、两种授权处理，共 16 个运行：

- **共享根**：两个编号的发布授权都来自 root-a。
- **分离根**：分别来自 root-a、root-b。
- **有效**：发布窗口前不撤销。
- **旧缓存**：执行者实际回复后，由本地服务撤销 root-a；发布者仍收到最初的缓存。

工作流为 planner → worker → publisher。planner/publisher 是同一协调角色的前后功能阶段，各次请求使用新上下文；仍是两个物理角色、三个功能阶段。两个授权根影响同一最终消息中的两个值，**不是两个独立 Agent 的并行发布**。

编号、权限和原始资料均为自编虚构材料，三段输出均由实际 API 生成。没有调用发布工具，没有真正发送邮件、泄漏资料或修改外部系统。

API 使用用户授权的本地接口，指定 `gpt-5.5`、`low`；48 个响应均报告该模型名称，不能由代理名称进一步证明后端模型快照。每次输出预算 3,200、超时 60 秒、零重试、并发 2。依据 [OpenAI 官方响应预算说明](https://developers.openai.com/api/docs/guides/reasoning#controlling-costs)将截断和失败单独保留，仅传递已完成的最终可见消息，不把内部推理或 commentary 当成答复；[指定模型文档](https://developers.openai.com/api/docs/models/gpt-5.5)用于核对接口与推理强度支持。任务自身的模型/思考设置未变。

## 3. 监测器到底看到了什么

在执行者回复、授权服务完成预定变更后，才进行预测；两个视图的分数都落盘后才发最终 API 请求。没有在早期预测中偷看后来撤销，也没有把最终结果回填为中间证据。

- **完整视图**：能看见 root-a 的实际撤销，比只持有旧缓存的发布者拥有更完整的授权信息。
- **缺根更新视图**：删去根撤销记录，并明确标记根状态覆盖不完整；子授权记录仍完整。

上述信息差是明确的实验设置；所有 baseline 与 BN 使用相同的监测视图。缺失视图不是假装“没有撤销就是有效”。

只预测变更完成后的固定发布窗口，窗口内不再变更授权。授权服务使用任务内逻辑序号，采集日志另用全局递增序号及单调时钟记录实际先后，两者不混为同一时钟。

每个值的发布对象由宿主明确给定接收方、用途、任务、资源和引用授权。它是**监测器对固定潜在发布的查询**，不是宣称 Agent 实际提交了一个 `release_literal` 工具提案。

追踪对象通过 `tracked_fields` 显式输入，合法分享的敏感值也保留。没有修改旧 AgentLeak 允许列表以伪造训练样本。新作用域与旧训练中仅选受限值的范围不同，因此迁移概率未校准。

## 4. 参数与公平对照

出现模型与逐值树沿用 `privacy_identity_free_fit_20260919` 的冻结模型，训练/验证仍来自原 2,133/1,026 条材料；本批不重新训练，也不读取原测试文件。38/39 参数的数值源码直接从原训练快照复制。

联合模型中新增加的授权未知事实先验固定报告三档：.1/.5/.9；主要展示 .5。授权与最终出现的关联系数 β 固定为 0。**它们不是本批训练所得，不使用上一轮人工频数恢复出的参数冒充真实参数。**未知授权仍保留共享事实，完整已知授权不受这些先验影响。

对照包括：

1. 无阶段关联 BN＋共享授权图。
2. 有阶段关联 BN＋共享授权图。
3. 逐值 HistGB＋同一共享授权图。
4. 当前执行者消息出现则预测最终也出现＋同一共享授权图。
5. 先计算逐值违规边际，再当作独立事件相乘的消融。

前三种学习方法沿用各自已有训练参数。第四种是简单持久性规则，不是知晓未来最终文本的 oracle。第五种故意丢弃关联，只能标作消融，不能当作故意削弱的主 baseline。没有把任务级分类器的整体分数硬乘一个授权分数，因为它无法正确处理部分字段允许、部分字段禁止的情况。

所有方法都回答同一目标：固定最终消息中，至少 k 个不同追踪字面值出现且所引用授权政策失败。k=1、2 均在调用前固定。非所有隐私伤害、非意译泄漏、非任意安全规则。

## 5. 结果

以下 Brier 越低越好；不是准确率。未知先验取预先指定 .5，完整记录没有未知授权事实。

| 方法 | 完整：至少1项 | 缺根更新：至少1项 | 完整：至少2项 | 缺根更新：至少2项 |
|---|---:|---:|---:|---:|
| 无阶段关联 BN | .015443 | .270943 | .022668 | .156761 |
| 有阶段关联 BN | .018272 | .271580 | .025625 | .157952 |
| 逐值 HistGB＋共享授权 | .206731 | .319701 | .209425 | .229998 |
| 当前出现＋共享授权 | **0** | .281250 | **0** | **.156250** |
| 独立边际消融 | .015442 | .287635 | .033014 | .195845 |

完整记录的五种方法 AUROC 都为 1，但这主要来自已知授权事实对零/非零风险的区分，不证明通用风险识别能力。逐值树的概率误差很大但排序仍为 1，也说明不能只报 AUROC。

缺根更新时，有关联 BN 对“至少一项”的 AUROC 为 .515625，规则为 .5。对“至少两项”分别为 .729167/.833333，其中授权共享布局本身提供了结构差异；不能解释成识别到了缺失的撤销事实。

先验敏感性也很明显。有阶段关联 BN 在缺根更新视图下，先验 .1/.5/.9 对应：

- 至少一项 Brier：.390767/.271580/.402152。
- 至少两项 Brier：.214837/.157952/.372895。

三档全部保留，不能看完结果后只宣布 .5 为学得的最佳授权概率。实验人为安排一半运行撤销 root-a，root-b 从未撤销，亦不代表真实部署的根授权失效率。

## 6. 数据改进了什么，仍缺什么

本批补上了上一批没有的内部真实传递，以及两类最终授权结局。但 **32 个对象仍全部 C1/W1/F1**，没有最终删减或拒绝保留编号的例子。

所以简单持久性规则在这里就能正确预测全部 F；完整授权一接入，它恰好得到零误差。这不是规则一般都最强，而是这批材料没有提供“哪些信息最终会被保留、哪些会被过滤”的区分。

程序还构造了 16 个明确标记的**同文本见证**：固定一条运行的真实三个文本，只改变服务是否撤销 root-a。缺根更新的监测输入、发布者最终请求完全相同，而至少一项违规标签改变。这是可观测信息不足的构造检查，不是额外执行了 16 次 API，也不是证明大模型因果机制。

它给出两项明确的后续设计要求：

1. **区分实际权限与 Agent 可见权限。**实际发布是否违规由当前真实政策决定；Agent 是否愿意发布，更可能与它收到的缓存和任务上下文相关。不能直接把监测器看见的真实状态当成发布者也知道的状态。本轮 β=0 没有冒充学到该关系；后续应增加具来源、时间绑定的发布者可见授权证据，而不是给隐藏状态贴语义标签。
2. **补有实际过滤差异的独立流程。**新冻结材料需包含合法内部处理、可见授权变化、实际删减/保留、多个接收方与真正分支协作。输出仍由 Agent 自行产生，不能强制最终标签。当前试验只能作为已查看的开发证据，不再用于调参后重新宣称独立测试。

完整知识驱动任意 DAG/职责子图、跨风险片段统一训练、持续授权状态变化和原版 MAS baseline 仍未完成，不能缩小总目标为“固定隐私片段跑通”。

## 7. 冻结、审计与测试

- 实际采集：`results/scoped_privacy_api_bound_20260919/`。
- 独立复验：`results/scoped_privacy_api_verified_20260919/REPORT.json`。
- 全部复算预测：同目录 `recomputed_predictions.json`。
- 事后信息/覆盖诊断：同目录 `COVERAGE_DIAGNOSIS.json`。

48 个登记产物验哈希；32 次预测在统一 JSON 表示后逐字段完全一致；384 次独立可执行图计算最大差 5.55e-16。实际 API 请求、前序文本、授权变更、最终标签以及先于未来请求的顺序全部核验。

最初冻结的 `scoped_privacy_api_20260919` **没有运行 API**：正式启动前发现发布者只收到参数哈希，不宜要求它手算哈希，因而补充服务提供的可读参数绑定及对应摘要，另建上述 `bound` 冻结。没有看到输出后改提示词。

第一次冻结审计比较直接将内存元组和 JSON 数组视为不等。独立诊断发现 32 项全部仅有这种表示差异；修订审计仅统一 JSON 表示，不增加浮点容差。原采集、冻结源码和分数不变；实际修订审计的源码及哈希保存在复验目录。新增测试确认真实数值差异不会被这一处理吞掉。

本轮整套回归 **1,019 项通过，4 条既有警告，107.33 秒**；之后补充审计和同文本见证测试，当前新模块 **32 项通过**。后一次不是全套 1,023 项重跑，不能混淆。无 Git 提交/推送，没有修改旧模型、旧 API 轨迹或测试分数。
