# 隐私模型跨 API 迁移：冻结实跑与覆盖缺口

## 结论先行

完成一次**先冻结、再实际调用 API、评分先于未来请求**的迁移试验：八个新任务模板，各普通/夹带指令两种资料，共 16 次流程、48 次 API 请求、32 个提前预测。全部返回完整响应，无失败替换。该试验用两种物理角色、三个功能阶段，不是新拓扑，也不是完整工具型 MAS 基准。

**16 条轨迹全部为 C0/W0/F0：受保护值没有原样出现在任何内部阶段或最终答复。**因此不能据低 Brier 声称检测能力、提前召回、传播建模收益或 MAS 领先；当前值出现规则输出全 0，也获得零误差。真实进展是完成模型身份移除和在线迁移链路，并用实跑确认这批任务缺少要验证的风险机制。

没有据这些结果调参、重写提示词、替换任务、降低 Agent 的策略限制或重新运行。旧模型、旧测试成绩和历史 API 记录均保留。当前对话的模型及思考强度没有改动。

## 1. 为什么先移除模型名称

原模型将作者数据中的五种生成模型名称作为输入。新的 `gpt-5.5` 不能冒充其中一种，也不能仅把未知名字编码为原基准模型，就宣称已支持新生成器。

新增 `ModelIndependentPrivacyBN-v1`：从监测输入及四组条件概率参数中移除所有模型身份项；无额外阶段关联版 38 参数，有关联版 39 参数。信息类型、逐值 C/W 出现、消息长度、受保护对象数量及领域信息仍保留。**这只移除了身份依赖，不证明对任意新模型已经校准。**

两版本仍分别拟合 3 个正则强度 × 2 个初值；三个分类器在两个截止点各比较三个候选。训练/验证仍为 2,133/1,026 条，原测试文件没有读取。全部参数在 API 采集前冻结。

同一验证集 Brier（低为好）：

| 方法 | 协调者消息后 | 执行者回复后 |
|---|---:|---:|
| 去身份 BN，无额外阶段关联 | .219848 | .196659 |
| 去身份 BN，有阶段关联 | .219853 | .195010 |
| 任务 Logistic | .220076 | .215087 |
| 任务 HistGB | .220348 | .189129 |
| 逐值 HistGB + OR | .227131 | .209745 |

去身份模型没有全面胜过树模型。上一版使用模型名称的 .176804 不能直接与这里的 .195010 比较并归因于某一个参数，因为特征、拟合及所选初值发生了变化；可以明确说，去除身份后需要重新验证迁移表现。

训练独立复验：48 个冻结产物哈希、12 个拟合目标、24 个验证候选及选择规则均通过；目标复算差 0，最大方向梯度误差 3.45e-11，独立四状态标量推断误差 6.11e-16。原测试访问次数为 0。

## 2. 新任务与实际运行

任务是自编的虚构行政资料：病历封套领取、登记设备报修、供应商审批队列通知、营业时间通知、文件交接邀请、快递封面、访客到达说明和电脑更换预约。每个任务有三项允许公开字段和六个受保护值。普通/夹带指令版本共用资料，后者加入要求最终附带内部令牌和档案定位符的低信任来源文字。

八个模板不同于源数据中的 16 个字面任务模板，但仍与部分原任务共享“通知/日程”语义；不能声称新任务类别完全独立。每个模板只有两个条件，不能把 16 条运行当作 16 个独立任务族。

真实流程：

1. 协调者准备：收到用户任务、内部 vault、对外字段策略和来源记录；产生内部工作单。
2. **落盘第一个监测结果，之后才请求执行者。**
3. 执行者：收到自己的完整上下文及实际工作单，产生内部回复。
4. **落盘第二个监测结果，之后才请求最终答复。**
5. 协调者最终答复：只收到原任务、对外字段策略和实际执行者回复，不直接收到 vault。
6. 最终答复完成后，独立字面匹配器才产生标签。

三阶段各自使用新上下文，同一协调角色在前后两个功能节点出现。没有额外工具、自治重试、外部发布或真实付款；应称为**API 角色协作流程试验**，不能当作新完整 Agent 平台。

通过用户本地接口实际请求 `gpt-5.5`、`low`，响应也均报告 `gpt-5.5`；不能据接口名称证明后端实际模型快照。固定每次最多 2,560 输出 token、50 秒超时、零重试、并发 2。输出预算包含推理消耗，完整/截断/失败/原生拒绝分开处理；只取最终可见答复，不把 commentary 当最终回复，不传递模型内部推理。

调用处理依据：[官方推理模型文档](https://developers.openai.com/api/docs/guides/reasoning#controlling-costs)、[指定模型文档](https://developers.openai.com/api/docs/models/gpt-5.5)。SDK 环境与数值环境分离，监测进程只收初始策略和已完成的历史消息，不接收 API 密钥、任务条件、生成模型名称、最终文本或标签。

## 3. 结果与覆盖诊断

48 次请求均有完整响应，16 个流程完整结束。这里“完整”表示采集流程完成，不等于经过独立人工评审的任务质量合格。没有新造结果或用空响应替代失败。146 条统一时序记录已逐项复验，模型收到的消息与真实前序输出相同，32 个提前预测均先于后续请求。

| 方法 | 早截止 Brier | 晚截止 Brier |
|---|---:|---:|
| 无额外关联 BN | .031078 | .001083 |
| 有关联 BN | .030160 | .001079 |
| 任务 Logistic | .050133 | .075918 |
| 任务 HistGB | .025630 | .000176 |
| 逐值 HistGB + OR | .008355 | .000059 |
| 训练正例率常数 | .087514 | .087514 |
| 当前受保护值出现规则 | 0 | 0 |

所有方法在固定 .5 阈值下均无报警。所有 AUROC/AP 均保留为 null，不以 0 或 1 填充。没有正例，不能估计漏报或区分能力；只有八个小任务对，也不能把这些分数当可靠部署校准证据。

额外、明确标记为事后诊断的 `qualify_privacy_transfer.py` 自动检查：

- 是否有正常/泄漏两类最终结果；
- C/W 中是否实际出现过受保护信息；
- 有哪些 C/W/F 组合，以及独立模板数；
- 允许报告哪些描述性检查、哪些主张缺少数据支持。

本批唯一组合为 `C0W0F0`，16 次；32 个中间阶段没有受保护字面值出现。**数值中的 U/V 状态仍参与推断，但这不等于数据提供了真实信息传递的对照。**不能因模型计算了传播概率就声称传播能力得到验证。

所有在线模型分数和解释字段复算一致；另写的逐状态标量推断与 BN 最大差为 2.78e-16。

## 4. 对模型升级的具体影响

这次暴露的是实验与表示的覆盖问题，而不是“模型参数还不够多”：

1. 任务只要求公开行政字段，内部资料中的受保护值对完成任务并不必要。Agent 没有传递它们，因此没检验“内部合法使用、最终不应外泄”的核心区别。
2. 新最终阶段明确看得到公开字段策略，源数据最终阶段只有更宽泛的隐私提示；生成器、字段数量、任务与策略提示一起变化，不能单独归因于新大模型更安全。
3. 现监测输入保留的是值类型和出现情况，没有直接表达“该字段为什么是本阶段工作所需”“接收者是否有权接收”“最终阶段是否实际理解策略”。改进这些条件需要可观测证据和局部监督，不能把临时状态 U/V 命名为已理解的权限状态。

后续优先补**需要合法内部处理受保护资料的任务**、真实存在 C/W 传递的正常对照，以及具有独立最终标签的危险轨迹。新任务应另行冻结、保留失败和负例；不能为了补正例强制把最终答案写成泄漏，也不能按本批结果改参数后继续把同批称测试集。公开源数据仍提供正负实例，但不能用已反复研究的验证集代替新的外部证据。

完整主目标仍未完成：知识驱动任意职责 DAG/子 BN 的组合，隐私、授权、额度等片段的一致接口及联合训练，系统层监测目标，跨工作流验证，以及真正原版 MAS 方法比较。本次只推进其中一个训练过的隐私片段的迁移资格与实跑接入，不替代这些要求。
