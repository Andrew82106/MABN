# 完整信息项事件 BN：变量消元与公开 MAS 开发验证

日期：2026-09-20。模型：`ObservableDAGWorkflowRiskBN-VE-v1`。

## 结论先行

本轮解决的是**完整轨迹的接入和精确推断容量**，不是取得新的领先成绩。公开开发数据中 2,133 条用于训练、1,026 条用于验证，共 3,159 条，所有受保护信息项均保留。验证较晚阶段 BN 的 AUROC 为 .71456，HistGB 为 .75006；BN 的概率误差也更大。较早阶段 BN 甚至没有胜过训练正例比例这个常数预测的 Brier 分数。

因此，之前少量自建流程上的满分不能用来宣称当前模型很强。当前结果说明：模型可以把逐条信息的未来出现概率算清楚，但现有结构与输入还不足以形成稳定的系统级预测优势。

本数据仅为此前使用过的 AgentLeak 训练/验证部分，**不是新独立测试**；本轮不读取旧测试数据，不更新发布默认模型，不调用 API，不修改任务模型或思考强度。

## 一、模型到底长什么样

### 1. 先固定功能工作流，区分功能节点与物理 Agent

本次根据锁定版本的实际请求构造器建立图，没有用大模型自动发现工作流：

```text
原始资料 ──→ 协调者准备 ──→ Worker 处理 ──→ 协调者对外答复
    └────────────────────→ Worker 处理
```

有两个物理 Agent，协调者出现于两个不同功能阶段，因此功能图无环。Worker 的系统提示中也包含完整资料，必须保留直接输入边，不能把 Worker 输出的一切都解释成来自协调者的传递。

AgentLeak 来源：[作者仓库](https://github.com/Privatris/AgentLeak)，锁定提交 `1301eb9245a03bbee8694ee2b74accbc8f6fefe6`。原始材料位于 `data/external/AgentLeak/benchmarks/ieee_repro/results/traces/`。本轮只使用既有开发划分对应的原始记录。

### 2. 每个功能节点里面，放有明确含义的事件

对每一个需要保护的字面值，建立四个二值事件：

- 它是否出现在原始资料文本中。
- 它是否出现在协调者给 Worker 的消息中。
- 它是否出现在 Worker 回复中。
- 它是否出现在最终对外回复中。

节点的 1/0 由真实完整文本核对，不是让一个没有监督的隐变量自行获得“危险”“意图”等含义。没有收到消息和收到完整消息但没有出现该值是两种状态。

本次每条轨迹含 9–13 组受保护值，形成 36–52 个事件节点。相同字面值的字段别名合并，原始允许列表和用户请求豁免规则保持不变，不为了适配容量删除字段。这里检测的是字面出现，不包含改写、编码、语义推断等泄漏方式。

### 3. 学习的是局部条件概率，而不是给节点写死风险分数

通用局部模板有五类功能：准备、处理、审核、发布、工具派发。每类共享五个系数：基础概率、支持线索、反对线索、父事件平均值、多父事件同时成立。概率由 logistic 函数得到：

```text
P(事件发生 | 父事件、可见线索)
  = sigmoid(基础项 + 支持项 + 反对项 + 父节点项 + 多父节点共同项)
```

这样不同节点可使用同类参数，但保留各自的事件身份和图上关系。模型有 25 个事件系数，以及既有授权部分的 3 个系数；本轮授权为已知静态事实，不拟合后三项。不是 28 个参数都从本数据获得了有效学习。

本次公开数据没有启用支持/反对文本特征，只训练 Worker 和最终发布事件。48,138 个未来事件标签对应的设计矩阵为 48,138 × 25，**秩只有 4**；可以学到四种条件概率，不能分别解释全部系数或称所有机制都已辨认。

以正则 .001 的拟合为例：

| 条件 | 对应事件的拟合概率 |
| --- | ---: |
| 资料中有该值，协调者消息没有 | Worker 提到该值约 3.80% |
| 资料及协调者消息都有该值 | Worker 提到该值约 67.86% |
| Worker 回复没有该值 | 最终回复出现该值约 0.30% |
| Worker 回复有该值 | 最终回复出现该值约 23.20% |

这些是本数据、本模板下学到的条件关联，不是因果效应，也不是适用于任意任务的固定概率。

### 4. 运行时只看已经发生的事，计算尚未发生的风险

较早预测点：协调者消息已产生，Worker 与最终回复仍未知。

较晚预测点：Worker 回复已产生，最终回复仍未知。

较早预测需把 Worker 的可能输出求和消去；较晚预测直接使用实际 Worker 事件。最终将未来出现事件与授权策略组合，计算“最终对外回复至少出现一个不允许值”的概率。

这不是将各 Agent 的风险分数取平均。一般组合器保留共享事件及共享授权依赖。本轮适配图的不同信息项之间没有共同随机节点，故此特定图恰好允许 `1 - 所有信息项都未泄漏的概率` 的逐项乘积核验；**不能把这种独立性当作任意 MAS 的事实**。

本轮的系统层是明确的概率与策略组合，不是额外训练一个不透明 GNN。本数据中的授权已知，所以系统风险查询简化为至少一项受保护值对外出现。此前实现过的授权、额度、组合危害等模块不能据此声称已在本数据统一训练和验证。

## 二、参数如何训练

每个训练流程只有一份联合训练目标：依据早期可见消息，预测后续 Worker 和最终回复中的逐值事件。使用真实未来文本产生监督标签，标签与运行时输入分开保存。

目标为每流程未来事件联合负对数似然，加 L2 正则；使用梯度优化。所有未来事件都被完整观察、且前缀祖先完整时，目标可精确分解为局部 logistic 损失，提高训练效率。标签部分缺失时，仍使用边缘似然，不把缺失补成零。

本轮预设 .001 和 .03 两个正则配置，零初始化，分别 20 和 14 次优化迭代收敛。没有根据验证分数挑选或更新默认模型。

独立 sklearn Logistic 对相同局部监督进行了等价拟合：训练损失差最多约 2.7e-15，局部 logit 差最多约 4.2e-7。**局部概率拟合本身是标准方法，不构成新的算法创新**。可能的贡献仍须来自有依据的结构构建、可核查中间语义、系统关系组合，以及后续实验收益。

## 三、这次具体升级了什么

旧实现枚举全部未知事件，默认上限 16，硬上限 18。本数据较早阶段有 18–26 个未知事件，完整接入时会触发容量限制。

本轮新增带解析梯度的精确变量消元：先纳入已知证据，剪除无关后代，再按 min-fill 顺序消去中间变量。保留联合查询时不丢依赖；只查询已知授权下的至少一项风险时，可直接计算“所有风险事件都没有发生”的标量概率，避免展开所有输出组合。

变量消元和 min-fill 是标准推断方法，参见 [pgmpy 官方文档](https://pgmpy.org/api/generated/inference/pgmpy.inference.VariableElimination.html)。本轮实现自己的概率/梯度接口，不把标准算法称作原创贡献。

模型接受最多 128 个事件定义，但**不等于任意 128 节点图都能计算**。实际容量还受中间因子宽度和保留查询维度约束，默认 16、硬上限 18。稠密图超限仍会明确拒绝，没有暗中改为独立近似。

## 四、验证结果

训练：8 个任务模板，2,133 条流程，631 个最终泄漏正例。

验证：4 个不重叠任务模板，1,026 条流程，326 个正例。它是已使用过的开发划分，不能作为新的最终测试证据。逐值事件与前缀也不是独立的流程样本。

AUROC 衡量危险流程是否排在正常流程之前，越大越好；Brier 衡量概率误差，越小越好；F1 使用统一 .5 阈值，不代表已经公平优化各方法的报警阈值。

| 方法 | 早期 AUROC ↑ | 早期 Brier ↓ | 晚期 AUROC ↑ | 晚期 Brier ↓ | 晚期 F1@.5 ↑ |
| --- | ---: | ---: | ---: | ---: | ---: |
| 事件 BN，正则 .001 | .60717 | .22404 | .71456 | .20459 | .41311 |
| 事件 BN，正则 .03 | .60009 | .24392 | .71449 | .22623 | .54960 |
| 最终标签 Logistic | .60614 | .21624 | .72690 | .20998 | .23611 |
| 最终标签 HistGB | .63368 | .22185 | .75006 | .17953 | .46103 |
| 训练正例比例常数 | .50000 | .21726 | .50000 | .21726 | .00000 |
| 当前出现则预测最终出现 | .58753 | .48343 | .70683 | .39669 | .61349 |

不能只挑 BN 的某个 F1 说领先：简单持久性规则的 F1 更高，但概率误差很大；提高正则后的 BN 的 F1 更高，但概率预测更差。

两个分类器只用当前已见信息的计数/共同出现计数，不输入模型身份或领域标签；BN 额外使用了逐值及中间事件监督，而分类器只用最终风险标签，**训练信息并不完全相同**。同局部监督 Logistic 是另列的等价检查，不能混作最终标签分类器。

这些分类器利用完整 MAS 前缀，但不是 QuadSentinel 等原生 MAS 方法的全面复现。本轮没有新增原生守卫模型对照，不与此前 8 例采购开发实验的成绩混表。

## 五、下一步依据及不能夸大的地方

已确认的局限：任务图固定、所有信息项共享很少的条件概率、不同信息项在本图中没有共同随机节点、文本线索未启用。系统判断最终会受到这些局部建模限制，精确推断本身不会自动提高预测质量。

下一步应在开发数据上检验：同一条回复中的多个信息项是否存在当前结构未解释的共同保留/过滤模式，以及任务要求是否提供额外可观测解释。只有数据支持，才引入有独立观测定义的消息级节点或更细模板，再以相同输入、监督和分组划分做消融。

这只是后续待验证方向，**本轮没有证明误差来自某一个机制，也没有实现消息级新结构**。不能通过不断扩大知识库就预先保证准确率单调上升。
