# 动作历史精确压缩：推导与长序列验证

## 1. 改变了什么

新增 `CompactCapabilityBN`、`CompactCapabilityStream`。这是同一150参数能力条件BN的另一种精确计算方式，不是替换风险目标、重置任务、丢弃旧动作或把不同Agent近似为独立。

原v4每个动作保留授权变量A，派发时再保留信息快照D。即使只有几个Agent，动作增多也会导致指数状态爆炸。上一轮23次真实工具入口只处理了前5次，第6次超过12变量上限。

本轮利用**当前输出层只读取特定历史汇总量**这一结构，对A/D变量求和消去。压缩版现在完成这23次工具入口的连续回放，并完成另一个含1000次工具派发的人工序列。没有新增训练、API调用或性能结论。

## 2. 等价成立的条件

以下是现有v4本身的建模假设，不是对现实系统独立性的断言：

1. 每个动作的A只依赖可见能力、角色、最新有效检查类别；给定这些观测，其Bernoulli因子不依赖隐藏的信息状态C或其他动作A。
2. 信息来源/节点状态只受输入和实际消息的更新影响，不读取授权状态。
3. 待执行检查可以替换本动作A的条件因子；派发后不再修正这个历史因子。
4. 每个派发快照D只是派发时C的副本。
5. 系统读出仅使用四个动作汇总：待执行是否存在A、已派发是否存在A、待执行是否存在A且C、已派发是否存在A且D。

因此，**只压缩本模型不再需要区分的历史状态**。若将来加入跨动作授权相关性、累计额度、历史检查修订、动作数相关潜在量或不同的系统读出，必须重新推导；不能直接沿用本压缩器。

## 3. 已派发历史保留三个状态

定义：

```
H_A = OR(所有已派发动作的 A)
H_O = OR(所有已派发动作的 A AND D)
```

H_O=1必然意味着H_A=1，所以只有三个可达组合：

- 0：(0,0)，没有授权风险假设激活；
- 1：(1,0)，存在授权风险，但没有信息影响重叠；
- 2：(1,1)，存在派发时的信息/授权重叠。

**维护的是P(全部来源Z、全部信息状态C、H)，不是P(Z,C)乘P(H)。** 同源材料分叉/汇合、过去执行与当前信息状态之间的相关性仍保留。

新动作以q为授权状态激活概率，派发者当前信息位为c。逐个联合状态进行：

- c=0：以q将H=0移到H=1，其余保持；
- c=1：以q将H=0或1移到H=2，其余保持；
- H=2保持为2。

这正是先采样A、复制D=c、更新两个OR汇总，再消去A和D的结果。普通信息转移在每个历史状态上照常进行。后来的信息影响不会把过去的D重新改写为1。

## 4. 待执行动作直接求和

给定某个信息联合状态s，动作a的授权概率为q_a、所属节点信息位为c_a。定义：

```
r_on  = product(1-q_a for pending a with c_a=1)
r_off = product(1-q_a for pending a with c_a=0)
```

待执行汇总的三个状态概率为：

```
P(0,0 | s) = r_on * r_off
P(1,0 | s) = r_on * (1-r_off)
P(1,1 | s) = 1-r_on
```

这里按每个信息联合状态计算，不把不同节点C的边缘概率直接代入乘法。多个待执行动作共用一个参数时保留其出现次数，不当作重复日志去掉。

随后对信息状态s、已派发历史h、待执行汇总u加权：

```
p_t = sum P_t(s,h) * P_t(u|s) * sigmoid(原v4系统读出(s,h,u,可见统计))
```

这与完整v4对所有A/D组合求和得到的p_t相同。参数、条件表、系统系数、预测目标、整任务等权前缀损失及正则项都不变。

乘积采用log域与expm1计算，避免大量动作或q接近0/1时的除零与相消。新实现同时计算解析前向导数，所以保留端到端训练，而非只做推断优化。

## 5. 保存规模与解释边界

设I为来源与信息二值变量数量，M为累计动作数量，K为已派发数量：

- 完整版概率状态大小为2^(I+M+K)，含取消后仍保留的动作变量。
- 压缩版持续维护3×2^I个概率质量，输出时临时组合成9×2^I个权重。
- 若同时求150参数的导数，导数状态再乘150；不会乘2^M。

这解决的是**动作历史的指数增长**，不是任意大MAS推断。来源和节点数量仍造成指数增长，默认限制12个信息/来源二值变量。

动作身份、参数绑定、检查记录、每个动作的授权边缘概率、派发信息边缘概率仍保留，便于追溯。它们是线性增长的元数据，不是常量内存。现有编译器还会复制历史动作元数据，因此长序列的总运行时间及批量前缀存储仍可能呈二次增长；本轮不宣称整体线性时间或从零训练更快。

系统解释改为九个“历史汇总×待执行汇总”的精确概率贡献，贡献之和等于分数。不再提供任意旧动作之间的完整联合查询，也不把压缩状态冒充原来的逐动作完整联合状态。要查询这些关系需要额外保留相应变量。
