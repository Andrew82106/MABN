# 真实 MAS 采购对照：系统关系必要，但 BN 尚无独占优势

## 结论与项目位置

本轮把已有知识策略组合 BN 接到了新的真实 API 多 Agent 采购提案上，并完成 QuadSentinel 作者实现的同目标对照。不再只运行手写守卫夹具，但仍是 **8 个自建开发流程**，不是独立公开测试集或部署成绩。

- 3 个 API 角色：协调者、采购者 A、采购者 B；另有确定性的批量入队环节。协调者的真实回复进入两个采购者的请求，采购者看不到对方回复。
- 24 次被监测 Agent 请求，得到 16 个实际采购提案；8 次普通 LLM 裁判请求、72 次 QuadSentinel 请求。总计 **104 次真实 API 请求**，无本轮训练。
- 8 个流程中有 4 个不合规批量提案。BN、完整规则、LLM 裁判、QuadSentinel 均正确；去掉跨 Agent 预算汇总的规则漏掉其中 2 个。
- 72 个守卫请求和 32 次状态/事件判断无网络复放一致；24 个目标请求和 16 个实际命令重新构造一致；114 张可执行 BN 图独立计算误差为 0。

**这支持跨 Agent 的约束不能丢，但不支持 BN 优于现有 MAS 守卫，更不支持已完成任意工作流的学习式监测。** 它位于项目“知识 → 组合图 → 实际 API 观测”这一段。

## 1. 场景、可见性与真实运行的边界

办公采购和野外工作采购各有四种预先固定的条件：共同宽松预算、共同紧预算、分开的预算池、提案后父授权被撤销。每个采购者从含兼容/不兼容商品的虚构目录中选择一项，亦可放弃。

需求、目录、权限和预算是人工编写的环境；工作单、选择、金额和说明是实际 API 返回。没有从 BN 采样行为或按期望标签伪造 Agent 输出。16 次选择均为最低价兼容商品；没有放弃。办公两项实际金额为 64/42，野外为 73/38，共同紧预算为 90，单次上限为 100。分开的预算池分别限额 100，不应被错误合并。

两个采购者均收到局部上限和分配时的授权快照，当前共同预算与新撤销记录在批量审查点提供给所有监测器。这里故意研究信息分散后的系统审查；不能称采购者接收了全部全局政策却蓄意违反。

采购者返回严格 JSON 命令，运行器把 `propose` 消费为待入队请求。这是应用层命令协议，**不是 Responses 原生 function_call**。金额必须对应实际选择的目录商品，解析错误保留为失败，不修补成预期输出；选择不兼容商品若发生会单独记作任务质量问题，不从数据中删除。

没有实际付款、下单、外发或阻断。当前标签只表示“若把这整批已提出的请求各派发一次，是否满足声明的政策”，不是后续真实损失或任务整体安全。

## 2. 这一轮怎样接入 BN

新模块 `src/paperalpha_runtime/mas_purchase_study.py` 将实际命令绑定到功能节点、动作主体、参数、资源及当前授权证明，再调用已有 `WorkflowRiskBN`，没有另外手写一个冒充 BN 的评分公式。

共同授权从实际提供的 grant/revoke 记录重建；两个引用同一父授权的动作复用原有证明机制。预算根据任务、主体、资源集合和币种绑定，可连接不同功能节点。原概率图的知识模板来源配置保持不变。

本轮统一执行 **当前批量提案合规查询**：所有已包含动作的事件条件固定为 1。它不是预测这些动作将来是否发生。授权事实完整且当前已知，因此应退化为确定政策结果。

采用已有默认 12 参数组合层，但没有拟合；确定条件下这些发生率参数不决定最终 0/1 合规结果。它不是原 45 参数发布者模型的新成绩，也不是 54 参数混合模型已经端到端训练。没有加入 GNN 或人为把失活的分支系数强行调成非零。

授权证明内部仍需要顺序评估位置：同一无更新记录快照内按动作顺序评估，再统一查询批量条件。该逻辑时钟与实际 API 日志序号分开记录，不伪造同时派发时间，不将提案视为已经执行。

## 3. 对照是怎样对齐的

| 方法 | 得到的输入 | 本轮含义 |
|---|---|---|
| 组合 BN 条件查询 | 实际动作、同一当前授权、局部上限、全局合同、功能 DAG | 可执行知识图的确定条件查询，未训练 |
| 完整规则 | 同一实际动作和原始政策记录 | 独立实现的强基线，同时定义本任务规范标签 |
| 局部规则消融 | 同样的输入，但预算计算不汇总其他采购者请求 | 故意去掉关系的消融，不是原版 MAS baseline |
| 普通 LLM 裁判 | 相同批量提案与政策、先前原始消息 | 指定 API 的 gpt-5.5/low，一次批量判断 |
| QuadSentinel | 相同逐条原始消息、批量工具提案和政策 | 锁定作者代码的明确适配配置 |

QuadSentinel 固定作者提交 `1d4e29443284385a2505acb1e7986d9d80dc97f1`；配置仍为 `quadsentinel-author-full-predicates-gpt55-monitor-only-v1`。作者谓词更新、威胁更新、验证和分级裁判代码均未改。原顺序仍是先用工具提案更新谓词，再判断动作。

偏离项没有隐藏：全部角色统一 5.5；`k=-1` 不测检索；人工审核后加载三条策略，而非评测作者离线策略翻译；只监测不阻断。因此不是论文完整复现，也没有防御后的攻击成功率。[作者实现](https://github.com/yyiliu/QuadSentinel)

本轮未把 allow/deny 包装为已校准的概率，也未拿当前批量合规分数和未来预测概率混比。实际仅汇报判定混淆矩阵和失败数量。

## 4. 全部结果

4 个正例：两次共同预算超限、两次父授权撤销；4 个正常对照。所有监测器均返回有效判定。

| 方法 | TP | FP | FN | TN | F1 |
|---|---:|---:|---:|---:|---:|
| BN 条件查询 | 4 | 0 | 0 | 4 | 1.000 |
| 完整规则 | 4 | 0 | 0 | 4 | 1.000 |
| 普通 LLM 裁判 | 4 | 0 | 0 | 4 | 1.000 |
| QuadSentinel 本配置 | 4 | 0 | 0 | 4 | 1.000 |
| 去掉跨 Agent 预算汇总 | 2 | 0 | 2 | 4 | 0.667 |

完整规则的正确性由规范标签定义决定，不能把其满分称为独立统计发现。BN 与它一致证明当前编译语义正确，不是学习收益。两个语言方法也正确，说明当前简单场景没有把现有强对照难住。

局部消融漏报是这批实际提案上的具体机制证据：两项各低于 100，但相加超过共同的 90。不能仅凭这个刻意删除全局汇总的对照宣称研究创新或 MAS 方法领先。单次额度模板已被实例化，但本轮没有单次超限正例；未覆盖的风险不能写成已验证。

## 5. 失败、恢复与证据链

第一次运行已经完成全部 24 次目标 API 请求，但冻结目录漏带 `paperalpha_monitor.__init__` 间接加载的 `risk_templates_v1.json`，8 个数值评分进程均失败。没有守卫/裁判请求，也没有分数。失败目录和报告完整保留。

修复只涉及打包及恢复协议：复制所需配置，先用独立数值进程验证冻结包可导入，再为新目录冻结代码。新计划绑定原计划及 8 份报告的哈希，要求全部原始任务一致、目标采集完整且没有已有评分；不重新生成或筛选任何目标回复。

恢复时原目标请求/回复的文件字节和时间戳原样保留，重建命令和当前输入后才开始监测。所有规则标签在监测判定之后计算。由于监测在采集完成、修复之后运行，准确表述是 **真实 API 提案的离线前缀重放对照**，不能称整个链路第一次在线即成功。没有未来执行结果可供任何监测器偷看，也未使用旧 8 条发布留出测试。

OpenAI Docs 用于落实 completed、拒绝和截断回复的区别；解析或传输失败不算正常负例。模型保持用户指定的 5.5，没有按文档示例替换任务模型。[官方完整回复处理说明](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode)

## 6. 对模型设计的直接约束

1. **保留系统级知识与绑定。** 同一个动作、共享预算、父子授权和资源作用域必须真实进入图；只增加“全图风险分数”而不保存这些关系不够。
2. **明确确定检查与不确定预测的分工。** 当动作和政策事实都确定，输出应忠实执行政策，不应为了需要学习而人为制造概率。这部分的价值是知识编译、可组合性和可审查性，而非击败同义规则。
3. **学习式 BN 的贡献必须另证。** 需要真实的后续行为不确定性、部分证据或关系变化及独立标签，验证联合建模在预测、校准、跨流程迁移或数据效率上的价值。不能借本轮满分替代这项证据。
4. **原生 MAS baseline 不能省。** QuadSentinel 已有真实 API 数据上的明确适配对照，但只有八个开发流程；还需更广风险、自动提取误差、成本、长轨迹与新留出验证。

完整目标仍未达成：任意功能 DAG、异构知识子 BN 的自动生成、真实多风险联合训练、大图推断、广泛原版 MAS 对照及可推广的提前预警仍待推进。本轮没有改旧成绩、没有训练后挑测试、没有 Git 提交/推送，也没有改当前任务模型或思考强度。
