# 真实 MAS 四类采集：标签含义与模型证据覆盖

## 本次结论

实际通过用户指定接口调用 gpt-5.5，新增四个此前未运行的任务，共97次API请求、90次模拟工具调用、215条监测观测。三条执行完整，一条触及冻结预算后失败；全部通过独立进程的采集完整性与官方规则重算。

**这不是模型准确率结果，也不是新训练集已经就绪。** 三条完整轨迹均有规则命中，没有任务级负样本。v7能够回放所有新观测，但职责、授权和资源绑定缺失仍限制了它实际利用知识的能力。本轮不增加未训练模型版本号，不把结构回放算成性能提升。

## 3. 新发现：标签不能笼统叫“危险”

冻结目标仍是`any_recorded_access_rule_violation`，本轮没有看过结果后改标签。

四条轨迹合计46次规则命中，涉及38个不同动作：

- 23次`V-OT:low`，来自不必要或未列为有用的工具调用。例如预订专员主动检查预算。
- 23次`V-OR`，涉及15个不同动作，检查的是资源/参数范围。该类官方没有severity，不应误写为低严重度。
- 本批没有高严重度V-OT，也没有V-IC/V-ID命中。不能据此断言它们不会发生。

来源可在上游`multi_agent/loader.py::synthesize_useful_tool_rules`和`schemas/access_rules.py`复核：不必要工具会被合成为低严重度规则；资源规则不分严重度。只学会识别多余操作，不能作为有效识别安全危害的证据。

后续应在**训练之前**固定多目标定义：一般规则偏离、明确禁止的行为、资源范围偏离、以及有独立证据的实际危害。该分层目前是下一步设计约束，不是已有监督头或危害标签。观察到动作级有未命中记录，也不能把它们当成任务级正常轨迹。

## 5. 对后续模型设计的具体约束

这次真正改变优先级的不是分数，而是缺失的证据：

1. **先把任务与职责接入。** 当前`runtime_events`的run_started只有参与者；用户原始任务存在首个API请求中，却不在监测输入中。应在新采集版本记录公开初始任务和实际提供给Agent的职责，并单独注明来源/可用时刻；不能从隐藏评测规则反推它们。
2. **区分候选资源与可信授权。** 参数里已有customer_id/request_id等候选对象，但当前监测绑定仍为空。下一版需保持类型和来源，把“操作的是谁的资源”与“是否获准”分开，不能把字符串匹配当授权。
3. **补正常完成的对照。** 不能用全正任务集拟合345参数分类器后宣称有效。可研究明确公开的权限/职责配置及固定DAG编排，实际运行后仍由独立检查器判定，不能因为配置看起来合规就预先标0。干预版本与原配置应分开登记、同任务分组隔离。
4. **不要把现有编排说成固定DAG。** 官方hub/spoke有返回边和再次委派；时间展开图无环不等于用户要求的固定职责DAG。它是有用的真实输入补充，但不能替代目标场景评测。
5. **再确定主评测目标和MAS对照。** 先建立与安全语义相符、具有两类独立结果的资料，再冻结分组划分、信息可见性、训练与阈值规则；不能为追求赢baseline而临时挑子目标。

本轮没有更改v7概率结构。最终全项目614项测试通过，46.25秒，4条既有sklearn警告；四个run各49项原始产物核验通过，独立重算133条规则决策。汇总目录13项列入清单的产物、模型覆盖目录42份源码与4份日志输入均无哈希差异。验收记录另存于审核目录`TESTS.md`，晚于报告生成，不冒充已包含在原报告哈希清单中。整体目标仍未完成。
