# 任务语义接入消息 BN：字段用途与整消息预测

日期：2026-09-20。本轮向“初始任务知识 → 局部事件与消息联合模型 → 系统风险查询”推进，不改变项目的 API MAS 监测主线。

## 1. 要解决的实际缺口

上一轮独立校准下，消息 BN 发现32/326个最终披露正例、误报35/700个负例。现有输入主要是具体信息项的出现状态和数量，没有区分“用于内部处理”与“需要写进最终答复”。

例如，生成贷款评估可能需要收入作输入，但最终答复不一定需要给出原始收入数值。这个差别可能帮助预测信息出现，却不能赋予披露权限。

同时发现一个结构问题：旧消息模型的整消息节点只使用四个计数特征。只给逐字段事件加入语义，并不能直接改变晚期“至少一项出现”的消息节点。因此需要将语义同时接到局部字段与整消息，而不是只增加接口字段。

## 2. 实际调用与特征来源

指定本地 API 上的 gpt-5.5/low 共12次分类，全部返回结构有效、任务引用可定位的结果。共162个字段判断：内部用途50个needed、61个not_needed、51个unclear；对外形式19个verbatim、33个derived_or_aggregate、87个not_requested、23个unclear。

发送给分类器的只有初始任务和**完整字段名/JSON类型清单**。不发送具体数据值、允许/禁止字段列表、风险标签、领域/生成模型标识、任务模板ID或后续Agent回复。研究中的API模型/思考强度与当前任务设置互不修改。

3,159条已有开发流程经有边界的文本规范化对应12个缓存输入。规范化器使用16种显式请求文字形状，将其中的姓名、编号或部门主体替换为占位符；每条保留原请求哈希及替换区间。**这是人工编写的固定基准适配，不是自动理解任意任务、自动DAG识别或完全无人工模板。** 它丢失主体身份与记录匹配信息；这批初始数据中请求姓名与vault姓名也不应被假定一致。未知请求形状保留原文，采集器不超过64种输入，不选择性丢弃超额输入。

缓存按发送内容哈希，而非隐藏模板ID。分类失败预设为全部unclear，保留涉及流程；本次没有失败。提取token用量：输入10,484，输出9,127。没有新被监测Agent行为生成，也没有读取旧测试集。

引用定位只证明分类器引用了任务文字，不证明其分类正确。人工阅读发现：case_id与case_number的用途判断存在主观区别；“摘要是否应包含具体值”往往仅凭短任务无法确定；referral中的电话是否必要也依赖未提供的应用语境。本轮保留全部原判断，不根据风险结果改标签，不把这些判断当语义真值。

使用[OpenAI结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)落实JSON schema、完整状态与拒绝检测。仍验证字段覆盖和引用，结构合规不等于语义可信。

## 3. 如何接入同一张概率图

对每个被追踪字面值，将其对应字段的分类映射到两种阶段线索：

- Worker内部用途：needed→支持，not_needed→反对，unclear→未知。
- 最终发布形式：verbatim→支持，derived_or_aggregate/not_requested→反对，unclear→未知。

这里的“反对”是**任务用途分类得出的预测线索**，不是原任务明确禁止，更不是授权撤销。同一字面值有多个字段别名时，若线索不一致就使用未知，不把别名变成多票或多个事件。资料库、协调消息、Worker实际回复以及现有授权证据均原样保留。

逐字段概率沿用原来的25参数。消息门控从每类4个特征扩为6个：基础项、log(1+信息项数)、父事件出现比例、上游是否出现任一项，以及本消息字段的支持比例、反对比例。五类功能共30个消息系数，与25个字段系数合计55个事件参数；另有3个既有授权参数。本次授权已知，3个授权参数不拟合。名义参数位不代表各类工作环节都有充分数据。

消息联合分布仍是原来的可观测OR门控：全零概率1-q，非零字段向量使用q乘以排除全零后的Bernoulli乘积。联合分布、精确推断与授权查询仍一致，不额外加一个任意的加权风险分数。新结构不构成新概率分布，晚期OR门控仍是一种逻辑回归。可能的优势必须与同信息对照实测，而不能归因于“用了BN”。

这些是**离线计算的初始可用信息特征**。图中source sequence=1指原任务/配置的可用时刻；实际分类完成时间另有记录，不伪造当年已经在线调用分类器。当前没有新增在线挂钩或端到端大模型微调。

## 4. 固定对照与评价方案

沿用上一轮完全相同的1618拟合/515校准/1026开发验证划分和三个报警规则：固定.5、整流程最大分数校准10%预算、早晚各5%预算。所有材料都曾在开发中接触，不能称新的独立测试。

BN三组各用预设正则.001和.03：

1. counts：55参数事件结构，但所有语义线索为0，是旧计数模型的等价扩展。
2. local：原45参数消息结构，语义只进入字段节点。
3. task：55参数事件结构，语义同时进入字段和消息节点。

普通Logistic与HistGB分别在计数和语义两种输入上重训。计数版8个特征；语义版加72格的联合直方图，保留每个字段在vault/协调者/Worker中的出现，以及内部/发布线索类别的共同分布，合计80维。早期Worker尚未出现，使用独立阶段模型的占位，不读取未来实际值。字段名、主体名、模板ID、领域和生成模型名不进入拟合特征。

BN仍使用后续Worker和最终消息的逐项联合监督；任务级分类器只使用最终标签。这个监督差别继续披露，不宣称所有方法监督预算完全相同。语义API在本轮拟合中被冻结，只有概率参数联合优化。

所有模型、阈值和结果保留，不根据验证成绩换默认模型。输出需同时报告概率误差、排序、误报、全流程召回、早期首次召回和模板差异。

### 数值诊断与后续源码修正

发现完整消息OR查询通过历史联合归一化计算时，数学上相同的门控输入可能有约1e-15的分数差，足以人为打破AUROC并列。以.001为例，counts/local/task的晚期存储AUROC分别为.73265/.73527/.73395；直接按同一模型的消息门控公式计算后，三者均为.73467。因此这些微小排序差异不能当作结构收益。

晚期诊断还发现local .001的分阶段阈值在一个数学等分组内部被浮点差异切开。该检查只覆盖晚期，不把“其他晚期规则未发现此问题”外推为整个协议都无数值问题。源报告保持原样，诊断另存`results/task_cue_message_score_resolution_20260920/REPORT.json`，不是重新选取更好指标。

当前源码已增加严格范围内的等式计算：**已知授权、目标恰为一条完整消息、全部父输入已观测**时，最终OR概率直接取消息节点q，局部字段参数对该概率的梯度精确为0；其余情况仍用原联合推断。沿用父类的证据/策略检查，不将子集风险或未知父事件偷换成整消息q。这个修正只消除数值上的假差异，不使预测模型变强。

上述实验及独立复验使用修正之前的冻结源码，未据修正重写分数或重新校准。本轮结构/数值修正后的36项专项测试通过，随后全套1,446项通过（10条既有警告，198.64秒，进程91064退出码0）。后续重新评测需使用新冻结版本，不能将旧冻结结果直接贴到新数值入口上。

## 6. 代码与证据入口

### 结构诊断：不能把“加了语义”当成已经理解动态信息流

在查看本轮性能结果之前，另补一个可执行反例：同一任务要求输出地址、不输出SSN；两份Worker回复分别只含地址或只含SSN，其他输入相同。v1消息节点的字段总数、已出现项数以及全体字段的语义比例均相同，因此**最终至少一项出现的风险概率完全相同**，即使逐字段概率可以不同。权限保持同一外部配置，不把任务文字改成授权。

`tests/test_task_cue_relational_gap.py`固定了这个限制见证。普通分类器的80维联合直方图能区分这两种输入；不能靠删掉对照的信息掩盖BN的缺口。下一次结构升级应让消息节点显式接收“到达的字段与它们用途的对应关系”，例如按用途区分的上游出现比例，而非只有任务整体语义比例。该方向来自结构反例，不是根据验证集挑选超参数。本轮冻结概率结构和实验保持不变。
