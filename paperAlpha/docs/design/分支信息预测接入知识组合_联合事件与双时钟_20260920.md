# 分支信息预测接入知识组合：联合事件与双时钟

## 本轮结论

已有45参数分支信息出现模型，已实际接入上一轮知识策略组合器，形成`BranchWorkflowRiskBN-v1`。不是只传递两个边际风险分数，而是保留整个“哪些信息一起出现”的分布，再与一次共享授权图及组合政策计算。

默认54个参数位：原分支模型45个（包括3个授权先验）＋可选工具派发预测9个。**没有再复制一套授权先验**。只有文本发布的输入不会启用工具预测参数；参数位数量不表示全部被数据识别。

20个构造输入、296张图查询（含16条真实开发前缀回放）通过独立复算；图概率最大差9.99e-16，条件似然差4.44e-16，全参数梯度差9.40e-11。真实前缀的新旧预测最大差1.11e-16。

本轮**没有新增API调用、没有重新训练真实开发数据、没有读取已使用的8条留出测试、没有新准确率结论**。实际是将已实现模块连起来，并验证连接忠实；不是完成任意DAG、多风险泛化或原版MAS baseline比较。

## 1. 两个连接错误必须避免

### 不能只接单项概率

两项信息各有一半概率出现在最终报告，不足以确定它们一起出现的概率。两项可能受到同一个发布者状态影响，不能默认二者独立。

原分支BN保留两个执行者状态和发布者状态。新接口`joint_appearance_law`输出所有信息出现组合的概率，不把它们展平成相互独立的分类结果。构造参数下，“两项一起出现”比边际相乘高约.0311–.0358；新增“二者不得同时发布”的政策直接使用这个联合概率。

这只是结构表达与计算检查。**实际冻结模型的最终状态系数仍是0**：16条真实开发前缀的联合概率与边际相乘相差最多1.11e-16，依然没有相关结构收益。连接方式正确，不能把不生效的结构变成已证实的创新。

### 文字出现不是工具派发

接口明确区分两类事件：

- `literal_appearance`：固定下一条发布答复中出现指定字面信息；这些是监测器定义的潜在发布查询，不是Agent已经调用了`release_literal`工具。
- `tool_dispatch`：确实已提出且参数绑定的工具动作，在固定窗口内最多派发一次；不等于成功返回或实际资金结算。

金额出现在文本中，仍然只是字面出现。预算模板只接真实工具类型的付款候选，不能把文字“60元”算成支付了60元。测试用同一图中的数字信息与独立付款候选检查了这个边界。

## 2. 接口怎样保留原模型

记已观察到的执行者回复为W，未来各项信息是否出现为向量F。直接复用原实现的联合似然：

`P(F | W) = P(W,F) / Σ_f P(W,f)`

每一种F组合都调用原模型的联合似然，求和时已经积分掉执行者/发布者潜在状态。原模型已有的分支矩阵、信息归属、上下文与发布者可见授权线索全部保留。

其解析梯度是：

`∇log P(F|W) = ∇log P(W,F) − ∇log P(W)`

不能因为W已观察到，就把随参数变化的分母删掉。新接口同时返回条件分布、梯度及W的证据概率，分别由已有独立标量图解释器复核。

授权真值不作为出现标签传入这个接口，因此对授权随机事实求和后不会影响行为预测。组合器只在当前策略侧使用一次这些事实。它没有假设Agent知道监测器所见的撤销记录。

## 3. 同一图可以接哪些东西

组合器逐个事件对齐精确动作ID和参数绑定，继续使用知识配置中的授权、单次额度、累计额度、禁止组合算子。文字事件与工具事件共享策略图，但保持不同含义。

当输入只有原两项发布信息、没有新增组合政策时，新模型还原旧模型“至少一项引用违规”的概率。加入预先声明的共同发布禁止政策后，查询可以覆盖“每项单独有授权，但两项一起出现违反组合政策”。该政策是明确输入，不是从结果倒推或声称我们自动发现了组合危害。

可选的其他工具动作采用原组合器的可学习派发模型。其与发布信息、不同工具动作之间当前仍假设条件独立；**并未解决任意消息、动作、资源之间的联合依赖**。

构造的混合输入包含发布信息＋独立付款候选：付款额度风险只由付款事件控制，文字组合风险由两个相关的F控制。两种风险再按同一联合分布求OR，不是风险分数相加。

真正的API回放只含原有发布事件，没有给旧记录补造付款候选或新政策。混合输入明确位于`branch_workflow_fixtures.py`，是机制夹具，不是实验数据集。

## 4. 证据绑定和时间

原始分支输入有两套时间：

- 授权逻辑时钟：原记录中发布查询截止通常为12，静态授权窗口至30。
- 实际采集日志序号：例如发布前输入捕获于20。

新的引用同时保留原始观察摘要、输入可用日志序号及预测日志序号，不把20伪装成授权时钟12，也不因两个数字不同就误判未来信息泄漏。

策略侧必须复用原分支的授权证明和共同事实身份；附加工具动作的证明仍需来自同一当前记录前缀及相同作用域。已知到期若落在预测窗口内会被拒绝，未建模的后续撤销/批准仍不在支持范围。

顺带补齐原分支输入对执行者列表和派生“序列化合并是否一致”标志的重建比较，避免修改这些派生字段后仍通过校验。未改冻结历史输入或成绩。

## 5. 训练、图和解释

组合后的目标是**给定已观察W后的未来事件/事实/策略标签的条件似然**。它与原始分支模型联合拟合W/F的目标不同，不能把不同训练目标的改善归因于新增结构。

原分支参数、工具预测参数和唯一一套授权先验可以通过解析梯度联合优化。构造频数检查中，优化13步，联合分布恢复最大差3.14e-8；这是已知模型产生的频数检查，不是现实泛化实验，也不证明隐藏参数唯一可识别。

导出的图保留原执行者状态、发布者状态、已观察消息节点及F节点。策略图直接连接这些F节点；没有导出一张“看起来有相关性、实际却按独立边际计算”的示意图。共同授权根也只出现一次。

对于只含原发布数据的输入，新增加的9个工具派发参数没有监督，不报告它们已学好。被引用的旧模型有训练记录，也不能据此把新组合模型标为已经端到端训练；新模型单独保存优化元数据。

本轮复用OOBN式片段组合与上一轮已有风险知识，并未提出新的概率分解定理。[上一轮来源与组合范围](工作流风险子图组合_共享动作与策略_20260920.md)继续适用。

## 7. 仍需推进的完整目标

当前真正接通的是“固定分支的信息出现模型 → 类型化联合事件 → 知识策略组合”。不是任意工作流自动建图，也不等于知识库中所有风险都已覆盖。

下一步应在新开发队列中，先验证真实运行是否提供需要建模的关系变化和可用监督，再决定增加哪些子结构。尤其要区分：文本共同出现、真实跨Agent依赖、确定规则可判的约束、不可观测导致的信息不足。不能只设计恰好符合我们BN的数据来证明优势。

原版MAS监测方法的同协议复现、独立新数据上的效果比较、更多角色/工作流、自动提取和大图推断仍是明确未完成项。本轮没有改任务模型/思考强度，也没有Git提交或推送。
