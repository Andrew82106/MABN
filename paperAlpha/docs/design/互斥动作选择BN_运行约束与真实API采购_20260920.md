# 互斥动作选择BN：运行约束与真实API采购

本轮把应用自身的“每个采购槽位最多派发一个候选命令”编译进局部概率结构，再接入既有共享授权、单次额度和系统累计预算图。它是项目知识组合方法的一项结构升级，不是完整MAS框架完成，也不是已经证明性能领先。

## 1. 实际补上了什么

旧采购实验每名Agent只有一个已经提出的请求，条件化后做确定政策判断，没有互斥商品候选，所以旧成绩不受影响。但若直接把一名采购者的多个候选商品放进独立二值发生模型，会产生同一槽位同时执行多个选项的概率；这与应用协议冲突。

新 `ExclusiveDispatchInput` 要求每个候选动作恰好属于一个明确的选择槽位。同一槽位须属于同一功能节点和主体，并携带在预测时已可见的运行约束来源。默认允许放弃；不能用Agent口头承诺代替应用约束。

`ExclusiveDispatchWorkflowRiskBN` 用标准条件softmax计算“不执行、选基础款、选增强款”等互斥结果，再映射为原策略图使用的动作位。非法组合概率严格为0，不是训练一个惩罚项希望它足够小。授权、单笔限额和全局预算仍复用同一份动作/授权事实。

概率图导出使用等价的顺序二值条件表，保留可执行解释；给定某选项发生是条件推断，不是因果干预。互斥条件冲突或零概率标签明确报错，不归一化成另一种事件，也不生成NaN。

旧独立模型现在会拒绝带显式选择组的输入，防止悄悄忽略约束。每个选择组只有一个候选时，新模型退化为旧Bernoulli模型。旧无选择组输入和历史冻结结果保持原状。

注意边界：不同选择槽位仍在当前可见线索下条件独立。共同父授权仍保留联合依赖，但未来共享规划状态还未进入这个新片段。不能把组内互斥说成已经完成跨Agent未来共同原因建模。

## 2. 真实API数据与执行语义

事先冻结24个自建流程：studio/garden训练，classroom/fieldcamp验证；每域三个任务简报、两个全局预算。每个流程一名规划者和两名采购者，最多三次指定接口gpt-5.5/low请求。采购者看实际规划回复和自己的目录，不看彼此回复及财务检查点的全局额度。

目录全部虚构：A的两种商品价格35/65，B为45/75，单次限额90，共同额度110/170。低额度下只有两人均选增强款等组合才超限；每个单次正常候选都不超限。任务质量、真实采购和恶意意图均不是标签。

流程清楚分开：API回复 → 单个命令解析 → 本地模拟工具派发 → 政策结果标注。`SimulatedDispatchSlots.execute` 实际限制每个买方槽位一次调用，允许放弃并拒绝重复；它不根据BN分数阻断。

这里的工具派发是程序执行的本地模拟操作，不是Responses原生function_call，更没有真实下单、付款或联系供应商。文本提案自身不冒充执行记录。API原始请求/可见回复、解析结果、模拟派发和前缀各自保存。

前缀在两名买方请求之前记录。输入中的cutoff/horizon是静态授权模型时钟位置，与API日志序号/计时值分开；实际可见性由原始日志先后核验，不声称这些时钟可以互换。还保留了规划者之前的INITIAL材料，但本轮没有用它声称更早预测。

## 3. 外部失败和检查器修正

采集进程真实完成并退出0：实际55次生成请求，15个完整流程、9个因InternalServerError中断的流程。全部12训练流程完成；验证只完成3/12，1危险、2正常。未重试或重新生成任何失败/已成功回复，也没有把缺失结果当负例。

因此本轮不能报告完整验证集准确率、模型领先或跨域泛化。所有fieldcamp流程和classroom的均衡采购流程都未完成，缺失并非可忽略的小尾部。

服务端错误原因目前未证实。只读账户检查未报告普通使用额度已耗尽，这不能证明本地代理没有另一种错误；未兑换额度、切换对话模型或改思考强度。

原数值评测在任何拟合前因严格计时递增检查失败。检查实际记录发现，相邻事件具有连续序号但相同monotonic_ns。修正为“序号严格连续、时钟非递减”，仍拒绝时钟倒退、缺号及未来输入。原数据/源码/失败记录保留，在新目录单独冻结修正后的评测器；模型、提示、任务、划分和训练设置不变。

使用OpenAI Docs落实completed、拒绝和不完整回复的区分，未把失败回复修补成合格JSON。[官方回复处理说明](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode)

## 4. 同监督训练及结果

仅用12个训练流程的实际模拟派发标签，比较两个既定正则.001/.03：新互斥BN、去互斥约束的独立派发消融、独立实现的同条件softmax。另外保留相同边际但独立动作的消融，以及预先固定的优先级规则，共6个拟合、9种评分方法、135组预测。

独立派发是刻意去约束的结构消融，不能当作强的合法选择基线；独立softmax则是同信息同监督的有效对照，不伪装为新原生MAS论文。原生守卫的当前动作判定不能混为此处的未来派发预测。

| 互斥BN .001 | .095002 | .00002858 | 0 |
| 同边际独立 .001 | .059725 | .00004677 | .007425 |
| 独立派发重训 .001 | .058699 | .00014119 | .014553 |
| 独立softmax .001 | .095002 | .00002858 | 0 |

三条完整验证上的所有方法均判对，不具有足够区分力。互斥BN与普通softmax近乎等价；.001系数差约8.04e-6，同一参数下独立目标差约1.12e-16。因此这是将正确运行约束纳入模型，不是发明了softmax或已建立BN独有优势。

独立消融训练Brier反而较低，是通过给不可能的多选世界分配概率来抬高某些预算风险；不能用这种分数奖励违反应用协议的模型。正确的概率取值范围和预测准确性应分别验证。

## 5. 新数据暴露的实质设计缺口

训练中4个“均衡采购”流程、8个买方槽位全部选增强款。但当前模板对这些槽位的两个候选都给visible=unknown，两个选项的有效概率特征都为[1,0,0]。**无论如何训练，这个模板都只能给两种商品相同概率。**

目录价格和品质描述对Agent可见，金额进入了政策图，却没进入选择概率；仅增加互斥softmax没有解决候选选项的可区分性。这是从真实训练结果和代码得到的具体问题，记录在 `TRAINING_SUPPORT_DIAGNOSIS.json`，不是按3条验证调整模型。

下一版需要证据绑定的候选属性或具有明确语义的多类别结果参数，不能用随意的SKU/任务ID代替语义。之后才能检验共享规划状态的不确定性如何影响多个下游选择。此次不据验证分数选模型、不宣布这些部分已经完成。

此外，本轮只有payment偏好系数得到监督；release/other和授权先验没有真实学习证据。12个参数位不等于12个参数都被数据识别。

## 7. 与完整目标的距离

本轮真正推进的是：运行约束成为局部概率结构的一部分，互斥动作、共享权限和全局预算能够在同一风险计算中组合。仍缺候选属性建模、未观察共享规划状态、完整新验证队列、更广风险类型、自动工作流生成以及同目标原生MAS对照。目标保持进行中，不因小样本高分或测试通过而缩小完成标准。
