# 动作级BN：条件更新与阶段建模

## 1. 本次真正改变了什么

新增可选研究原型`ActionScopedJointBN-v3`，不修改或替换已经评测的69参数模型及71参数`TypedJointBN-v2`，不修改旧预测和指标。

上一轮发现：同一动作先提出、后得到权限检查时，v2的局部授权状态不能更新。本版把授权变量从“每个Agent一个累积值”改为“每个动作一个状态”，支持后续检查修正、检查过期、待执行动作取消，以及派发时保存信息状态。

**已实现可微模型、批量/增量计算、JSONL入口和机制测试；没有完成新数据上的训练评测，也没有新的准确率、真实预警或基线优势结论。**示例参数明确为未训练初始值。配置不假定文献已提供概率数值。

## 2. 文献依据与我们自行作出的选择

重新核读[AuthGraph §3.3–3.4](https://arxiv.org/html/2605.26497v1)：授权规范与实际轨迹分开，并检查工具及关键参数的来源。本版据此要求检查绑定明确的主体、动作和参数，而不是从消息来源推导权限。

动作生命周期、下述“最新完整检查替换条件因子”、事件序号有效期、派发快照及73参数网络是本项目的建模选择，不是AuthGraph原算法，不证明创新性，也不等于复现其参数来源检查器。原文没有提供我们的贝叶斯概率表、训练标签或跨Agent认证机制。

## 3. 状态与结构

| 变量 | 实际含义 | 何时改变 |
|---|---|---|
| 来源`Z_r` | 来源风险假设 | 来源首次出现；沿用已有模板 |
| 节点`C_i` | 信息影响假设 | 输入接受、实际消息传播 |
| 动作`A_a` | 该动作的授权风险假设 | 首次提出、有效检查更新、待执行检查过期 |
| 派发`D_a` | 派发当时节点`C_i`的快照 | 首次派发时确定；此后不变 |
| 动作阶段 | pending/dispatched/cancelled | 由可见事件确定，不是隐藏标签 |

来源、信息、动作状态保存在完整联合分布中。消息只传递信息状态，不传递授权异常；同一Agent的两个动作有不同变量，分组到同一工作流节点的不同Agent也不能借用彼此的动作绑定。

`D_a`保存模型当时对信息影响的假设，不是已经确认的恶意执行或外部副作用。`tool_call`表示派发记录，不自动等于操作成功或真实危害；外部执行结果目前没有接入。

### 3.1 后续检查怎样更新概率

检查返回unknown/no_mismatch/mismatch，结合已声明角色选择共享条件表，得到`q = sigmoid(theta[role,status])`。令`R`为其他变量，则替换规则为：

```
P_new(A_a=1, R) = q * [P_old(A_a=0, R) + P_old(A_a=1, R)]
P_new(A_a=0, R) = (1-q) * [P_old(A_a=0, R) + P_old(A_a=1, R)]
```

这样会更新当前动作的风险估计，但不改变其他变量的边缘分布，也不会把同一动作每次检查都算成一个新的独立风险。模型保留其他状态之间的相关性；当前授权因子仅以角色和最新检查类别为父项，没有建模不同动作检查器错误之间的相关性。

**这不是传感器似然的贝叶斯证据更新。**假设是：同一个检查器提供对同一完整动作范围的最新评估，新完整评估取代其旧版本。不能把此规则用在多个独立检查器的证据融合；目前检测到配置内的不同检查器接管同一动作会拒绝，等待明确的融合机制。

“无不匹配”只是一个观测类别，不是完整授权证明。数据不足时不同表项的真实语义不可识别；联合训练也没有保证表项必然按风险高低排序。

### 3.2 为什么保存派发快照

派发时确定`D_a = C_actor`，保留其与其他信息状态的联合相关性，同时固定该动作的`A_a`与检查记录。后来的消息、另一动作被取消、检查有效期过去，不会重新解释这个派发时点。

这里冻结的是历史监测记录，不是在断言历史判断不可被纠正。事后审核可能提供新事实；未来需要另设“当前回溯评估”，与原时点记录并存。本版对已派发动作的新检查明确拒绝，尚未实现这部分。

取消只移除待执行动作的当前输出项；不清除信息状态，不清除其他已派发动作，不保证系统总风险变成0。

## 4. 输入条件与信任边界

本版是信息较完整场景的可选增强，不能把这些字段假定为所有API日志都自带。敏感动作必须明确提供：

```
action_id, actor, principal, tool, resource, arguments
```

完整范围以规范JSON生成指纹。任一主体、工具、资源或参数改变，都需要新的动作ID。检查和取消必须针对已经出现的动作；不借检查记录预先创建未来动作。

独立检查事件还需要：

```
event_type = authorization_checked
checker_id, permission_status, check_revision, valid_until_sequence
```

- `trusted_checkers`在任务开始前由调用方配置；未知检查器或权限屏蔽条件下，检查不进入状态更新。
- **checker_id字符串不是认证。**可信日志适配器必须在模块之外确认消息来源。不能把任意Agent输出的JSON直接当作可信检查事件。模块没有实现签名、身份服务或权限规则引擎。
- 普通事件内的`permission_mismatch`/`permission_denied`裸字段不被当成绑定检查；解释会标明忽略。旧数据要使用旧协议评测，不能把裸字段补上伪造身份就冒充新协议数据。
- 检查版本严格递增。同一事件传输重试用`event_id`去重，不重新计数；内容冲突的重复ID拒绝。
- `valid_until_sequence`是本原型的事件序号有效期，不是墙钟时间。即使没有工具调用，只要到达后续事件，也会让过期的待执行检查回到unknown。未来真实接入需提供明确的时钟/策略版本合同。
- 当前敏感工具仍限于既有原型的`payments.write`、`filesystem.write`、`shell.exec`。动态工具目录、委派范围衰减和资源预算尚未实现。

缺字段会显式拒绝，不默认为安全，也不会静默改用旧模型。已有v2仍可独立用于更少观测的研究设置；二者输入条件不同，不能直接比较得分。

## 5. 系统输出与训练

继续以当前前缀预测任务最终风险，不把最终危险标签解释为每个时刻已发生危险。

参数总数为73：原四组概率表与消息置信度共52项，13项可见统计的系数，4项信息状态汇总系数，新增4项动作汇总系数。其中三个可见量明确更名为“存在待执行或已派发动作”“保留的权限评估非未知”“保留的权限评估有不匹配”，不把已过期的待执行评估继续当有效检查，也不把派发时的历史检查误称为当前仍有效的批准。

新增四项为：待执行授权风险、已派发授权风险、待执行的信息/授权重叠、派发时的信息/授权重叠。前四项原节点状态汇总现在只表示信息通道，因此参数名称已改成information前缀；不可把v2参数文件直接装入v3。

整任务等权、前缀分摊的二元交叉熵加弱正则，使用解析梯度联合训练。梯度穿过来源/接受/消息的OR更新、授权替换和确定性的派发快照。终态损失不应依赖已被完整检查替换的首次未知条件；早期前缀损失仍能训练该条件，此项有专门测试。

推断仍默认最多12个二值变量，包含来源、节点、动作和派发快照，复杂度指数增长。取消后的变量目前也不回收。超过容量拒绝事件；未解决大图或长任务推断。

输出包含动作范围指纹、阶段、检查来源/版本、忽略证据的理由、当前动作状态、派发快照及系统概率混合项。独立可执行的v3整图导出尚未实现，不能用v2解释图替代；`include_graph=True`会明确报错。

## 6. 机制验证而非性能评测

完整`paperAlpha/tests`测试277项通过，仍有4条既有sklearn数值/弃用警告；没有屏蔽警告。原版本的既有测试也包含在本次运行中。

新增测试包括：

- 同动作检查修正/过期、不重复叠加，其他动作不受影响；
- 主体/参数/资源/工具变化不能借用检查，失败不消耗序号或修改状态；
- 委派消息不传播授权状态，工作流分组不混淆原始动作主体；
- 派发快照不因后来信息影响改变，取消不抹去已有派发记录；
- 传输去重、检查版本、不同检查器冲突、缺失范围、容量拒绝；
- 每个前缀的批量与增量分数、完整联合分布一致；
- 独立的逐状态字典枚举与生产矩阵实现一致；
- 73个解析梯度在正/负标签、前缀/终态损失下均与数值导数一致；
- 小型带标签夹具可完成联合拟合，测试只断言训练目标下降，不输出“准确率”；
- JSON参数加载、规范指纹、CLI错误行处理、未训练标记和不覆盖结果。

机制演示保存于`results/action_scoped_mechanism_verified_20260919/`：11个手工事件、未训练参数、无标签、无API或工具执行。批量/在线分数和联合概率差异为0；历史状态最大浮点差异约`3.47e-18`。早期`action_scoped_mechanism_20260919`快照保留；新目录包含上述可见量名称修正，旧参数文件的规范指纹不能混用。

初始参数下某动作授权状态依次为unknown约0.0474、mismatch约0.2689、no_mismatch约0.0180、过期后约0.0474。这些只是初始化和更新规则的演示，**不是学出的真实风险率、校准概率或评测成绩**。不能与旧12组结果放在同一性能表。

对现有`results/independent_mas_v3/traces_public.jsonl`再次逐事件核查：4000条轨迹、37162个事件，其中4000个敏感调用全部缺少`action_id`、`principal`、`resource`和`arguments`；`authorization_checked`与`tool_proposed`均为0。文件SHA256为`a00577945e804edda2d5901f148ace27d5fd1684752598eff4707e6909ac1d6b`。

因此旧合成数据不能承担此次机制的实际有效性验证。必须收集或找到具有这些观测的正常/危险对照，并独立标注结果；不能通过伪造标准字段或按模型规则生成标签“证明有效”。
