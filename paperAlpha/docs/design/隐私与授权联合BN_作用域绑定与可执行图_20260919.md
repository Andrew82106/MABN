# 隐私与授权联合 BN：作用域绑定与可执行图

## 这次实际推进了什么

新增 `PolicyGatedPrivacyBN-v1`，把已有的隐私阶段模型和共享授权证明图接成一个联合概率模型：**预测内容出现，与判断该次内容传递是否满足指定引用授权政策，是两个不同变量。**授权链不再只放在解释文字里，也不是把两个最终风险分数相加。

默认 43 参数可通过同一个目标一起优化；导出的概率图能够脱离生产推断函数重新计算。48 个图例、全参数梯度、受控参数恢复及训练目标均已验证。

**这不是新的真实检测成绩。**本轮没有调用 API，没有改动旧隐私模型、旧分数或测试划分；真实、有授权边界的训练和独立验证数据仍缺。上一批 16 个 API 流程的 C0/W0/F0 结果不能用来验证这个新模块。

## 1. 知识依据对应什么实际结构

知识库原有条目已经明确：RB013 的成立条件包括敏感性、接收方与用途；RB014 的正常对照是获授权且任务必要的内部传递。本轮落实了其中可由结构化记录检查的部分：

| 条目 | 进入模型的内容 | 没有声称解决的部分 |
|---|---|---|
| RB009 委派扩大权限 | 复用父子授权范围收窄检查 | 不从角色名称推定授权 |
| RB010 参数来源 | 接收方、用途、字段组绑定到被评估的确切提案 | 不证明这些参数最初由谁自然语言提出 |
| RB011 跨主体/任务授权 | 绑定任务、主体、委托人、资源 | 不把 API 文本当认证身份 |
| RB012 撤销/过期 | 使用预测前已观察到的撤销、期限 | 不预测未来漏收的撤销 |
| RB013 对外泄漏 | 内容出现 AND 不满足配置引用授权政策 | 不覆盖所有隐私规范、意译泄漏 |
| RB014 内部过度披露 | 明确“出现敏感值”本身不是违规 | 本版仍只预测固定最终消息，没有逐个内部接收方的完整模型 |

条目及来源随实验冻结到 `KNOWLEDGE_BINDING.json`。这是**人工审核知识到可执行结构的具体映射**，还不是自动从全部文献生成任意子图。

`purpose` 当前是参与参数绑定的明确字符串，**不等于模型已经理解或证明“分享是完成任务所必需”**。必要性仍要额外的证据和监督。

## 2. 模型怎么连接

沿用隐私模型的 C/W/F 逐值出现变量，以及执行者 U、最终答复 V 两个统计状态。对每个被追踪的独立字面值 j，增加：

- `A_j=1`：该次预定发布不满足所配置的“必须引用有效授权链”政策。
- `H_j=F_j AND A_j`：值出现且该次引用政策失败。
- 系统目标：至少 k 个不同字面值的 H 为真；默认 k=1，可显式查询 k=2 等，不从测试结果选目标。

共享授权原子和 AND/OR 路径直接复用 `AuthorityProofGraph`。同一根被两次引用只出现一个随机变量，缺父链/未认证记录则保留作用域内的未知，不伪造共享依据。

联合分布（给定已知上下文与 C）为：

```
P(U | x) P(V | U,x) P(授权事实状态 z)
    × ∏_j P(W_j | C_j,x,U)
    × ∏_j P(F_j | W_j,x,V,A_j(z))
```

其中最终出现概率新增一个系数：

```
P(F_j=1 | …) = sigmoid(原最终阶段线性项 + δV·V + β·(1-A_j))
```

β 允许支持授权的发布和未满足授权的发布有不同出现倾向，是统计参数，不是因果效应。前一版 39 个参数 + 3 类授权未知事实 logit + β = **43**。不使用额外黑盒融合头来定义 H。

模型保留两类依赖：同一个阶段状态影响多个值；同一个授权事实影响多个发布提案。在每个共同状态内部计算违规数量分布，最后才混合。不能先压成逐项边际概率再相乘。

仍有明确假设：U/V 初始状态和不同授权原子之间按模型声明条件独立；W 不直接依赖最终授权状态；未观测授权失效在窗口内固定。最终 F 的条件项允许统计关联，但这不等于已解决共同攻击者、动态撤销或所有跨模块依赖。

## 3. 作用域和输入绑定

`ScopedRelease` 接收：身份无关的历史消息特征包、实际授权记录编成的证明图、发布上下文和逐值绑定。

每个证明必须与以下字段一致：任务、发布主体、委托人、资源、接收方、用途、字段组，以及 `release_literal` 提案类型。授权记录必须早于提案，提案不能晚于当前可见前缀。这个名称是监测契约中的提案类型，不是本轮真实调用了一个发布工具。

同一个字面值的别名仍为一个对象；不允许把它拆成多个独立泄漏，也不允许只绑定部分别名后悄悄计分。一个图只对应一个最终消息及指定接收方；不能把来自多个不相关任务/消息的值直接塞进来共享 V。

只有外部配置/适配器提供授权记录时才能启用这个分支。Agent 在文本中自称“已获批准”不会成为可信授权。引用政策失败也**不等于系统不存在其他未引用的合法权限**。

原隐私包只选择原允许列表之外的受保护值；新模块把输入对象视作明确指定的追踪集合。若要学习获授权的敏感分享，必须重新采集那些对象及其局部标签，不能把旧训练结果直接解释为该新范围的校准概率。本轮没有篡改旧数据的允许列表来伪造这项验证。

## 4. 学习与可解释图

联合训练使用实际/受控观察的 W、最终 F、可得的引用失败标签；缺少引用真值时逐项填 None。也支持独立提供系统结局标签，按 H 的确定性定义约束可能的授权世界，而不伪造每个局部授权标签。矛盾标签会报错，不给它们偷偷加噪声以维持拟合。

模型提供基于联合似然的梯度，所有 43 个参数可同时交给 L-BFGS-B。也允许预声明只优化部分参数；返回值区分“联合似然拟合过”和“所有参数一起优化过”。**能全参数优化不等于当前数据识别了全部参数**；有些参数在小对照中只受正则影响。

`probability_graph()` 导出逐节点二元条件概率表、共享原子、授权逻辑节点、出现节点、违规节点和系统计数节点。独立的 `scalar_binary_graph.py` 不调用生产前向函数，直接按这些表枚举并保留观察 W 的证据似然。

这说明输出图具有计算含义，而不只是事后画出的流程图；它仍是条件概率模型，不是发现了大模型内部的真实机制或因果图。

## 5. 实际数值检查

### 合法敏感内容不自动成为违规

人工设每个值出现概率 .8：完整支持的两项发布，违规目标为 0；同样的两项内容改成不匹配授权参数的接收方后，至少一个违规的概率为 .96。

0 只针对这个明确的引用政策目标，不保证没有其他风险，也不证明合法分享必要或安全。

### 相同局部边际，不同系统关系

人工设每项出现概率 .5、每个未知根失效概率 .2：

| 授权结构 | 每项违规边际 | 至少一项违规 | 两项同时违规 |
|---|---:|---:|---:|
| 共用同一个根 | .10 | .15 | .05 |
| 两个独立根 | .10 | .19 | .01 |

生产代码和独立枚举一致。这不是准确率比较，而是检查连接关系是否真的参与概率计算。共用根不应被简单设计成“总是增加风险”：至少一项和两项同时违规是不同问题。

### 可学习性，而非泛化成绩

六种明确构造的总体频数条件，共 256 个加权组合、总权重 6。**不是 256 条独立实验轨迹，更不是 API 数据。**固定已知的出现模型，只学习三类事实参数和 β：

- 设定 .20/.30/.40，学到 .19999993/.29999977/.40000009。
- 设定 β=.980829253，学到 .980829243。
- 8 次优化迭代收敛。

另一个四行小型机制对照优化全部 43 个参数：带正则训练目标从 4.195980 降到 2.448472，46 次迭代收敛。它只证明联合优化能运行，不是准确率或内部状态可识别性证据。

48 个导出图覆盖两种共享结构、六种授权情况、两个截止点和两个计数目标；独立图计算与生产概率最大差 7.22e-16。冻结复验检查 25 个产物，两个拟合目标差 0，六个方向梯度最大误差 1.02e-10；全部保存预测在 JSON 序列化规范化后逐字段完全一致。

## 7. 对整篇论文的意义和未完成项

共享随机事实、逻辑规则、BN 的组合不是新理论；[ProbLog 官方语义说明](https://dtai.cs.kuleuven.be/problog/tutorial/basic/08_rule_probs.html)已经明确区分共用随机选择与独立实例化。潜在贡献仍是 MAS 中的证据身份、作用域、时间和知识模板如何正确连接，以及这种连接是否在真实任务里有价值。

本轮让“隐私出现”和“授权关系”第一次在这个隐私候选的同一可训练概率图里计算，而不是两份互不相连的结果。它仍不是全部风险的统一模型：必要性、多个发布接收方、任意职责 DAG、持续变化的权限、额度片段融合与全图目标都未完成。

下一步应采集需要合法内部处理敏感资料、带真实发布提案与授权绑定的正常/危险对照，使用冻结参数或只用训练集学习，再评价新任务和新工作流。不能为了补正例强制产生泄漏；也不能从本轮人工规律恢复，跳到“胜过 MAS baseline”的结论。
