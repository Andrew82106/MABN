# 多工作流消息图与策略联合训练：来源补全及线索类型

日期：2026-09-20。研究主线仍为知识模板生成局部图、组合成系统图、监测API MAS风险。本轮完成不同既有工作流的统一编译、策略绑定和共享参数训练，不把框架接通或小样本高分写成MAS全面领先。

## 1. 本轮结论

- 两批40个既有API流程统一进入通用消息编译器：并行执行者汇合，以及共享/独立审核者后接两名发布者。沿用20训练/20验证，未新增API或读取保留测试。
- 分支图补上两个执行者各自直接收到的资料来源；实际私有记录不再仿佛凭空来自规划者。来源不是额外Agent。
- 消息目标与真实策略证明通过公共接口绑定，保留同一授权根和接收方/用途等完整作用域；不把可见缓存当作当前真实授权。
- 同一套BN参数在两类工作流上拟合。**简单事件BN优于复杂消息BN，强规则仍最好**；没有证据支持继续把复杂度本身当贡献。
- 初次运行发现沿用了“任务用途线索”模型名称来容纳“代理可见授权线索”，随后补了显式类型契约并重新冻结、训练、复验。旧结果不覆盖；896组概率保持完全一致，修正的是模型输入含义，不是分数。

## 2. 数据与工作流

### 分支汇合：16个既有流程

原结构为规划者→两名执行者→发布者。实际API输入还给每个执行者提供了各自的assigned_record，旧四节点事件投影没有表示这两个来源。新图有六个功能节点、12个字段事件：规划者、资料A、资料B、执行者A、执行者B、发布者。

两份资料分别从已记录的执行者请求的assigned_record组件提取，保留完整来源请求绑定；它们不是新模型回复。执行者仍接收实际规划文本，发布者仍汇合两份实际回复。字段是否在非归属分支出现按原文检查，不能按归属声明强制设为0。

这一批只有发布前截面：当前授权在执行者回复后才发生服务变更，因此不能拿后来的撤销状态编造“执行者回复前”的风险输入。数据仍为8训练/8验证，每边两个任务模板；最终各有2个危险流程。

### 审核后双发布：24个既有流程

一份原始材料进入一个共享审核者，或者分别进入两个审核者，再由两名独立API发布者生成答复。分别有4/5个功能节点，包含审核前和审核后两个输入截面。使用已保存的真实请求核对每名接收者获得的具体文本。

沿用12训练/12验证，各一个任务主题。训练仅1个最终危险流程，验证没有危险流程。中间回复有正负字面出现事件，可以训练审核节点，但不能据此声称最终风险检出充分。

两批合计核对原有148次API请求，得到64个输入截面。所有任务材料原本就是虚构的受控开发材料，不是新采集真实用户业务。合并后的验证只有2个正例；14种方法都是在同一批已暴露开发数据上比较。

## 3. 模型与策略如何结合

`message_policy_binding.bind_message_policy`接受已编译事件DAG、独立授权证明图、具体未来消息事件及完整动作绑定。每个目标必须指明主体、资源、接收方、用途、字段别名等，且与既有证明一致。目标名称不是权限，也不能从任务线索生成授权。

事件预测给出两项目标的完整联合分布；策略图判断每种组合是否违规。共用的上游审核事件不拆成两个独立副本，共用的授权事实也只保留一份。流程序号和授权服务窗口继续分开，不伪造时间换算。

本轮真实记录的当前授权事实均已知，因此系统策略是确定的；不确定的是后续消息出现。共享授权未知情形通过构造机制测试检查，但**没有在本轮实际数据上学习或证明未知授权概率校准**。

## 4. 线索必须有类型，不能只叫“支持/反对”

初次运行使用`SemanticArrivalWorkflowRiskBN-v1`，其保存语义宣称是初始任务相关性假设。但分支发布者输入的是可见授权链判断。这两者虽然能使用同样数值0/1表示，含义却不同，不能沿用同一含糊名称。

修正后的`ContextualMessageWorkflowRiskBN-v1`保留65个事件参数及原消息概率公式，但增加明确的当前模型输入契约：

- 审核阶段：`task_retention`，表示实际指令要求保留、删除或未明确。
- 发布阶段：`visible_authority`，表示代理实际看到的缓存是否支持、反对或无法支持发布。
- 未提供线索为unknown；非零线索必须带正确类型。类型与阶段、具体事件、底层原始记录和可见时刻绑定。
- 当前真实权限仍由独立策略证明图给出，不是上述任一线索。

这两个类型当前分别对应审核和发布参数族，并没有新增一个按类型任意插值的黑盒头。模型会拒绝不支持的非零类型；这个受限契约不等于所有任务用途/权限/审核语义已经通用化。

类型、原文引用和字段一致性只能证明模型用了什么依据，不能自动证明分类本身正确。本轮的用途线索来自采集时显式指令映射，授权线索来自实际可见缓存的既有检查，不是新调用大模型打的标签。

原始实验保存在`compiled_multiworkflow_development_20260920`，带`SEMANTIC_SCOPE_CORRECTION.json`；修正结果另存`compiled_multiworkflow_contextual_20260920`。全部896组联合概率与运营分数逐项一致，没有根据结果修改数据、数值特征、正则、阈值或默认模型。

## 5. 训练和对照协议

四个BN拟合：简单逐事件BN、上下文消息BN，各用既定正则.001/.03。每个模型都在20条流程上共同拟合，不为两个数据来源分别训练。每流程只用最早可用截面的完整后续联合似然：审核数据训练审核/发布事件，分支数据训练发布事件，共58个字段标签；消息版共50条未来消息因子。既有3个授权先验不拟合。

普通对照：两个正则的直接四分类模型、一个小型HistGB；每个方法按早/晚截面分别训练输出头。早期训练12条审核流程，晚期训练20条混合流程。输入949维固定填充表示保留事件功能、线索、已观察状态、目标位置、相邻关系、同消息分组、同信息关系以及当前策略真值表；不使用任务/条件ID、生成模型名或未来结局。16事件容量超出就拒绝，不裁剪。此表示对节点排列敏感，不能声称图同构不变。

BN使用中间字段监督，而直接分类器只使用末端两位标签，监督量不同；直接分类器的早晚头也各自拟合，不冒充同样的训练预算。

另外保留四个BN各自的“同边际、去掉目标间依赖”版本，以及始终不出现、按上游保留除非要求删除、仅可见支持才输出三种规则，共14种评分方法。独立边际对照仍使用同一套当前策略，不能通过删权限信息弱化对照。

本小实验没有另分校准集，.5报警指标仅为预定描述性统计；不根据20个验证流程挑阈值。正式概率采用统一8位舍入，联合分布和原始风险概率同时保存。汇总首/末截面时每流程只计一次；分支只有晚期，不伪造早期。

分组看，分支数据晚期Brier为：事件BN .001约.000246、消息BN .001约.002713、HistGB约.0000025、强规则0。审核验证没有危险结果，强规则全部预测不出现恰好正确。总体上BN数值优于部分普通分类器，不等于BN独有收益，也不能推广到AgentLeak上一轮千条数据。

## 8. 后续研究边界

本轮解决了按工作流编译后的共享训练、来源缺边和上下文线索定义问题。没有完成自动职责/DAG提取、多种语义危险机制、足量独立标注数据或原生MAS方法完整对照。当前执行来源参数只在已经观察到的分支阶段出现，本轮并未因此学到执行者之前的行为预测；不能把补两条输入路线当作提前预警提升。

下一步需要的是能检验联合关系价值的新任务和观测条件，并固定同信息、同监督的强对照；不是在这20条验证上继续调出更好数字。模型内部仍不要求权重或激活，不自动阻断，不改用户选定的对话模型和思考强度。
