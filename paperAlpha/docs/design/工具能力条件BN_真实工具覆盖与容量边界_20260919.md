# 工具能力条件BN：真实工具覆盖与容量边界

## 1. 本次升级的位置

新增可选 `CapabilityActionBN-v4`，位于“公开工具知识 → 条件模板选择 → 动作级BN”这一层。它不替换v3，不沿用v2的评测分数，不表示自动职责分组、自动DAG或完整风险子图生成已经完成。

真实采集已暴露：47个领域工具调用的名称均不属于旧版三个敏感工具别名。现在每个工具操作都进入动作监测，通过有来源的公开描述选择能力条件表，不再依赖这些别名。读取资料同样可能受访问范围限制，不设“读取工具一律安全”的旁路。

## 2. 描述如何进入计算

配置 `configs/harnessaudit_public_capabilities_v1.json` 收录8个公开工具名称和完整描述，并逐条附支持片段。原仓库提交与描述已逐项核对。未使用任务授权规则、标签、`is_resource`、模拟返回或工具后端逻辑作为模型输入。

第一版是**人工审核的主能力归类**，不是自动LLM抽取，也不是已经验证的实际副作用。片段确实出现于描述，只能支持标注的可追溯性，不能证明分类一定正确或工具实际实现与描述一致。

主能力为：读取信息、信息处理、对外通信、状态修改、付款效果、未知。每项操作暂只有一个主类别，复合工具的多种效果、参数级敏感性及多个风险机制仍待实现。例如金额和收款方目前用于绑定同一操作，尚未被解释为预算或收款范围特征。

旧授权表为 `角色×检查类别` 共15个单元。新版变为：

```
q(action) = sigmoid(theta[主能力, 角色, 当前可信检查类别])
```

共6×5×3=90个单元。其他信息来源、接受影响、消息传播及生命周期规则沿用v3；两个新增可见统计分别表示未知能力动作比例、动作范围不完整比例。系统层仍与局部条件表联合求导训练，不是仅在解释中增加一个类别名称。

参数总数150：来源3、接受影响15、能力条件授权90、消息传播18及置信度1、系统读出23（15个可见统计、8个潜在状态汇总）。所有类别以同样的旧授权初始值开始，不人为宣布付款必然比读取更危险；当前没有校准概率或单调性保证。

工具名称只用于查找冻结的描述和绑定动作。改名且同步更新注册表后，同样的能力、事件和参数给出相同分数与联合状态，包括故意改成旧别名 `shell.exec` 的测试。能力变化则能选择不同可训练参数并实际改变预测。

## 3. 不完整观测如何处理

动作仍须提供真实 `action_id/actor/tool/arguments`；`principal/resource` 可以缺失或为null。它们保留为未知，不从角色名称、参数中的任意字符串、工具返回或基准答案推测。

不完整动作可进入风险监测，但不能接受范围绑定的授权检查。绑定首次记录后不可变；本版尚不支持同一个动作后来补全范围。需要另行设计范围补全事件，不能把“补全失败后新建动作”自动当作同一次调用。

完整范围下，可信检查更新、过期、取消和派发快照仍沿用v3。配置中称为 `available_tools` 的清单只表示工具可用，不表示当前动作获准。`authorize_payment` 依据公开描述属于付款操作，名字中的authorize不会生成检查事件。

未登记工具进入显式unknown类别，输出缺口清单，使用独立可学习单元与未知比例统计；**这不是未知时保证高风险或自动拒绝，更不是默认为安全**。本原型仍只评分，不阻断。

动作参数作为不透明载荷保留在范围指纹中；合法参数名`label`不会被当成训练目标。事件/轨迹外层的标签与事后结果字段仍被拒绝，参数文本没有被解析成可信授权或风险类型。

## 4. 实际验证结果

运行目录：`results/capability_action_verified_20260919/`。

### 公开描述与真实工具覆盖

两次此前API运行的47次工具调用映射如下：读取33、信息处理9、对外通信3、付款1、状态修改1、未知0。8个工具描述与固定版本官方目录逐项一致；旧别名匹配仍为0。

这是**已知目录的表示覆盖率**，不是47次都检测正确，也不是对未知工具的泛化成绩。只用公开名称/描述选择类别，没有读取基准权限规则作为模型特征。目录中的隐藏标记、结果或标签改变不会改变对应检查结果。

### 真实工具入口的有限前缀回放

仅第二个真实运行有23组工具入口记录。本次投影只采用入口处实际观测到的调用身份、Agent身份、工具和参数；不读返回结果，不借用事后标签。`principal/resource` 均为null，角色保留unknown。

为了不凭不一致的时钟猜通信顺序，**本次回放只含工具入口，不含跨Agent消息，不是完整MAS评测**。事件以原入口日志的记录顺序编号，表示实际派发入口，不冒充更早的模型提案。

在12变量精确推断限制下，前5次工具调用能正常接入并与批量计算一致；第6次明确触及容量上限，后18次未处理。没有静默重置、分块后宣布全任务通过或任意增大指数状态空间。容量拒绝不修改此前状态。

### 机制与回归

- 另有11事件手工MAS例子，包含跨Agent消息、完整检查、过期、派发、第二动作及取消；批量/在线分数和联合分布差异0。手工例子与真实记录严格分开。
- v3与升级前冻结源码比较：13个参数向量×11个前缀，分数和联合分布差异0，说明接口重构在该范围内没有改变旧模型数值。
- 150参数在正/负标签、前缀/终态损失下的解析梯度与有限差分一致。
- 独立字典枚举未调用生产代码的转移、状态编码或特征函数，结果与模型相符。
- 小型拟合只验证训练目标下降，不报告准确率。

本轮新增39项测试，完整项目378项通过，保留4条既有sklearn数值/弃用警告。结果目录中52项冻结源码/输入哈希已复核一致；当前能力模型源码与该快照一致。测试通过证明所检查机制和接口，不证明监测效果。

运行脚本保存参数、输入哈希、源码快照、逐前缀解释和显式未处理数量。参数均为未训练初值；没有新API调用、性能评测、基线比较或现实安全保证。

## 5. 尚未解决的核心问题

1. **长轨迹推断**：每次已派发动作继续保留授权和信息快照，容量随动作数增长。下一步应研究按系统读出保留必要历史统计、消去不再变化的旧变量，并在小图上与完整枚举比较；不能直接假定节点独立或静默丢弃历史。
2. **从描述到结构**：现在只选择能力条件表，没有按风险知识自动增加多效果、数据泄露、预算累积、凭证委派、共享记忆等不同子图。
3. **语义证据**：工具结果的信息来源、消息内容的实际采纳、参数敏感性仍未抽取；读取操作被登记不等于读取内容已经成为来源变量。
4. **真实MAS评测**：采集的两例不足以训练或比较。需保留正常/危险及截断任务，构造独立标签、消息与生命周期统一时序，并对齐真正MAS基线的输入和任务。
5. **可解释性范围**：局部潜变量仍是假设，不是已识别真值。新增能力条件表可能不可辨识；知识或参数更多不自动提高效果。v4整图独立导出仍未实现，不能使用v2图冒充。

本轮只是使“知识选择模型参数”和“不完整API动作观测”成为可运行结构，并通过真实记录确定下一步容量问题；不缩减完整研究目标。

```python
from paperalpha_monitor.tool_capabilities import load_tool_registry

# 仅示范接口；默认是未训练参数，不能作为真实风险率。
model = CapabilityActionBN()
monitor = CapabilityRiskStream(model, tool_registry=load_tool_registry())
monitor.push({"sequence": 0, "event_type": "tool_call", "action_id": "actual-call-1",
              "actor": "worker", "tool": "authorize_payment", "arguments": {"amount": 5}})
explanation = monitor.explain()
```
