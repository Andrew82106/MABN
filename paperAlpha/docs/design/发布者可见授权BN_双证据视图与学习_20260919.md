# 发布者可见授权 BN：双证据视图与学习

## 本轮结论

新增 `PublisherViewPrivacyBN-v1`，把上一轮发现的输入视图差异落实为概率图结构：**发布者实际收到的授权线索影响内容出现，监测器的当前授权证明决定出现是否违规。**两者不再通过同一个“真实授权是否失败”变量控制。

默认 44 参数可联合优化。34 项新测试、50 张机制图、32 个真实输入视图的 128 次图计算及冻结复验已通过。新增系数为零时，旧 32 条完整评分记录精确保持不变。

**没有新增 API 调用，也没有新的真实检测提升。**旧真实材料中的发布者可见授权线索全为“表面支持”，无法据此学习支持/反对/未知之间的差异。本轮没有拿受控频数训练结果去替换真实评分器。

## 1. 知识依据与实际改动

继续使用既有知识库，不把这一轮当作新增文献成果：

- RB009：委派不能扩大父授权范围，角色名称不是权限证明。
- RB011：授权必须绑定主体、任务、接收方和范围。
- **RB012**：动作等待期间权限变化，执行者可能仍依据旧批准；这直接要求区分当前记录与执行者收到的记录。
- RB013/014：内容出现不等于违规，接收方、权限和必要性不能被混为一个文本标签；本模块仍未解决任务必要性。

代码：

- `src/paperalpha_monitor/publisher_view_bn.py`：双视图输入契约及新 BN。
- `policy_gated_privacy.py`：将原有出现条件项提取为可替换接口；原版默认结构、参数名、序列化模型名和输出保持原有含义。
- `scripts/publisher_view_fixtures.py`：明确标记的机制材料。
- `scripts/study_publisher_view_bn.py` / `verify_publisher_view_bn.py`：冻结学习、真实请求输入重建与独立复验。

这不是恢复了 API 模型内部信念，也不是因果发现。它仍属于项目“知识约束的可解释风险图”主线，是一个可以组合的隐私/授权片段，而非完整职责 DAG 自动生成。

## 2. 两类证据不再混用

### 当前授权视图

沿用 `ScopedRelease` 和共享授权证明图，记录监测器有来源的当前授权事实。对值 j 得到 A_j：是否不满足配置的引用授权政策。同一授权根被多项发布引用时，仍只建立一个共享随机事实。

### 发布者输入视图

新增 `PublisherInput` 保存实际送给发布者的请求负载及其摘要、可信传输记录器名称、捕获序号和当前传输日志截止序号。`ViewSeparatedRelease` 核对任务、主体、接收方、用途、资源、字段别名及参数摘要。

这里只从**发布者收到的缓存**提取两项可观察线索：

- E_support：所呈现的引用链表面支持该次发布。
- E_contradict：所呈现的引用链明确不支持该次发布。

输入未捕获、父链未解析等情况使用明确的未知参考类别，两项均为 0；不把未知当作拒绝，也不自动从监测器记录补齐发布者缓存。每项状态及所依赖的请求摘要都保留在解释中。

**传输记录器捕获到一段 JSON，不等于证明 JSON 内自称的授权机构、签名或权限真实。**这些线索只用于预测行为，不自动升格为当前授权事实；真正的授权证据仍须由外部适配器独立提供。这也允许描述发布者收到了误导性或过时授权说明的情况，而不授予其权限。

## 3. 概率结构

沿用信息出现变量 C/W/F 和阶段状态 U/V，联合分布变成：

```
P(U | x) P(V | U,x) P(当前授权事实 z | 监测证据)
  × ∏j P(W_j | C_j,x,U)
  × ∏j P(F_j | W_j,x,V,E_support_j,E_contradict_j)

H_j = F_j AND A_j(z)
系统目标 = 至少 k 个 H_j 为真
```

最终出现项为：

```
logit P(F_j=1) = 原阶段出现项
                 + β_support × E_support_j
                 + β_contradict × E_contradict_j
```

没有从当前真实 A_j 到 F_j 的直接边。未知类别是基准，不另加第三个与截距冗余的类别系数。两个 β 不强制正负，实际行为可以违背输入中的要求；训练目标仍需数据判断这种关系。

参数数目：39 个阶段/出现参数＋3 个当前授权未知事实参数＋2 个可见线索系数＝**44**。移除阶段关联的版本少一个参数。

保留两种系统依赖：多个值共享 U/V；多个引用共享当前授权事实。在这些共同状态内计算违规计数分布，之后再混合，不先把各项压成边际后相乘。

这仍假定在指定上下文下，初始阶段状态与不同当前授权原子按模型声明独立；没有学会任意视图相关性、动态权限变化或隐藏攻击者策略。外部记录融合依然是适配器职责，不能以新增两个输入线索宣称完整解决证据融合。

## 4. 两个关键结构检查

1. **固定发布者输入，只改变监测器当前授权视图**：每项最终出现概率保持不变，但违规概率随当前权限改变。
2. **固定当前授权事实，改变发布者收到的支持/反对线索**：最终出现概率可以改变，授权失败概率不变。

两个检查都使用明确给定的非零系数验证，所以不是因为参数全零才“碰巧独立”。导出的 F 节点父节点为 W、V 和两项可见线索，不含 A；H 仍同时依赖 F 和 A。

机制材料包含当前真实记录与输入说明不一致的组合。这是在检验错误/过时输入与事实分离的结构，不将所有组合都描述成同一个诚实、单调授权服务的可实现历史，也不称作 API 因果实验。

## 5. 时间边界

授权事件沿用任务内逻辑时钟，输入捕获使用实际传输日志时钟；二者分别检查，不能拿一个时钟的数字比较另一个时钟。

发布者的最终请求包含执行者回复，因此当前接口**不允许在执行者回复前使用它**。早截止点只允许“尚未捕获发布者输入”的显式未知视图。若将来要支持预配置策略在早阶段生效，应增加独立的早期配置证据接口，而不是提前读取最终请求。

实际回放中，输入取得时点是最终 API 请求事件：晚于原有监测结果，早于最终响应。新模型这次只做离线重建，不能将新分数伪称为当时已在线输出。

## 6. 学习与验证结果

### 受控频数学习

设置最终出现概率：支持 .8、反对 .1、未知 .4；执行者出现概率为 .5。展开得到 48 个带精确权重的组合，总权重 3，**不是 48 条独立轨迹或实际 API 样本**。

固定已知出现基准，仅学习两个新增系数：

- 目标值约 +1.791759469 / -1.791759469。
- 学到 +1.791759470 / -1.791759471，8 次优化迭代。

这只证明有区分条件时两个参数能从频数中恢复。普通条件 Logistic 也能表示这一出现项；新增条件项本身不是新统计理论。

另一个四行机制对照联合优化全部 44 参数，65 次迭代，正则训练目标从 3.261125 降至 2.062533。部分参数仍主要由正则约束，不能解释为四行材料识别了全部参数，更不是泛化成绩。

### 真实输入回放

复用上一轮 16 个实际流程的两种监测视图，共 32 个输入视图。新增系数均置零，只从既有训练模型迁移原参数，不使用上述受控拟合值。

- 原版完整评分记录 32 项逐字段保持一致。
- 新版两个模型、两个计数目标，共 128 次概率计算与旧对应分数最大差 **0**。
- 每个新可执行图均独立计算验证。
- 共 64 个“视图×字段”输入均为支持类别；它们来自 32 个实际对象被两个监测视图重复表示，不能当作 64 个独立对象。
- 可见线索加截距的设计矩阵秩为 **1**，无法识别支持/反对/未知的条件差异；且旧数据没有最终过滤例子。

因此本轮没有在旧真实数据上训练新系数，也没有产生新性能领先结论。

## 7. 下一步与完整目标

下一批应使用新冻结材料，让发布者分别收到：有效批准、撤销前旧缓存、明确的新撤销通知、缺少完整依据。让 Agent 自行决定保留还是过滤，不强制最终标签。

新增条件也必须给简单规则、Logistic/树模型等 baseline 同样使用，不能只给 BN 增加可见权限信息。训练/验证/测试按任务或工作流隔离；当前已查看轨迹不再冒充新的独立测试。

仍需扩展到实际多分支协作、多接收方、角色知识子图及不同风险片段的统一学习，并完成可用的原版 MAS 对照。当前固定隐私最终消息模型是中间组件，不是将完整项目缩小到这个组件。

本轮未新增 API 请求、未改任务模型或思考强度、未提交/推送 Git；既有冻结结果不覆盖。
