# 字段到达与任务用途联合建模：消息 BN

日期：2026-09-20。新增`SemanticArrivalWorkflowRiskBN-v1`。本轮继续完善“可观测工作流 → 知识线索与事件关联 → 系统风险查询”，没有改变API MAS安全监测的研究对象。

## 1. 从具体结构反例出发

上一版能读取任务字段用途，但消息节点只知道全体字段的用途比例。若一条回复只含需要输出的字段、另一条只含不需要输出的字段，只要数量一样，最终整消息风险仍可能相同。该反例已经固定在`tests/test_task_cue_relational_gap.py`，不是依据本轮验证结果临时添加特征。

本轮把“哪项信息的上游出现了”与“这同一项信息在下游的任务用途”对应起来。不是再加一个抽象的恶意状态，也不是把工作流有边当作实际信息已经到达。

## 2. 新消息节点的精确定义

沿用可观测OR消息节点G：固定追踪集合里是否至少有一项字面值出现在这条完整消息。它不是内部意图，也不是授权事实。给定G=1时的字段向量仍采用原非全零条件分布，概率归一化与逐字段事件含义保持不变。

对消息中的字段j，记其自身上游事件状态均值为m_j。若有两个上游，就取这两个该字段事件的均值；没有上游则为0。新增两个消息特征：

```text
支持用途的上游出现比例 = Σ(字段j的支持线索 × m_j) / 字段总数
反对用途的上游出现比例 = Σ(字段j的反对线索 × m_j) / 字段总数
```

线索仍来自上一轮冻结的初始任务分类：内部用途与对外形式分开；未知不强行设为支持或反对；语义分类不授予权限。这里的“出现”指所声明输入事件中的字面出现，不额外声称真实接收、采纳、语义泄漏或因果关系。

已观察到上游回复时直接使用实际事件；Worker尚未回复时，上游状态仍是联合推断里的未知变量，不补为0，也不提前使用后来回复。固定AgentLeak发布阶段只依赖Worker；Worker阶段保留资料库与协调者两条输入。

新节点把原6个消息特征扩成8个。五类功能合计40个消息系数，加25个局部事件系数，共65个事件参数；另有3个既有授权参数，本轮授权已知、不拟合。参数槽位存在不代表全部功能类别已被数据识别。

所有关系仍在同一联合分布里。没有把第二个分类器的分数加到BN上，没有加入不透明的GNN。新增关系是可学习交互项，不是新的概率定理或已经证明的因果机制。

## 3. 结构验证与解释边界

固定反例中，若支持/反对到达系数分别设为+2/-2，两字段场景中只到达支持字段时q约.731，只到达反对字段时q约.269。旧版两种情况相同。这只证明新路径参与了计算，不是训练效果。

将两个新增系数置0，能恢复旧语义消息模型的完整联合分布，而不只是恢复一个终点分数。显式BN导出、训练似然、65个事件参数的训练与预测梯度均有测试；字段重新排序不会改变结果。授权与策略输入保持不变。

早期预测的独立参考计算枚举Worker所有二值字段组合，再按各组合下的最终消息概率求和；它不调用生产模型的消息因子、设计矩阵或变量消元。较晚整消息查询沿用上一轮已经限定范围的精确q等式，避免历史归一化的浮点尾差。

## 4. 冻结实验与同信息对照

继续使用原1618拟合/515校准/1026开发验证划分；不读取旧测试集，不新增API请求。复用上一轮12次分类的原始请求、回复和162个字段判断；没有因为上一版效果变差而重新提取或手工改分类。

BN对照：无语义计数版、静态用途比例版、本轮字段到达关联版，每组都用原预设正则.001和.03。普通Logistic和HistGB分别使用原8个计数特征或80维计数+字段状态/语义联合直方图。后者本来就包含这种配对信息，没有通过弱化对照制造优势。

BN仍使用实际Worker与最终消息的逐字段联合监督；普通分类器只用最终标签。这个监督差异继续披露，不能称监督预算完全相同。所有模型重新拟合，所有阈值重新在校准负例上确定，不移植旧阈值。

### 分数精度是统一运行协议，不参与梯度训练

上一轮发现约1e-15的舍入差会人为打破数学等分样本的并列。本轮预先规定十种评分方法都对原始二进制浮点概率执行Python `round(p, 8)`，再做校准、排序和报警。原始概率同时单独保存，模型/评分流程指纹包含该变换。训练损失和梯度仍使用未舍入的概率。

这个精度远大于先前核验的浮点误差，不是根据本轮结果挑选；最多改变约5e-9的概率。独立复验同时检查原始概率、变换值、阈值、报警，以及相同有效特征的样本是否仍同分。它不保证新任务的误报率，也不是数学意义的通用浮点误差上界。

所有材料都曾被用于开发，只有四个验证任务模板，不能称新的独立测试或部署验证。原生MAS监测方法的新对照、自动DAG、异构知识模板生成、跨工作流与多风险目标仍未由本轮完成。

## 5. 已完成结果：结构有区别，但没有带来整体提升

十种评分方法全部完成。以下召回/误报采用相同的整流程阈值校准规则，各方法的实际验证误报率不同，不是同误报率排名。正例326、负例700；每个预设配置均报告，不更换默认模型。

到达关联相对于静态语义仅小幅降低晚期Brier，早期反而退步；两组都没有超过对应无语义BN。共同阈值下，.001仍只发现5例，误报8→10；.03仍发现11例，误报11→13；两组首阶段正例召回都是0。不能把“能区分构造反例”说成“真实监测更强”。知识线索增加没有自动带来效果增加，也不能据此反推语义分类全错。

固定精度后，.001计数版与静态语义版晚期AUROC均为.734673532，到达关联版.734717353；不把约.000044的差别当作显著提升。旧分数与排序不被覆盖。

### 消息门控的同监督Logistic对照

`scripts/audit_semantic_arrival_gate_equivalence.py`只读取1618条拟合流程的实际中间/最终消息，分别为六个BN配置的Worker/发布门控拟合独立sklearn Logistic，共12个门控对照。截距也是被正则的显式常数列，采用相同平均损失与L2权重。

最大训练logit差5.59e-5、最大目标差3.69e-11。到达版Worker/发布设计秩为7/8，静态语义为5/6，计数为3/4；新增特征确实提供了新的线性方向，但没有取得相应泛化收益。这里只证明门控目标的等价与优化近似一致；不把它称为完整的早期联合推断baseline或新的MAS原生对照。
