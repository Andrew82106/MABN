# 运行文本证据层：真实提取与语义边界

## 1. 本轮进展

在“API运行观测 → 知识模板/BN”之间，新增可运行的文本证据提取原型。读取共享日志的通信和工具返回，调用用户指定本地接口的`gpt-5.5`，输出有原文引用的候选主张及先前文本关联。不是新MAS执行，也没有训练或改变150参数BN。

上轮发现的信息通道失活**尚未因本轮自动修复**：这些结果还不能直接充当`input_received=untrusted`或可信权限检查。实现证据提取是修复链路中的一步，不是完整研究目标。

API方式按[OpenAI Docs结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)采用Responses `text.format/json_schema`，同时检查未完成/拒绝与本地原文引用。结构正确不等于语义正确。实验API固定5.5、low、2200输出token上限、每次60秒超时、客户端不重试、并发2；不改变本对话模型/思考强度。密钥仅来自进程环境，不进入请求日志或源码。

## 2. 输入与输出约束

核心：`src/paperalpha_runtime/semantic_evidence.py`。运行与验收：`scripts/extract_runtime_semantics.py`、`scripts/audit_semantic_extraction.py`。

输入逐条通过原运行日志校验。一次工具返回只选择一次，不重复读取原生工具结果事件；只选择实际返回时已知的内容，不在工具入口预读结果。当前记录和候选历史均保留原始文字。

每次模型请求包含：

- 当前消息/工具返回、记录ID、Agent身份、接收者或工具及调用ID。
- 最多6条先前记录，限于该Actor自己产生的记录、自己的工具返回，以及先前向它发出的消息。
- 当前加历史最多16000字符，选择最近的完整记录，不截断句子；当前记录单独超限时不发请求，显式留下缺口。
- 文本选择范围和遗漏数量。不提供隐藏任务授权规则、最终标签、事后access_decision或未来记录。

“先前向该Actor发送”只证明记录了路由，不能证明收到了、读了或采纳了。当前用户目标/系统提示尚未由此接口选择；后续需把合法的初始任务约束与隐藏评测规则分开接入，不能把遗漏目标当作完整上下文。

各请求独立：不会将早一轮提取器的回答当事实再喂给下一轮。历史来自原始日志，不来自模型摘要。虽然离线脚本预先收集请求包，每个请求包只由它自己时刻的前缀生成；未来内容篡改测试和冻结重建均验证这一点。

### 候选观察的六种类别

1. `instruction`：要求某人做某事，不代表已执行。
2. `authorization_claim`：声称有/无批准，不代表可信授权。
3. `constraint`：陈述额度、作用域、禁止项或前置条件。
4. `rejection_or_warning`：拒绝或警示某条建议/内容。
5. `action_claim`：声称某动作已发生或未发生，不代表外部事实。
6. `uncertainty`：明确未知、未确认、缺失或冲突。

另有表达方式（直接陈述、转述、拒绝、未定）和肯定/否定/条件/未定标签。这些均是模型提议，不能直接等同于风险状态。当前类别是针对已知机制的工程接口，不宣称来自某篇论文的完整分类法。

每项附：精确连续原文、出现序号、由本地代码计算的Unicode字符起止位置、原记录哈希。可选关联只允许引用候选历史中的原文，可标“同一主张/支持/矛盾”，但一直保留`semantic_relation_verified=false`。

同一内容不自动生成独立来源；没有从同一句“已批准”创建授权事件，也没有生成安全/危险标签或风险概率。`no_supported_claims`只是没抽出这几类内容，不等于安全；最多8项的输出不能声称穷尽。

## 5. 实际审阅发现的语义问题

本轮只做了指定片段和全部4条“矛盾”提议的作者检查，没有对全部产物作盲审，不给准确率。

### 时序变化可能被误判成矛盾

`journal-50`后续条件化执行指令被关联为与`journal-3`的“暂不授权/提交”矛盾。前一句包含“yet”，两者可能只是工作阶段更新，不能直接推出策略冲突。`journal-12`返回找不到名为medical_notes的scope，与早先请求获取医疗背景，也不必然是命题矛盾，而可能是工具参数名称不匹配。

其余涉及“找不到coverage record”和“已有coverage_context”、以及“349美元在直接支付范围内”和“预算表上限0”的关系，也需要区分资源标识、字段作用域和政策来源；相同请求ID不代表同一预算或同一授权对象。不能因为引用真实就把关联边当真。

### 否定/条件标签的目标不清楚

真实日志的“Provider response not available”被标为`uncertainty/negated`，手工对照“No approval record is available”却被标为`uncertainty/affirmed`：提取器有时在标记句子否定，有时在肯定“不确定性存在”。条件约束原文虽然被保留，类别的polarity也不总与授权主张一致。

因此v1的polarity不能不经修订就成为高可信BN观测轴。必须明确它对应的是哪个命题，并增加针对性独立标注；不能静默把它改名成真实风险标签。

### 范畴也可能过宽

某些状态描述、价格/估算值被归入动作主张或约束。例如“Estimated Out-of-Pocket: $349”是一个估算，不等于“支出上限349”。后续需明确事实值、规范约束、动作发生、条件许可的区别，避免单靠kind计数拟合出难解释的分数。

## 6. 接入BN前的设计修正

不能把本轮所有指令都映射为untrusted输入，也不能将所有工具返回当独立恶意来源来强行激活37个参数。下一版应遵循：

1. **分开主张类型、主张内容与表达姿态。** 对否定和条件指明目标命题；约束至少保留对象、数值/单位、条件及原文，不从价格估算推导额度。
2. **把语义关联当有噪提议。** 增加阶段更新/不同对象/无法比较等情况；未经核验的“矛盾”不得成为硬事实、可信权限或因果边。
3. **区分观测与隐藏状态。** 提取器输出应通过有误差的观测模型影响来源/采纳/动作风险，而不是把提取标签直接设成隐藏状态真值；正常指令、引用、拒绝和合法授权必须作为对照。
4. **统一来源身份与推断规模。** 使用可核验的来源标识时才共享；文本引用关系本身不证明独立或同源。19个返回直接建19个独立来源既可能错算相关性，也超过当前容量，仍需明确的消去或近似设计。
5. **再做整体比较。** 先有标注规范、开发/留出划分、抽取质量和缺失率，再训练BN并比较真正MAS方法。不把本例用来宣布模型整体提升。

知识目录仍是RB003信息转交、RB008授权主张、RB009委派范围、RB026来源关系等机制的入口；本轮没有新增文献证据、因果发现或创新性结论。角色相关子图、自动DAG、全图风险类型、真实对照数据和MAS原方法复现仍保留在完整目标中。
