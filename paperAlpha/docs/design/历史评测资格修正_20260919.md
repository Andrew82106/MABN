# 历史评测资格修正（2026-09-19）

本审计只修正结论资格，不删除或重写任何历史预测、指标、训练结果。`paperAlpha/results/` 被 Git 忽略，因此在此保存可版本化的结论与核验依据。以下路径均相对于 `paperAlpha/`。

## 1. Temporal v1 没有通过在线预警资格

- 代码证据：`scripts/evaluate_temporal_monitor_v1.py` 调用 `evaluate_two_layer_v2.event_features(e)`，后者先遍历整个 `events` 构造 source/sink。`temporal_forward` 从完整 source 初始化状态，并用完整 sink 判断早期消息上的激活。
- 最小核验：事件 1 为 A→B 消息；事件 2 才是 A 收到不可信输入；事件 3 才是 B 调用付款工具。13 个参数均置零时，只给事件 1 得到 `first_sink_sequence=null`；给完整日志却报告 `first_sink_sequence=1`。即未来输入和未来工具调用改变了对时刻 1 的判断。
- 指标证据：脚本用最后一条消息的 sequence 减 `first_sink_sequence` 计算 lead；它既不对应独立违规时刻，也不对应最终风险头第一次报警时刻。
- 处理：`results/temporal_monitor_v1/metrics.json` 原值保留。F1=0.413081、AUROC=0.716524 仅是离线整轨迹评分；`early_warning.positive_alarm_rate=0.022333` 和 `mean_lead_events=0.222222` 不得称为预警召回率或领先真实危险的事件数。`REPORT.md` 已就近注明。
- 后续资格：必须逐事件隔离输入，用追加未来事件不改变既有前缀结果的测试；没有独立违规时间时，不能报告真实危险提前量。若用敏感工具派发时间作替代，应明确标注为代理指标。

## 2. Fusion 和 OOF 不是同划分配对比较

| 保存位置 | 外层划分 | 训练/测试数 | F1 / AUROC / AUPRC |
|---|---|---|---|
| `results/fusion_v3/metrics.json` | family 字符串尾部留出 | 2622 / 378 | 0.770 / 0.930 / 0.718 |
| `results/fusion_v4/metrics.json`（修正后 Fusion v3） | family 字符串尾部留出 | 2622 / 378 | 0.753 / 0.933 / 0.744 |
| `results/fusion_oof_v1/metrics.json` | 随机 GroupShuffleSplit，内部 3 折 GroupKFold | 2543 / 457 | 0.752 / 0.922 / 0.682 |

核验脚本：`evaluate_independent_fair_baselines_v1.group_split` 对 family 排序后取尾部；`evaluate_fusion_oof_v1.py` 使用随机 GroupShuffleSplit。不同测试集不能隔离 OOF 的影响，也不能用分数下降“证明原融合有轻微同样本乐观偏差”。OOF 避免二级融合头使用基础模型对自身训练数据的预测，是训练协议改进；收益仍需固定外层划分、输入信息、基础模型和阈值协议后配对测量。

此审计不授予 OOF 全部协议合格资格：例如各方法阈值是否同等验证、权限信息是否一致、是否有新数据外部验证，仍需单独核对。

## 3. 旧满分只是标签规则一致性

旧组合基准以 source-to-sink 路径规则生成标签，再让动态图方法识别同类路径。F1=1.000、与 flat logistic 的 F1 差值 0.392 等数值保留，但只能作为实现能否复现既定机制的检查，不是现实 MAS 安全优势。所谓 MAS-specific baseline 也只是 protocol-compatible proxy，不是对应论文原方法的复现。

真实优势仍需独立标签、合理的信息可见性、固定划分和预算，以及在同一协议下运行的真实 MAS 对照方法。增加知识或模板并不自动保证提高准确率。
