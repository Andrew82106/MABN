# 中间节点语义锚定：真实 MAS 前缀训练

## 结论先行

本轮最重要的发现不是更高的最终检测分数，而是：**只用最终结果训练一个有命名中间节点的图，不能保证中间节点学到的就是名字所表达的含义。**

新采集的真实 API 数据中，在正则系数同为 .001 时：

- 只用最终结果训练：验证集 18 个中间事件判对 **3/18**，Brier **.670091**。
- 同时用后来实际看到的中间回复训练：同一批中间事件判对 **18/18**，Brier **.001646**。
- 但验证集最终风险正例是 **0/12**。始终预测“没有出现”的规则误差为 0；不能把这批最终风险分数写成检测优势。

这是小规模受控开发诊断，两个任务模板分别承担训练和验证，非公共基准或独立论文测试。18 个中间事件来自 12 个工作流，也不能当作 18 条完全独立的系统样本。审核输入特征及结果模式在两模板中相同，语义诊断通过不等于复杂场景泛化。

## 1. 新实验实际做了什么

- 共 24 个开发流程：图书馆通知 12 个训练、博物馆通知 12 个验证。
- 每组覆盖：共用一个审核者/分别使用两个审核者 × 保留/删除/自行摘要 × 原始材料包含/不包含指定标记。
- 两名发布者在独立 API 上下文中生成对外通知。共用审核者时，两人接收同一条真实回复；分开审核时，各自只接收对应审核者的真实回复。
- 共 **84 次真实 API 请求**，全部完成，无重试、无失败样本替换。使用用户指定本地接口和 `gpt-5.5`、`low`；没有改变当前任务的模型或思考强度。
- 原始任务和标记均为自编虚构材料，不涉及真实个人信息，不发送通知或执行工具副作用。
- 工作流由采集器明确调度，不是自动发现。两个结构分别有 4/5 个功能节点，其中源材料节点是适配器，不是另一次模型调用。

每条流程保存两个输入截面：任何审核回复生成前，以及所有审核回复完成但发布者尚未调用前。后续消息单独保存为监督数据，不能进入较早输入。

**本轮模型在开发数据采集后拟合，属于输入时序正确的离线评测，不冒充已训练模型在采集现场的在线预警。** 两个新测试主题共 24 个预留流程尚未调用，旧留出集也未读取。

研究契约规定指定标记不获准向外发布；该契约提供给监测器，代理请求仅使用实际任务、角色指令及其上游消息。模型预测行为时不会把监测器的否决事实偷放进代理可见特征。这里的违规是该虚构契约下的字面出现，不等于已造成真实损失，也不覆盖语义改写泄漏。

API 返回只有完成的最终文本可以成为下一节点输入；截断/拒绝保留为采集失败，推理内容不落盘。返回处理参考 [Responses API 文档](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。

## 2. 本轮模型升级

仍使用上一轮的 `DAGWorkflowRiskBN`：25 个事件条件系数加 3 个未知授权先验，共 28 个参数。没有用另一套模型的成绩替代它。

新增 `observable_event_learning.py`：

1. 后来实际得到的中间和末端回复，单独附带原记录标识、时刻、正文和字面出现标签。
2. 标签校验要求其时刻晚于预测输入；重新核对标签与正文是否匹配。不允许把未知记录补成 0。
3. 对同一流程所有被监督的未来事件计算**一次联合似然**，未标注事件仍求和消去。不是把多个重叠前缀重复当成独立训练样本。
4. 全事件方案每条流程使用审核者和发布者的实际回复；终点对照只使用发布者结果。全部从零初始化，正则 .001/.03，各完成一次拟合。
5. 本轮只优化事件的 25 个系数，明确标注授权先验未拟合。实际条件设计为 42×25、秩为 **6**，所以也不能说 25 个参数含义都已被数据独立识别。

训练的父事件取值现在确实包含 0 和 1，修复了上一批“父均值永远 .5”的实验覆盖缺口。当前仅审核与发布概率族获得有用监督，其余族不是已验证能力。

新增 `observable_event_qualification.py`：单独评价中间事件的预测与真实含义是否一致，并报告最终标签是否包含正、负两类。类缺失时不虚构召回率；类都出现也不自动代表样本量充足。

## 3. 为什么最终预测对，不代表中间解释对

以审核事件 `X` 和发布事件 `Y` 为例，模型使用：

`P(Y=1 | X) = sigmoid(b + wX)`

当审核结果在输入中尚未观察时，换一套表示 `X'=1-X`，再令：

`b'=b+w，w'=-w`

并将审核节点相应条件系数取反，便可以保持相同的最终联合预测。原来代表“出现”的中间状态，现在可能在计算中实际代表“不出现”。

本轮对四个已拟合 BN 都做了这项参数副本变换；原始参数文件不动。24 个早期前缀上的最终分布最大差只有 **2.22e-16**，审核概率互为补数。终点的未正则化训练似然完全一致。

但若后来把实际审核回复作为观测输入，两个版本的预测会分歧。终点监督模型 .001 的最大晚期分布变化为 **.35444**。这是运行时必须处理的问题，不只是图画得是否好看。

完整轨迹监督会区分这两套表示。例如全事件 .001 模型的未正则化完整轨迹损失由原参数 **.321870** 变为翻转后的 **6.774755**。

L2 正则在两套表示上可能不同，它可以偏好某种方向，但并不因此证明其语义正确。此变换仅针对本次单层审核到发布结构，非任意网络的统一变换或首创因果发现。

**设计原则因此进一步明确：不仅要给节点起一个可读的名字，还要给关键节点配可核对的观测定义和语义监督；只有末端分数，不能支持整图解释可信的主张。**

## 4. 所有结果与对照边界

完成 4 次 BN 拟合、4 次直接四分类拟合（早/晚前缀各两种正则），另完成 2 次局部 Logistic 拟合等价检查。保存 6 个模型文件、12 种评分配置、576 条前缀预测，不选择新默认模型。

| 方案 | 验证早期风险 Brier | 验证晚期风险 Brier | 验证中间事件 Brier |
|---|---:|---:|---:|
| 全事件 BN，.001 | .015445 | .016589 | .001646 |
| 终点监督 BN，.001 | .013742 | .089026 | .670091 |
| 全事件 BN，.03 | .041126 | .040858 | .079056 |
| 终点监督 BN，.03 | .033702 | .051511 | .306002 |
| 直接联合分类器，.001 | .046997 | .054751 | 不预测中间事件 |
| 直接联合分类器，.03 | .038926 | .028896 | 不预测中间事件 |
| 依审核指令保持/删除规则 | .333333 | .333333 | — |
| 始终不出现规则 | **0** | **0** | — |

最终训练有 1 个危险流程，验证没有危险流程。四个 BN 在 .5 阈值下也都没有检出训练中的那个正例，不能据此宣布安全检测成功。

保留同一组拟合边际、只去掉联合依赖的对照也全部报告。全事件 .001 的早期风险 Brier 由 .015445 变为 .015489，差很小；不能把这一差值当作可靠关系建模优势。晚期父事件均已可见，两者一致。

用同样中间标签训练的局部 Logistic 与 BN 条件模型等价，最大联合预测差约 **8.59e-8 / 7.76e-9**。这进一步说明，不能仅以“使用 BN”作为创新证明。全事件 BN 有额外中间监督，也不能与只见终点标签的分类器混称完全同监督对比。

原生 MAS 当前动作守卫已在上一轮采购任务对照。本轮没有把它们的即时允许/拒绝答案强行改成未来概率，也没有新的原生 MAS 领先结论。
