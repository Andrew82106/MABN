# 作用域数值 BN v6：局部限额与系统累计

## 结论与版本

`ScopedBudgetTextBN-v6` 在326参数文本模型上增加14个数值参数，共340项。它解决了v5只识别“有金额说法”、不能区分具体数额的部分缺口，但只覆盖经过审核的公开工具字段，不处理任意文本中的金额或条件。未训练，没有新准确率。

v6把数值条件加入原动作授权风险因子，这会混合“授权”和“额度一致性”的解释。后续[v7知识子图](知识子图BN_v7_授权与额度分离_20260919.md)因此显式分离机制；两个版本及原结果均保留，不能混用性能或语义。

## 输入、比较与概率

- 当前只注册HarnessAudit的`authorize_payment`。字段说明来自固定上游提交的公开工具schema，并与保存的实际API请求核对。
- `amount`和`amount_usd`须相互一致；不同币种不换算。只解析非负整数或普通十进制字符串，不猜测带符号、单位、千分位或科学计数法的含义。
- `amount_limit`是调用参数中自报的单次上限，不是可信批准，也不自动成为全局限额。
- 全局合约必须在运行前外部提供，明确任务标识、币种、上限与累计含义；不从隐藏评测策略取值。配置中的来源字符串不是身份认证。
- 只按已观察到的工具派发累计非负请求额，不声称是实际支出。相同调用ID去重；不同任务不混算。缺失或矛盾的贡献保留为缺口，不能由已知小计低于上限推出总额未超限。

使用Decimal精确比较，数值差特征为`(amount-limit)/(1+amount+limit)`。动作因子为：

`sigmoid(能力×角色×可信检查表项 + 14个数值特征的加权和)`。

数值比较只改变动作假设，不改变可沿消息传播的过程状态。默认14项权重全为0，默认分数不会因金额特征改变。

## 证据

优先结果：`results/scoped_budget_bn_verified_20260919/`。较早的`scoped_budget_bn_mechanism_20260919/`保留；优先版本明确每个产物对应的参数探测编号，避免将扰动参数预测与默认参数解释混用。

- 真实同一任务47条观测、1次有数值注册的付款请求：349，对比自报上限400。没有全局合约，不能验证真实累计风险或批准。
- 默认数值屏蔽差为0；预先固定的8组非默认参数下，最大差约0.04496。只证明实现能使用金额，不证明正确性或性能。
- 关闭数值路径与v5差为0；增量/批量差为0；340参数终态分数导数有限差分最大误差约3.20e-11。
