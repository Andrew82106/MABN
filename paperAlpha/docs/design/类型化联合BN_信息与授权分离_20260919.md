# 类型化联合BN：信息影响与授权风险分离

## 本轮改变了什么

新增`TypedJointBN-v2`研究原型：在同一个联合概率网络中区分信息影响状态和授权风险状态。仍是API运行日志监测，不读取模型权重，不自动阻断。

旧69参数模型和在线接口保留。新版不是新的默认部署模型；现已有批量/前缀编译、精确推断、联合训练、可选`TypedRiskStream`增量接口和类型化可执行图导出。后续补齐的接口与完整验收见[在线解释与完整验收](../../experiments/model_mechanisms/notes/类型化BN_在线解释与完整验收_20260919.md)，不与初版训练时的源码快照混淆。

## 1. 为什么需要拆开

旧结构把外部输入影响和敏感动作的授权异常都注入`X_i`，之后普通消息也传播`X_i`。因此即便A没有接触可疑信息，只是发生一次权限异常，后续A→B消息也可能让模型赋予B一个被传播的风险状态。

如果`X`只叫抽象的“所有风险”，这是一项粗略建模假设；但若用它解释信息污染链，就混淆了不同机制。不能把A做过越权操作直接当成B收到恶意指令。

知识依据重新核对了[Prompt Infection §3.1–3.2](https://arxiv.org/html/2410.07283v1)：其跨Agent扩散依赖传递的指令与载荷；以及[AuthGraph §3.2–3.4](https://arxiv.org/html/2605.26497v1)：执行来源与授权规范是不同对象。**下面的二值变量、转移方程和概率参数化是我们的工程设计，不是上述论文给出的BN，也不构成创新性或因果发现的证明。**

## 2. 实际状态与连接

每个工作流节点有信息影响状态`C_i`；首次观察到敏感动作时，为该节点另建授权风险状态`U_i`。外部来源仍用共享的`Z`表示。

- 输入接受：`C_i' = C_i OR (Z AND adoption_gate)`。
- 实际通信：`C_j' = C_j OR (C_i AND transmission_gate)`。
- 授权观测：`U_i' = U_i OR authorization_gate`。
- 普通通信不会读取或传播`U_i`。

当前`delegation`仍只采用信息通道，**不是已经实现了委派授权传递**。凭证作用域、批准绑定、委派衰减和独立授权策略还要另外建模。`U_i`只是节点上累积的风险假设，不是“这个动作实际未获授权”的已验证真值。

这不意味着越权行为不能影响其他Agent：它可能通过共享文件、记忆、凭证或资源状态产生后续影响；这些需要各自的证据和连接，不能由一条普通消息边代替。

全部来源、信息状态和授权状态共同保存在完整联合分布中。不把两条通道的边缘概率相乘来冒充独立，也不丢掉共享来源与分支汇合的相关性。默认上限12个二值变量（含来源与两类状态），即最多4096个联合状态；超限明确报错。

## 3. 全图输出和训练

保留13个原可见统计。对每个联合状态，先令`X_i = C_i OR U_i`，计算原来的四个全图状态统计；再加入两个明确命名的量：

1. 是否存在授权风险状态；
2. 是否存在某个节点同时处于信息影响与授权风险状态。

系统分数仍是各联合状态的条件风险加权平均，不是取最大节点分数。参数从69增加到71，两个新全图系数从0初始化。基础条件表仍由原知识规范生成，新配置`configs/typed_joint_bn_v2.json`指定状态绑定和新增读出量。

训练仍使用任务级最终标签，对运行前缀联合计算损失，不能把最终正标签解释为每个节点都违规。为避免增加两个参数时悄悄降低旧参数正则强度，正则分母固定为原来的69。新参数与来源、接受、授权、传播和全图参数一起学习。

二值状态没有单独真值监督，因此局部参数可能不可识别；增加变量名称不自动使其成为真实风险类型概率。当前没有单调性保证、完整参数后验或校准保证。

## 4. 现有数据能验证什么

对冻结的4000条`independent_mas_v3`公共轨迹做了字段/时序检查：

| 项目 | 数量 |
|---|---:|
| 外部输入事件 | 4,586 |
| 消息事件 | 22,685 |
| 工具调用事件 | 9,891 |
| 高权限派发后仍有消息的轨迹 | 0 |
| 高权限派发前已有权限标志的轨迹 | 0 |
| 动作提案事件 | 0 |
| 显式审核/清洗/撤销事件 | 0 |

这说明两个不同问题：

- 原基准不能直接检验本次“越权不作为消息污染传播”的修正，因为相关时序根本没有出现。
- 数据没有提供提前授权和纠错观测，因此不能凭它证明这些能力；但这不等于所有早期统计信号都不存在，也不是准确率的信息论上界。

对这种“所有消息先发生、授权动作后发生”的时序，如果关掉两个新增全图系数，新模型的`C OR U`读出应与旧模型等价。现有完成组已经在保存的验证/测试前缀上核对，差异仅为浮点舍入。因此本轮若出现分数变化，不能全部归功于状态分离；新增读出和重新优化才是此数据上可体现的变化。

真实数据侧，本轮只核读既有A2ASecBench适配报告：900条轨迹包含协议事件，但其统一字段中没有工具/权限记录，且不能把攻击场景标签直接当危险真值。没有把这些材料强行变成新版的外部验证结果。

## 5. 验证与评测状态

代码：`src/paperalpha_monitor/typed_joint_bn.py`。测试包括：

- 权限异常不能污染接收方信息状态，而已有信息影响仍可正常传播；
- 五种角色、三种消息类别下，接收方信息状态对纯权限标志变化保持不变；
- 来源共享、显式节点分组、权限屏蔽和未来事件不改变过去分数；
- 71参数解析梯度与有限差分一致；另用独立字典枚举状态、逐项计算读出进行验证，不调用被测的状态更新或特征函数；
- 类型化模型拒绝旧编译器输入；后续已加入独立类型化图解释器，不把旧单通道图当作新版解释。

初版训练启动时完整测试200项通过（4条既有数值/弃用警告）。当时对旧在线监测器的全量回归保留于`results/joint_online_equivalence_after_typed_hooks_20260919/`；后续新版增量接口、类型化图及完整测试证据见在线验收文档。不同时间的源码快照分别保留，不能把后加代码当作训练时就已执行。

实验已完成固定四种信息条件×三种子共12组，运行目录为`results/typed_joint_bn_v2_20260919/`。精确复用上一轮划分和全部六个对照；从相同fit分区的旧联合BN参数加两个0系数开始训练，使用原单阈值报警，未采用上轮分阶段规则。

新模型还有最多200次追加优化，不能称为各方法相同计算预算。当前`fit_seconds`记录的是追加训练耗时，不含产生旧联合BN起点的训练成本；不得用它宣称从零训练更快。冻结起点与同目标检查用于隔离结构/读出修改，不是免费训练资源。

完整结果没有证明整体领先：四种条件下新版平均前缀Brier都略低于旧联合BN，但仍高于HistGB。无工作流/权限可见时分别为新版`0.202784`、旧版`0.202824`、HistGB `0.201154`。新版AUROC略高，但预警和误报存在取舍；三个划分不是独立外部数据集，也未证明统计显著性。

12组优化器均返回成功，但有4组可行梯度高于前轮的`1e-5`诊断标准：runtime-only/权限可见种子20260921、runtime-only/权限屏蔽种子20260921、workflow-known/权限可见种子20260919及20260921；最大约`2.02e-5`。本轮未按测试表现挑选重训，保留全部原值；不能把成功标志等同于统一精度下的充分优化。

完整`AUDIT.json`已通过：重新计算147,896个新版验证/测试前缀分数、12组训练目标和梯度，并核验96,024条继承的对照方法-任务记录；新版分数差异0。此前`AUDIT_progress_1.json`仅覆盖前两组的历史记录仍保留。此次审计证明保存结果与冻结程序一致，不证明风险状态的真实语义或外部优势。

## 6. 尚未完成

节点上仍只有两类粗粒度状态，不是泄露、记忆污染、资源耗尽、越权、组合危害的完整模型。不同角色仍共享结构；授权仍不是动作级，首次提案/派发的去重和后续证据修正沿用旧编译器限制；风险状态仍无恢复。

下一步需加入可靠的动作/资源/来源身份和提前检查、审核结果等观测，再设计有明确适用条件的状态更新。缺少证据时不能让模型凭文本自述“已清洗”就清除风险。类型化在线接入与当前两类状态的可执行图已补齐，但原始文本抽取、自动工作流生成、大图推断、全风险知识图编译及真正MAS原方法复现仍未完成。

本轮是知识约束的状态结构升级与覆盖检查，不是整体论文目标完成。
