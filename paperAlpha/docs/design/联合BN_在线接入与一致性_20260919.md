# 联合BN：在线接入与一致性

## 已实现的接口

`JointRiskStream` 是按任务创建的、进程内的被动监测器。它逐条接收结构化API Agent运行事件，返回当前风险概率、可选报警标记、第一次报警序号，并可展示当前节点/来源概率和全图概率分解。它不调用被监测模型、不执行工具、不阻断动作。

```python
from paperalpha_monitor import JointRiskStream

# model 是已加载的 DynamicJointBN；阈值由独立验证步骤确定。
monitor = JointRiskStream(
    model,
    workflow=declared_workflow,  # 不知道时传 None，不能从未来日志倒推
    permission_mode="observed",
    threshold=validated_threshold,
)

for event in incoming_runtime_events:
    estimate = monitor.push(event)
    # estimate: risk_probability、alarm、first_alarm_sequence、sequence
    # monitor.explain(): 当前状态及模型内的概率分解，不是因果真相
```

每个任务创建一个新实例，不在不同任务之间复用风险状态。模型参数、角色和能力资料在创建时复制，之后修改原模型或原字典不会改变正在监测的任务。

## 实际计算方式

- `JointEventCompiler.push` 只处理新到事件并生成这一时刻的概率转移。
- `JointRiskStream` 保留当前联合状态分布；新来源或节点出现时增加变量，原有概率质量保持原位置，新变量初态为0。
- 只执行新事件对应的转移，不重新运行旧消息，不扫描未来事件，也不调用批量模型的 `_forward`。
- 批量 `compile_trace` 已改为使用同一个事件编译器，避免在线和训练各维护一套事件语义；训练仍可对全部前缀反向求导。
- 概率过滤是增量的，但现有事件校验器还维护去重、动作和路径证据，部分记录会随任务长度增长。不能声称无限流上的常量内存或常量总时延。

同一个事件ID的原样重试不重复注入风险，也不增加已接受事件数。匹配的工具提议和派发仍是同一个动作。新事件超出精确状态容量或字段无效时拒绝更新，保留上一个有效状态；拒绝不表示新事件安全。

## JSON日志入口

`scripts/monitor_joint_events.py` 从标准输入逐行读取事件JSON，从标准输出逐行给出结果。可直接放在日志管道之后；不需要让API供应商提供内部激活或权重。

```powershell
# events.jsonl 每行是一条结构化运行事件，不是一整条任务轨迹对象。
Get-Content events.jsonl | python -B paperAlpha/scripts/monitor_joint_events.py `
  --model-parameters paperAlpha/results/dynamic_joint_bn_v1_20260919/runtime_only__observed/20260919/model_parameters.json `
  --explain
```

不指定 `--threshold` 时只输出概率，`alarm=null`，不是“确认不报警”。需要报警时，由调用方提供另行验证的阈值。不要将另一种信息条件或另一种部署分布的阈值当成安全保证。

需要已知工作流、角色或能力清单时，用 `--context` 指向JSON，支持键 `workflow`、`roles`、`allowed_tools`、`permission_mode`。默认是无工作流、权限可见。

坏JSON或被拒绝事件输出 `status=rejected`、`risk_probability=null`、`alarm=null`；后续合法事件继续从最近有效状态处理。只要有拒绝，进程最终返回非零退出码，调用方必须保留这类观测缺口。模型初始配置错误则不启动监测。

加载使用具名参数JSON，不加载外部pickle，不训练模型。当前示例模型仍来自合成开发数据，接口可运行不代表具备现实部署资格。

## 与冻结版本的核对

证据目录：`results/joint_online_equivalence_20260919/`。

`scripts/verify_joint_online_equivalence.py` 使用训练运行开始前保存的旧批量源码作为参考，与当前增量实现分别计算：

- 原有4000条公开轨迹，每条都使用；不读取标签，不挑选成功例子。
- 4种可见性条件，共16,000个“轨迹×条件”实例，不是16,000条独立轨迹。
- 共148,648个前缀，风险分数最大差异 `1.11e-16`。
- 每个前缀的联合状态分布最大差异为0；未出现节点对应的额外状态质量为0。
- 使用同一个已拟合参数向量跨条件，只为检验实现等价，不构成新的性能评测。

保存了当前源码快照、旧参考源码/模型哈希和逐条件统计。新在线代码不在先前性能实验的源码快照里；上述一致性结果把两个版本的联系单独证明，不能冒称之前训练的是后来修改的代码。

## 测试和剩余差距

当前新方法测试集146项通过。新增覆盖增量/批量数值与边缘概率一致、角色与能力上下文、共享来源汇合、无批量重放、未来节点不可见、模型/上下文冻结、错误更新原子性、重复事件、JSON入口和报警语义。

仍未完成：原始消息文本的语义解析、真实API Agent框架中的运行挂钩、部署时延基准、多租户/任务并发服务、规范工作流自动提取、完整知识模板生成、风险类型拆分、风险恢复、大图推断和独立现实评测。当前是可接入的监测组件及日志适配器，不是已部署的完整防护系统。
