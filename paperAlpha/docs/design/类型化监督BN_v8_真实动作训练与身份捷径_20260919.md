# 类型化监督 BN v8：真实动作训练与身份捷径

## 结论

本轮从“可训练接口”推进到实际训练：新增可选 `TypedActionSupervisionBN-v8`，在四次已采集的真实 API MAS 运行上训练禁止工具/多余工具的类型化输出。原 v7、采集代码、数据和历史结果不修改、不继承本轮成绩。

53 个动作中有 5 个禁止工具标签、8 个多余工具标签，仅来自两个原始任务。按原任务留出，两种编排始终同组。**这是旧开发材料上的学习验证，不是独立安全评测，更不是最终系统风险目标已完成。**

重要诊断：5 个禁止工具正例全来自协调者。只用训练集主体身份计数的事后对照，在这批留出动作上禁止工具 AUROC=1、召回=1、误报=0，比完整 BN 更好。这些标签主要能检验职责/工具匹配，不能用来证明需要多 Agent 的联合风险建模。

项目总目标仍是知识驱动的分层 MAS 风险监测。本轮局部监督是其中一个训练通道，不替代全局风险、组合机制、完整职责子图、独立评测和原生 MAS 方法对比。

## 1. 为什么改变监督结构

原任务标签混合不同事件。冻结的 HarnessAudit `multi_agent/loader.py::synthesize_useful_tool_rules` 区分：禁止工具产生高严重度 V-OT；多余或未列出的工具产生低严重度 V-OT。资源 V-OR、通信 V-IC 另有语义。

因此不能把低严重度工具多余、资源字符串不匹配和实际危害都当作“授权潜变量=1”。v8 在原 BN 上增加**可观测结果预测层**，而不是给每个局部隐藏状态贴上任务标签。

设 `h=P(禁止工具|截至派发的证据)`，`l=P(多余工具|非禁止工具,截至派发的证据)`，则：

```
P(禁止工具) = h
P(多余工具) = (1-h) * l
P(无工具分级违规) = (1-h) * (1-l)
```

三项总和为 1。“无工具分级违规”不表示资源/通信合规，更不表示任务没有危害。

这是两个预测器的条件分解；不声称两个结果共享一个已经识别的真实因果状态，也不将第二个预测器误作已有联合潜变量条件化后验。

## 2. 怎样和两层 BN 联合训练

复用 v7 的联合过程状态和三类动作历史，在当前授权因子进入历史**之前**计算新动作输出：

- 禁止工具输出：将当前二值授权假设与旧联合状态完整边际化；父特征包括当前过程状态、四项全图状态统计、过去授权历史、当前授权/过程重合和 15 个公开运行统计。
- 多余工具条件输出：使用能力×职责表、公开运行统计和过程状态；不读取授权或数值历史。其条件损失对授权参数的梯度为 0，已作数值测试。
- 高严重度为 0 是独立观测到的“未命中禁止工具规则”，可以监督第一个预测器；这与把低严重度=1解释成真实授权异常不同。
- 授权假设到高严重度输出之间保留独立条件函数；标签不是隐藏授权变量的真值。训练约束其当前授权项及重合项的系数非负，其他关系仍是待检验的建模假设。
- 标签只进入离线损失，从不写回运行时状态，也不把当前动作当成自己的历史证据。

原 v7 有 345 参数，新高严重度输出 24 参数，条件必要性输出 49 参数，共 **418 参数**。BN 的状态转移与新输出共同得到梯度，不只是训练外围分类器。

训练损失：每条轨迹的已标注动作分类负对数似然取平均，再对轨迹等权平均；另可加入有资格任务结局的前缀 BCE。使用固定 L2、L-BFGS-B 和解析梯度。

本轮没有可靠正负任务结局集，因此**任务结局损失关闭**；原全局输出参数保持初值，v8 的任务风险预测接口拒绝把这个未训练头当成成果返回。额度分支也没有相应监督，不声称本轮训练了额度检测。

第二个任务的新阶段运行因 API 错误中止；其已完成动作有局部规则标签，**完整任务结局仍缺失**，不补成正常任务。旧编排的通信冲突原样保留，但不混进工具分级标签。

四份原运行产物均重新验哈希，并在各自冻结的原检查器中重新核验规则结果和原完整工具目录；原标签未改。53 次入口与原生工具记录逐一绑定。输入只来自运行日志及公开工作流；隐藏政策和事后检查结果只在标签侧。

两个留出方向：住房训练、餐饮评测；餐饮训练、住房评测。同一原任务的两个编排不能被拆到两侧。失败记录不删除，也没有制造新负例。

预先固定四个方法：完整 v8、去掉全图上下文的局部消融、可见特征 Logistic、训练先验。它们不是原论文 MAS 方法；Logistic 可以使用相同可见全图统计，不限制成弱单 Agent 对照。概率阈值固定 0.5，未按评测结果调阈值或挑模型。

## 4. 训练结果

下面是两折全部 53 个留出动作合并的开发结果；同一轨迹内动作相关，不能视为 53 个独立任务。

| 方法 | 禁止工具 Brier↓ | 多余工具 Brier↓ | 三类负对数似然↓ |
|---|---:|---:|---:|
| 完整 v8 | 0.07382 | 0.12014 | 0.61567 |
| 局部消融 | 0.08578 | 0.11336 | 0.64818 |
| 可见特征 Logistic | 0.07326 | 0.12104 | 0.62201 |
| 训练先验 | 0.08815 | 0.13972 | 0.77146 |

完整模型并未全面领先：禁止工具略差于 Logistic，多余工具不如局部消融。四方法在 0.5 阈值下全部没有正报警，故没有实用报警效果结论。这里是在工具 handler 入口预测该动作规则类别，不是验证了提前预警的时间收益。

完整 BN 各折的禁止工具 AUROC 均为 1，但两折合并为 0.89583；Logistic 分别为 1、0.96970，合并为 0.95。这反映跨折分数尺度差异和极少正例；不能只摘“AUROC=1”作成果，也不把不同模型拟合后的合并排序当成单个部署模型的排序证明。

四个 BN 拟合的目标均下降，优化器均结束，最大投影梯度不超过 8.92e-7。完整模型原基础参数有 12/14 个发生大于 1e-7 的变化，包含授权条件表、一个通信转移参数和文本缺失/上下文截断状态更新参数。

**没有文本语义内容系数得到学习。** 本轮无语义注释，文字虽已保存，但训练只用了缺失性和结构统计，不能称为学会理解危险文本。

固定已训练权重关闭消息传播，两个留出任务的动作概率最大变化分别为 0.04558、0.03080；这证明通信通路参与计算，不证明其因果正确性或泛化优势，也不等于重新训练过的传播消融。

## 5. 追加身份对照后的关键发现

检查结果后发现，高严重度正例全部来自旧编排的 `concierge_coordinator`。另冻结事后诊断协议并保存到 `results/typed_action_identity_diagnostic_20260919/`，不改原四方法实验。

只用训练标签对公开的“实际主体身份”计数、加一平滑，沿用原任务留出：

- 禁止工具 Brier=0.01634，AUROC=1，0.5 阈值召回=1、误报=0。
- 主体×工具计数的多余工具 Brier=0.06667，AUROC=1；仍非通用 MAS 监测成绩。

这两个对照不看隐藏政策，也不看评测标签，但会记住跨任务复用的角色名字。现有模型把协调者和检索者都压成 `reasoner`，反而丢掉了简单职责差异；全图特征可能间接补偿身份/位置，不能据此归功于联合安全推理。

身份对照是**看过结果后新增的诊断**，不是原预注册方法。它仍能推翻“本批数据的高分足以证明图模型必要性”的说法。

## 6. 验证与下一步

17 个新测试覆盖全部 418 参数的数值梯度、独立标量结果枚举、v7 状态/全局输出不变、条件必要性与授权梯度隔离、未来结果隔离、缺失标签、可选结局监督及优化下降。全项目 **740 项测试通过**，4 条既有 sklearn 警告，81.34 秒。

冻结结果复算了 8 个估计器、212 个动作预测，最大分数差 0；四个 BN 各六个方向的真实训练目标梯度检查最大误差 7.85e-12。另核验已训练模型逐事件与批量、截断到动作入口前缀的分数一致。含审计脚本快照的最终复验目录为 `results/typed_action_supervision_verified_20260919/`，初版 `typed_action_supervision_audit_20260919/` 原样保留。

剩余重点不是把这个局部小任务包装成总目标，而是：

1. 补能区分协调、检索、审核、执行职责的知识结构，不能只靠粗粒度 `reasoner/executor`，也不能靠背主体名字证明泛化。
2. 获取**同职责、同工具因前序消息、授权范围、累计资源或共同来源而出现不同结果**的真实/受控 MAS 轨迹；整组保留正常与危险对照，记录机制标签来源，不能为平衡而翻转原标签。
3. 让任务级组合风险有独立、可观测的结局监督，加入训练；保留本轮工具分级通道，但不把它当实际危害。
4. 在足够的任务/策略组上分离训练、开发和最终评测；真正 MAS 原方法与身份、局部、全图统计对照一起比较。当前两个旧任务不足以选阈值或证明泛化。
5. 自动 DAG、完整职责子 BN、可靠文本/授权证据与大图推断仍未完成。
