## 1. SentinelAgent：框架非常接近，但本体代码入口未确认

核读 [作者论文 v1，§IV—V](https://arxiv.org/html/2505.24201v1)：静态图来自 Agent 角色、工具及访问约束，运行图来自实际通信和调用；Phoenix 采集事件，Granite Guardian / LlamaFirewall 做局部语义检查，再结合攻击路径库与人工审核。**这里的边检查不是只数“多了一条边”。**

- 输入：任务、角色/工具配置、消息与调用内容、顺序，以及可取得的权限、记忆和历史信息。无需被监测模型的权重/激活；框架配置与运行观测仍需真实提供，不能从标签反推。
- 标签/知识：规则、攻击路径库和人工审核参与设定。论文未提供本次可直接定位的完整训练集、提示词/阈值配置和统一离线 `predict(trace)` 入口。
- 可用性边界：核查论文代码链接、作者题名/姓名限定的 GitHub 搜索，未确认本体仓库；**这是“未找到”，不是证明作者没有发布**。论文引用的 Phoenix、CrewAI 示例等是组件，不是 SentinelAgent 完整源码。同名其他项目不算本论文实现。

推荐实施单元是“规范与工具配置＋逐时刻可见图＋节点/边语义判定＋路径匹配”的检测适配版；若更换审查模型、路径库或人工流程，逐项记录为偏离原文。不得把本项目已有图特征分类器改名为 SentinelAgent。

## 2. BPD：已找到真正算法源码，但目标不是通用工具风险

官方归属由 [论文 v2](https://arxiv.org/html/2510.19420v2) 直接链接 [ChengcanWu/BPD](https://github.com/ChengcanWu/BPD) 确认。本次通过 GitHub API 核验 `main` 提交为 `9e1619fedf6744a23264b4d27a2a4ab0aab7e53f`；后续复现应固定该提交或另记更新，而非浮动使用 `main`。

### 需要什么观测与标签

- **检测时**：每轮实际回答、通信对应关系、边的赞同/反对评分、最终答案；不需要被监测模型内部信息。原代码检测依据是最终多数意见，不读取标准答案来判断某个 Agent 正误。
- **造攻击/验收时**：标准选择题答案用于构造错误答案攻击，攻击者 ID 用于设置攻击和核验定位；这些应留在独立评测侧，不能喂给监测器。原版不是用我们的任务风险标签训练一个分类器。
- **输出**：可疑 Agent、贡献分数与分差，不是校准的系统危险概率。`deviation` 在未达到阈值时为 0，不宜直接拿它宣称完整风险排序；另取未截断分差属于明确记录的分数适配。

### 为什么当前合成日志不能直接冒充原版输入

本项目 `independent_mas_v3/traces_public.jsonl` 面向消息、权限和工具行为，没有原方法所需的逐轮答题观点与 A—D 最终选择。把“不可信”当“反对”、把危险标签当最终答案、或补造带标签暗示的文本，都会改变算法含义，甚至泄漏答案。

原方法也依赖最终结果才能初始化反传。若改成每个前缀临时投票，必须命名 `BPD-prefix adaptation` 并单独说明，不能把事后定位时间当提前预警。

## 3. 推荐的最小实施顺序

1. **原核心一致性单元**：固定 BPD 提交，缓存实际回答对的边评分；构造其原生三轮 `EdgeGraph`，调用原 `run_bpd`，关闭修复。测试本项目包装器与原函数在同输入下完全一致；缓存只消除重复调用，不改变评分。
2. **匹配任务的小规模对照**：收集带通信记录的正常/受污染多 Agent 答题轨迹，独立保存攻击者和答案标签；比较定位、误报与成本。这验证 BPD 接入，不代表已经覆盖付款、隐私等风险。缺真实文本时停在“数据不适用”，不要生成标签提示文本补齐。
3. **通用风险迁移另列表**：若把末轮多数意见改成安全审查结果、把分差转概率，明确命名 `BPD-derived risk adapter`，在同观测、同划分下另评。SentinelAgent 自行实现也遵守相同命名纪律。

判定复现完成的证据应包括固定源码版本、真实运行命令/环境、输入映射、原始输出、API 模型与提示词记录、偏离项和独立验收结果；本轮只完成了入口与适用性核验。
