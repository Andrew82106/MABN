# 统一运行时序：通信、工具接入与边界

## 本轮位置

在“API可见事件 → BN观测”这一层增加共享运行日志。工具入口、框架工具结果、处理函数返回/异常、Agent通信使用同一个进程内序号；不再从两个旧文件的时间戳猜总顺序。旧数据和旧运行源码不改写。

代码：

- `src/paperalpha_runtime/journal.py`：不依赖研究环境或SDK的记录器及观测投影。
- `scripts/collect_harnessaudit_api_pilot.py`：工具包装器与原始ActionSink共享记录器；旧两种日志保留并添加对应序号。
- `scripts/replay_runtime_journal.py`：逐条投影到压缩版BN，冻结输入、参数与源码。
- `scripts/audit_harnessaudit_api_pilot.py`：交叉核对统一记录与旧生命周期/通信记录的绑定、参数、结果及内容。

按[OpenAI Docs的生命周期说明](https://developers.openai.com/cookbook/examples/agents_sdk/migrate-from-claude-agent-sdk/readme#what-you-migrate)区分记录和执行控制。本轮沿用此前已经验证的原工具处理函数包装边界，只加本地观测，不加审批或阻断。新记录字段来自本地代码核验，不把官方文档当作本地兼容网关或HarnessAudit时序的证明。没有更改本对话模型/思考强度。

## 实际序列与模型输入

记录器在短锁内分配序号并写入，通信和工具阶段共用它。即使时钟相同或回拨，也不需要排序。**这只是同一进程的实际观测顺序，不是分布式因果顺序。**

开始记录只声明参与Agent和外部端点；不把基准授权规则或useful_tools清单当成许可。每个实际工具入口使用新的invocation ID，并保留SDK call ID。同一个provider ID被重复使用，也不能把两次调用合并。

投影规则：

| 记录 | 模型如何使用 |
|---|---|
| 内部Agent通信 | 消息事件，保留原文，信息类别unknown |
| 发给用户等已声明外部端点 | 对外消息观测，不把用户加入Agent图 |
| 工具处理函数入口 | 一次派发事件，保留真实身份/参数，principal和resource仍为null |
| 框架内部工具结果记录 | 仅作绑定核对，不能重复生成第二次动作 |
| 处理函数返回/异常 | 保留结果/异常观测，不充当提前证据或权限检查 |
| 任务结束状态 | 单独报告完整/失败/缺失，不输入风险模型 |

投影严格按连续记录顺序读取。缺行、乱序、未声明身份、调用绑定不一致会报错，不静默重排或修补。旧arrival/lifecycle文件没有这种共同序号，不能事后升级为已验证的统一日志。

无法解析为对象的工具参数不会被补成空对象；会记录“未建模入口”的覆盖缺口。截断日志保留未结束调用与未知运行状态，不生成安全标签。

## 没有解决的语义问题

本轮保留通信和返回文本，但**未实现文本语义抽取**。消息统一为unknown，返回内容没有被擅自当成独立危险来源，也没有凭工具名或自述产生可信授权。

因此，当输入没有已建模的来源风险时，信息通道仍可能保持0；不能把“日志完整进入模型”解释成“模型已理解全部信息污染链”。后续必须设计可验证的来源/采纳/参数语义提取，并处理新增来源变量的容量问题。

回放脚本逐条更新，但它是离线回放，不是在工具执行前运行的在线评分服务，没有测量实时预警延迟，也没有提供自动阻断。提供参数文件时检查v4参数顺序和规格；不因成功加载就宣布参数训练或校准已验证。

## 验证证据

新增19项测试；完整项目 **415项通过**，保留4条既有sklearn警告。覆盖：

- 并发相同工具/参数的不同身份绑定，处理函数原返回值保持不变；
- 100次多线程写入、相同时钟下的连续唯一序号；
- 工具入口在原处理函数前、结果只在后续阶段可见；
- 内外部通信区分、重复计数排除、参数不完整显式报告；
- 乱序/缺行/错误身份/原生参数不一致拒绝；
- 改变未来返回和结束状态不改变先前风险分数；
- 统一日志与原始两类日志的序号、内容和结果交叉核验。

另用真实 `openai-agents 0.22.3` 的FunctionTool和ToolContext、HarnessAudit原始工具处理函数、ActionSink及SQLite模拟业务库做了集成检查：

- `results/runtime_journal_components_20260919/`：2次实际组件工具调用、4条手工消息，共12条统一记录。开始/结束、原生结果与包装器记录均能按调用身份匹配。
- `results/runtime_journal_component_replay_20260919/`：投影为8条模型事件，全部依序回放；用户没有被加入Agent节点，缺失授权范围保持未知。
- 对该产物实际运行了共享日志交叉核验，所有原日志链接一致，无未结束调用。

**这些调用参数和消息是手工安排的，模型API调用数为0。** 原始工具处理确实执行了，但这不是大模型生成的MAS任务，不是完整任务成功率、检测准确率或预警结果。回放参数是未训练初值。

首次组件启动因上游默认文件编码在Windows下使用GBK而失败，失败发生在输出目录创建前；随后显式使用`-X utf8`，不修改上游文件，组件验证通过。新API采集同样应显式使用UTF-8。
