# 可观测事件 DAG-BN：可变工作流与缺失历史

## 结论和主线位置

新组件 `ObservableDAGWorkflowRiskBN-v1` 将固定的两个执行者/单个发布者结构，扩展为**显式无环工作流中的可观测事件网络**，并接入现有授权、额度及组合政策图。不是在旧模型旁边画一张无法计算的解释图。

- **结构实现**：节点数、分支数和链长可变；角色概率模板共享参数，未来中间事件先求联合分布再组合风险。没有固定 U_A/U_B/V 三个“披露倾向”状态。
- **观测语义**：已见完整消息、过去缺失内容、真正的未来事件分开。缺失不补 0；历史缺失变量可被已见下游证据更新。
- **实际学习**：默认 28 参数；在原有 8 训练/8 验证流程上完成 4 个 BN 拟合和 2 个同形式 Logistic 拟合，另有 2 个规则对照。
- **重要结论**：本批所有目标的父事件都已观察到，输入的父事件均值又恒为 0.5。BN 与同形式 Logistic 的预测差约 7e-10/4e-8。**本轮扩展了可计算结构，没有证明传播学习优势或提高了真实泛化。**

仍遵循“风险知识 → 分层图构建 → API MAS 风险监测”。本轮没有读取旧留出测试、没有 API 调用、没有选择新默认模型，也没有将组件升级写成完整论文方案已完成。

## 1. 图里面是什么

工作流继续分功能节点与实际 Agent 主体。一个功能节点可以声明多个主体；每个概率事件绑定具体主体和阶段。事件不是“Agent 是否邪恶”，而是：

- `literal_appearance`：某个指定字面信息是否出现在绑定的消息中；
- `tool_dispatch`：某个精确绑定的待执行工具动作是否派发一次。

两个类型不会互换。文本出现“60元”不会因此成为付款；字面追踪不等于检测语义改写、指令感染或真实损失。

可观测事件有三种状态：

1. **已经观察**：保留原消息和来源，直接核对该字面信息是否出现。0 要有完整消息支持，不能由日志缺失推出来。
2. **过去内容缺失**：明确在过去，但该信息是否出现未知。保留随机变量并按证据更新，不冒充未来动作。
3. **未来事件**：尚未观察到，作为预测对象或中间变量。不能放入未来正文或未来标签作为证据。

例如同一条未完整记录的上游消息被送给两名 Agent，其中一人的后续回复已可见，另一人的回复尚未生成。新模型可以用已见回复更新对上游缺失内容的判断，再计算另一人的未来输出概率。这个例子目前只有构造机制验证，没有相应真实训练数据。

事件边必须对应显式功能工作流中的直接传递边，并携带“已有传递记录”或“已声明未来传递”的依据。文本到文本的边必须追踪同一字面信息。它不是从输出相似性猜边，也不是因果发现。

## 2. 局部概率模板怎样学习

`configs/observable_event_dag_v1.json` 定义 prepare/work/review/publish/dispatch 五类阶段，每类共享五个系数：

`logit P(X_i=1 | 父事件, 前缀) = b + w支持×支持线索 + w反对×反对线索 + w均值×父事件均值 + w组合×多父事件全部成立`

只有一个父节点时，最后一个组合项固定为 0，避免和单父项完全重复。系数可以为正或负，不能事先假设所有信息传递必然增加风险。没有父事件时两个父项均为 0。

五类各五个系数，共 25；再复用一套已有的 3 类未知授权事实先验，合计 **28 参数**。没有另外保留原独立工具预测器的 9 个参数，也没有复制一份授权事实。

模板引用风险库 RB013/RB014 的跨通道隐私观察依据。引用支持研究对象与可观测关系，不代表论文证明了本项目选择的 Logistic 条件函数。模板选择/角色标记和线索提取目前仍由适配器给出，不是全自动知识发现。

这里采用带正则的最大似然点估计，不是对所有参数做贝叶斯后验采样。用了 BN 这一名称不表示解决了参数不确定性或因果识别。

## 3. 系统层保留完整联合概率

对所有未观察事件求和，计算：

`P(目标事件组合 | 当前已见事件) = P(目标事件组合, 已见事件) / P(已见事件)`

分母也随参数变化，梯度必须包含它。过去缺失事件和未来中间事件都参与求和；已见消息保持其原条件概率表和父边，不能剪边后伪装成同一个条件概率问题。

最终目标组合再直接连接 `WorkflowRiskBN` 的授权、单次额度、累计额度、禁止组合和系统 OR 节点。同一事件、同一授权根只出现一次。多个未来动作受同一个未观察上游事件影响时，保留其相关性，不以各自边际概率相乘代替。

提供的构造例子中，两个未来动作各约 0.5，但共同发生概率约 0.395，而不是独立假设的 0.25。给定其中一个动作发生后，另一个动作的条件概率也会更新。它只说明新结构能表达并正确计算这种依赖，不是现实中测出了该相关系数。

现有 `event_conditions` 查询继续可用。指定事件条件不是证明动作已经执行，也不是因果干预。授权真值不会被偷放进 Agent 行为的条件特征，行为预测使用的仍是它实际可见的前缀线索。

## 4. 真实数据拟合做了什么

只使用 `branch_publisher_fit_20260920/inputs/train.json` 与 `validation.json`，各 8 个已经采集的真实 API 流程。这个验证组以前已被研究使用，**不是新独立测试**。

`event_dag_projection.py` 从既有验证过的前缀提取规划消息、各执行者消息、发布者实际可见的授权线索与来源绑定，形成 8 个字面事件：6 个已经观察，2 个待预测。最终回复只作为训练/评测标签，不进入图输入。

全部 BN 从零初始化：有传递边/删除传递边 × 正则 0.001/0.03，共 4 拟合；全部成功收敛。另使用独立 sklearn 优化器训练同输入、同正则目标的 Logistic，再加入可见授权规则及保持出现规则。所有候选都报告，不先挑出漂亮成绩。

| 方法 | 正则 | 验证系统风险 Brier，越低越好 |
|---|---:|---:|
| 事件 DAG-BN | .001 | .0000627369 |
| 删除传递边的 BN | .001 | .0000643342 |
| 同形式 Logistic | .001 | 与事件 DAG-BN 预测最大差 6.87e-10 |
| 事件 DAG-BN | .03 | .0142240867 |

前六种和可见授权规则的 F1 均为 1。不能据此写成新结构独有的满分。

## 5. 一个必须防止的误读：非零关系系数不一定说明学到了关系

正则 .001 的模型学到了：发布偏置约 −2.65284、父事件均值系数约 −1.32642。但这不证明“上游出现会抑制发布”。

原因是所有训练输入中的该均值都是 0.5，模型只看到：

`有效偏置 = 发布偏置 + 0.5 × 父事件均值系数`

二者的作用无法仅凭这批数据分开辨认。直接输入矩阵为 16×25，秩只有 3；其余阶段的已观察消息在条件似然中被条件化，并不因此获得新的传播监督。不同参数分配还会改变正则惩罚，从而带来微小分数差，不能把这种差值全记作关系建模贡献。

同形式 Logistic 与 BN 几乎一致，正是这个判断的数值证据。优化器收敛、系数非零和图中有边，都不等于真实传播机制已经被识别。

因此下一批真实数据需要同时出现：不同的信息分布、确实未产生的中间/末端事件、可核对的传递关系、变化的权限/政策作用域和正常对照。不能仅继续增加形状相同的最终发布样本。

## 7. 尚未完成的整体要求

当前支持至多 12 个显式功能节点、36 个事件定义；未观察事件与未知授权事实仍受默认 16、硬上限 18 个二值变量的精确枚举约束，不是大图算法。只针对明确动作与固定授权窗口，不覆盖自动发现的新动作、重复执行或任意时间变化的授权。

已实现的是可变 DAG 的概率接口，不是自动读懂任意 Agent 框架。实际适配和拟合仍只有原固定四角色发布数据；更多拓扑目前仅有构造验证。过去内容缺失的概率也没有真实校准。

完整角色/职责识别、知识子图自动生成、真实多风险联合训练、可靠语义提取、大图推断、原生 MAS 方法在新独立数据上的公平比较及提前预警优势仍待完成。本轮没有 Git 提交/推送，没有改变当前任务的模型或思考强度。
