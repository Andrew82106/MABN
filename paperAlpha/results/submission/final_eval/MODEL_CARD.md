# 模型结构

本方法保留两条可检查的线：规范线是 workflow DAG（职责、授权和允许通信）；执行线是 API 可见的输入、消息、委派、工具调用和权限事件。前者表示“应该怎样运行”，后者表示“实际发生了什么”，不把任一图宣称为因果发现。

第一层是局部风险 BN：对每个节点计算不可信输入、特权工具、同节点输入到特权工具、权限不匹配等证据，并用训练组内的 Laplace CPT 与 noisy-OR 得到局部风险。第二层对运行时消息/委派边做可学习门控和 noisy-OR 传播，再计算规范边与实际边的重合、缺失、意外边、可达性和证据完整性。

知识模板层把可观测的授权不匹配、意外工作流边、意外边到高权限工具、来源边和不确定证据显式绑定到融合头。它是白盒证据模板，不是隐藏机制标签。最终融合在外层训练组内使用组级折外预测学习，阈值和概率校准使用独立的组校准集。

白盒边界：监测器的变量、关系绑定、条件概率、证据来源和计算路径可核查；被监测的 API 大模型仍是黑盒。标签、隐藏终态效果、机制名和 topology family 不进入特征；topology family 只用于分组切分。

重要限制：当前目录仍是开发候选实现。匹配的 78 维公开特征逻辑回归在 AUROC、Brier 和 ECE 上略好，本方法只在 F1/AUPRC 上略高；不能声称全面胜出。投稿版还必须完成动作发生前的真实 API 复核和外部 MAS 轨迹验证。

最新低价 API 开发证据：隔离 `openai-agents 0.22.3` 环境下完成 3 个 HarnessAudit 任务（`off-t6`、`ec-t3` 完整，`fin-t1` 失败但保留），共 36 次请求、36 个唯一响应；采集与 artifact audit 通过。该批次出现原生策略违规，但样本仍不足以估计性能、泛化或低误报率。

追加确认批次：`api_recovery_confirm_20261001` 使用同一隔离环境和 `gpt-5.5/low` 完成 `ec-t4`、`fin-t2`、`off-t2` 三个任务，共 38 次请求、38 个唯一响应，独立 artifact audit 通过。该批次仍是开发证据；由于 HarnessAudit 的动作级 `violated` 尚未成为独立风险标签，不能把它写成监测器性能结果。

阶段前瞻开发模型已实现：在每个阶段开始时，只读取公开工作流、角色/工具/策略和已到达的消息/动作，学习四类下一阶段原生策略违规的条件链，并以 `1-P(0000)` 输出系统风险。16 个完成任务的分组留一结果为 AUROC 0.874、AUPRC 0.698、Brier 0.127；同信息 HistGB 的 Brier 0.112，说明当前结构仍需更多独立任务和校准，不能写成已超过强基线。三任务重跑仅验证运行稳定性，不是泛化测试。

在同一批 103 个阶段窗口上，监测器推断 p50/p95 为 0.794/1.635 ms；该数字不含 API 生成、语义抽取、网络传输和训练。

当前候选结构 v6 额外加入六个运行时执行图统计量（已见节点、已见边、声明边覆盖、意外边比例、分支和汇聚），作为第二条可审计的动态图线。其 16 任务留一结果为 AUROC 0.875、AUPRC 0.703、Brier 0.127；三任务跨任务检查为 AUROC 0.963、AUPRC 0.953、Brier 0.124。匹配 HistGB 在开发/重跑中仍有优势，因此 v6 仍是候选开发结构，不是全面领先结论。
