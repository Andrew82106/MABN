# 整答监督减少拒答误报，但没有改善定位

五折两模式已按冻结方案完成。下面只比较两个相同 MLP：A 只有窗口损失，B 额外使用已有整答标签。每个结果都使用同一组选定轮次/融合系数同时计算两项 F1，没有把不同候选的最好指标拼在一起。

| 匹配对照 | A 定位 F1 | B 定位 F1 | A 整答 F1 | B 整答 F1 |
|---|---:|---:|---:|---:|
| 网络本体 | 0.478469 | 0.454319 | 0.632479 | **0.684211** |
| Lookback + 网络 | 0.629991 | 0.628753 | 0.693333 | **0.761905** |
| R26 + 网络 | 0.707156 | 0.703499 | 0.787234 | **0.801394** |

本体对 117 条安全拒答的整答误报由 **56 降到 12**。全部答案误报由 89 降到 49，同时检出的风险答案由 111 降到 104。说明加入整答监督改善了这一类误报，仍有召回代价。

定位则不同：本体 TP 600→639，但 FP 845→1111，F1 降低。两个匹配融合对象的定位也没有提高。这个固定的“整答最大值监督”对照没有解决定位问题，不继续搜索系数或增加轮次。

原 Lookback **0.616695 / 0.699346**、原 R26 **0.709014 / 0.800000** 均精确回放。上一轮 R29 的 LR+R26 为 **0.722039 / 0.804054**，只是历史结构参考；不能把 MLP 与 LR 的差异归因于整答监督。本轮没有产生更好的两级共同替代方案。

全部 10 个网络、100 个训练轮次及 epoch 0 诊断保留；每模式每折 210 次更新。原 R28/R29 控制零重训。拟合、校准和保存共约 **9.25 秒**，全程 CPU 四线程，没有使用 GPU。

独立审核已通过：重新核对窗口与整答权重、fit-only 标准化、组/回答/候选窗覆盖；重放全部 **110 个检查点**，保存概率最大差 **0**；两模式所有对应轮次的随机状态相同，初值和优化步数一致；重新核算所有轮次阈值、选轮规则及 **120 个 alpha 候选**；两级分母和外层每条样本只评一次均通过。结果见 `AUDIT.json`，完整曲线在该文件和每折各轮文件中。
