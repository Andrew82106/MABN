# R19 实现静态复核

**结论：已发现的启动阻断已修复，当前未发现其余阻断。** 本次只读代码及协议，没有正式拟合、生成模型或改动冻结模型。

- **接口一致：**六个方法名与 models19 匹配；输入维数依次为 785、787、789、789、795、10。LR 的权重、scaler、C、种子、float32 转换及预测接口与 R18 一致。
- **十维聚合正确：**MMD 先在每个 token 的两个来源上求均值/max，再沿窗口平均；ECS 按层优先、头其次的784列 reshape 为4×7×28，平均段内层和头；PKS28列按4×7平均。两者均得到4维，再平均同一原始BPE窗口。没有先窗口平均再取MMD最大值的顺序替换。
- **样本和划分保持一致：**只读取R16 train的602条生成记录；候选窗口逐条与R18文件比较，要求278组、9526个定位有效窗口。窗口包含标点、短窗口及拒答的处理沿用R17/R18；仅有效定位窗口进入拟合，拒答只进入整答无风险分母，未定不补零。
- **训练与阈值隔离：**原五折分配文件哈希必须一致；每轮3折拟合、下一折校准、当前折评测。scaler及类别权重只使用fit；窗口和整答阈值分别仅由校准数据选择。各方法均使用同一窗口次序和组划分。
- **基线对齐有硬校验：**逐折比较fit索引、标签、权重、类别系数、窗口key、scaler、LR系数/截距/类别/迭代数、所有候选分数及两类阈值。原先class_factors用数组直接作布尔判断会报错，root已改为np.array_equal，修复已核读。
- **指标复用可行：**r18.METHODS仅在本进程重绑定为六个名字，供pooled/bootstrap调用，不改R18文件。跨折汇总使用各自冻结阈值下的混淆计数，未混用不同模型的连续分数计算总AUROC；分层结果也删除混折排序指标。

本复核不替代提取完成后的接入验证：仍须由SignalBank检查原始数组形状、float32、有限值、精确token ID/坐标、生成记录哈希及提取签名；基线严格一致检查须在正式拟合时实际通过。GPU提取、扰动边界和来源池审核由提取负责人负责。
