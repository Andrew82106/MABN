# 新数据与最终测试方案

日期：2026-09-11。此次只做来源、字段、既往使用范围及官方资料核查；没有新生成、GPU、模型下载或候选 QA 回答/风险标签检查。索引和分区是**待审核提案**，不是已冻结的新测试集。

后续执行已另建 [benchmark_ragtruth_qa](../../benchmark_ragtruth_qa/README.md)：改用型号更明确的 Llama-2-7B-chat 原回答；细段与关联组审计后准备634个fit、159个calibration优质原回答，150个官方test继续密封。下文671/168是本次最初的源ID提案，后续数据以该目录manifest为准。该后续任务获授权读取开发标注并下载公开权重，和本篇只读勘查阶段分开记录。

**优先使用本地已有的 RAGTruth QA 人工 span 数据，补上目前数据缺少独立人工细标的弱点；同时保留一个真正新主体/新事件的控制场景测试。** 两者回答不同问题：前者检验在已有人工标注问答上的定位，后者检验能否推广到新的材料、主体与事件。当前原始 Mistral 版本尚未确认，不能直接宣称还原了当年的内部状态。

## 1. 本地现成数据能用多少

| 数据 | 本地核实规模 | 既往使用与可用范围 |
|---|---:|---|
| RAGTruth QA | 989 个 source，6 模型共 5,934 个回答；Mistral 每 source 1 个回答 | 官方 train 839 / test 150。旧新闻实验实际使用的 734 个 source 全属 Summary，与 QA source ID 重叠 0。未发现 QA 进入既往特征训练的证据。 |
| RAGTruth Summary | 943 个 source、5,658 个回答 | 已用新闻来源 734 个；旧新闻测试和错误案例已暴露，不能再当新的独立验证。 |
| RAGTruth Data2txt | 1,033 个 source、6,198 个回答 | 是结构化数据转文字，不是本项目优先的检索问答场景。 |
| R16 保留的 RAGognize 来源池 | 1,252 个来源；其中 800 个已作 R16 target/donor | 加入已记录来源拒绝与事件禁用后，剩 **312 个待语义审核来源**，不是 312 道已合格独立问题。 |

RAGTruth 原始全库已在 `prelab/data/raw`，无需再下载。旧最初的检查脚本曾统计全库任务/标签总量，因此准确说法是“未发现 QA 用于旧实验开发”，不能说“原始 QA 从未被任何代码触及”。本次没有读取候选具体回答或风险标签来筛选。

RAGTruth QA 有人工词/片段标注，问题来自 MS MARCO，每题 3 个检索段落。原论文每回答两名标注者独立标注，重大分歧再复核；它比把句级自动标签广播到每个词，更接近本项目要求。[官方论文](https://aclanthology.org/2024.acl-long.585.pdf)、[官方字段说明](https://github.com/ParticleMedia/RAGTruth#dataset)

## 2. 可直接执行的 QA 源级分区提案

已生成 [源级分区索引](ragtruth_qa_split_proposal.jsonl)：保留官方 150 个 test source 密封，839 个官方 train 按固定种子 `20260911`、源 ID 哈希排序留 20% 校准。

| 用途 | source / 单个原生模型回答 | 6 模型总回答 |
|---|---:|---:|
| fit | 671 | 4,026 |
| calibration | 168 | 1,008 |
| sealed test | 150 | 900 |

所有同 source 的六模型回答必须在同一分区；只用 Mistral 时实际训练规模是 671 个回答，不能称 4,026 个 Mistral 样本。没有按是否幻觉、span 数量、回答质量或任何检测结果分层抽样。

已完成的元数据核查：QA 没有重复的规范化整问句、重复的整份检索资料哈希；与旧 Round2 Trivia/SQuAD 的 5,849 个唯一问句哈希无精确重叠。**这些只证明精确重复检查通过，尚不证明主体/事件独立。** 冻结前还要检查单个检索段落重复、文章部分重叠、实体别名和具体事件；将有关联的 source 组成同一组。发现跨官方 test 的开发关联时，隔离相连开发资料或明确报告污染，不能让同事件材料跨区并继续声称全新事件泛化。

旧新闻 734 个 source 的排除记录及全部输入哈希保存在 [来源清单](source_inventory_summary.json)。原生模型及回放决策不明前，这份分区不升级为 R21 正式数据冻结。

### 回放的实际缺口

官方发布了 prompt 和 response 字符串，README 写明 `<s>[INST] {prompt} [/INST]` 外层；但没有确认 Mistral v0.1/v0.2/v0.3、权重 revision、原输入/输出 token IDs 或原生成脚本。QA 原指令还明确允许缺信息时拒答，与现有项目的中性问法不同，不能悄悄修改提示再保留原生实验之名。[官方 README](https://github.com/ParticleMedia/RAGTruth#dataset)、[原作者 TGI 回复](https://github.com/ParticleMedia/RAGTruth/issues/6#issuecomment-2264472559)

应先核实原 checkpoint；若无法恢复，允许预先声明采用指定版本、模板和精度的**教师强制重建**，但不能称精确原生隐藏状态回放。抽样 seed 缺失不是教师强制前向的核心障碍，权重、分词器和输入轨迹才是。完整核查见 [Mistral 回放可行性](MISTRAL_REPLAY_FEASIBILITY.md)。

保留原回答文字和人工字符 span，检查分词边界、截断、特殊 token 与字符定位。把 Mistral 原答案喂给 Qwen，只能研究 Qwen 对外部答案的表征；若让 Qwen 自己重新回答，必须重新标注实际输出，不能搬用旧 span。

## 3. 真正新事件测试能扩多大

剩余 312 个 RAGognize 来源的官方类型为：时间 84、身份/关系 93、其他/行为 115、数量 20、地点 0。原分类不限制同一文章中另一个真实属性；有出生地、发生地等明确事实时可人工改问地点，但不能将学校/机构名称冒充地理地点，也不能虚构缺少的事实。

因此现成池**不能承诺再造 400 个相互独立、五类均衡的新题**。如果每题仍需一个独占且此前未用的 donor，312 个来源理论上最多组成 156 对，实际还要扣除不合格来源和相连事件。建议先审一个 50–100 题的备用候选池，目标时间、数量、地理地点、人物/组织关系、事件行为都有覆盖；最终数量以审核通过为准，不为凑数扩大题意或编事实。当前 20 个数量来源及没有原 SPATIAL 候选是主要瓶颈。

候选元数据见 [剩余来源索引](ragognize_remaining_metadata_index.jsonl)。每条仅含 ID、标题、URL/revision、全文哈希、原类型和排除理由；没有导出原答案或新模型回答。仍需执行：

1. **先隔离来源。** 对照所有旧输入，而不只训练集：题目主体、文档标题、正文提及、别名、长原文重复，以及同一选举/报告/比赛等具体事件。目标与 donor 都纳入关联图；新题内部也按图分组。相同大领域不等于同一事件，不能单靠关键词禁掉整个领域。
2. **再选可检验事实。** 中性问题；完整资料为主体背景加证据，partial 保留同主体的真实背景，仅拿走所问事实。共同背景不能通过年份相减、语义推断或问题前提泄漏答案。固定同一独立他主体 donor，两个条件同顺序，长度控制不能靠重复 padding。
3. **独立来源审查后冻结。** 保存完整原文、唯一引文坐标、来源 revision/hash、每项证据与排除原因。数据构建不能看模型输出或检测分数。两个条件都可能答对、拒答或编造，不能用 condition 自动造风险标签。
4. **固定模型与方法后才打开最终测试。** 用一次生成的原始 token 轨迹，先盲标和独立复核，再由冻结脚本评分。测试的表现或错误案例一旦用于调整，转为开发材料，下一次主张新泛化须再留新测试。

若来源不足，再补真实公开资料；需要优先扩数量和地理地点，保留取得时间、页面快照、许可和事实证据。不是先指定想要的幻觉文本，再把编造内容当成“真实世界事实”入库。

## 4. 当前开发与已暴露测试的边界

| 数据 | 原划分规模（题目数） | 现在能承担的角色 |
|---|---|---|
| R1–R5 新闻 | 实际共用 734 个 Summary source，含多轮新旧验证 | 已用于方法开发/确认和案例解释；不再是全新测试。 |
| R6 | 18 train /6 val /6 test，另有开发预览 | 全部按历史暴露资料排除。 |
| R7/R8 | 120 train /40 val /40 test，50 外部题，20 开发题；R8复用标签作词定位 | 都有历史开发或结果审查；纳入旧来源隔离清单。 |
| R9 | 120 train /40 val /40 test | 原 test 已报告并逐例审查，不可重新当独立测试。 |
| R10 | 复用 R9 的 120 train /40 val，新增 60 test | 60 test 已使用、解释；后续合并不能把它重新变“新”。 |
| R16 | 301 train /49 val /50 test，合计400题、373事件/主体组 | 原 val/test 已在 R17 使用；原 train 是后续优化开发域。 |
| R18/R19/R20 | R16 train 的301题、278组、602固定回答 | 交叉验证、方法诊断与选型范围；其中 OOF 回答被反复用于研究后，不等于未暴露最终测试。 |

不同轮复用的题不能重复相加当独立样本。R16 的 25 个旧事件相连问题被固定放到训练，说明其“400道新问题”不等于“400个从未见过的事件”。旧 combined manifest 的 fresh-test 表述是当时的角色记录，不代表现在仍新鲜。

## 5. 数据问题应怎样修

- **目前标签并非独立研究人员人工金标。** 既有 R16 等为助手初标、独立助手复核与裁决；应明确披露。用 RAGTruth 人工 span 作独立基准，同时请真实标注者盲审自建集的代表性来源/回答，区分确实标签错误与合理边界分歧。
- **任务是“资料能否支持”，不等于世界真伪。** 无依据但碰巧答对仍可能是本项目风险；正确拒答不是幻觉。RAGTruth 的 `implicit_true`、信息冲突、质量排除与拒答如何进入目标，须只用训练资料定好，不在看到新 test 后改口径。[官方类型定义](https://github.com/ParticleMedia/RAGTruth#dataset)
- **当前场景偏窄。** RAGognize 改造集多为英文 Wikipedia 近期事实、两条短资料、一句回答，不是实际多轮联网搜索，也不代表中文情报研判。控制集适合检验证据绑定，外推时须另测真实检索、较长回答、多来源与来源冲突。
- **计分不能把相邻窗口当独立样本。** 4 词元滑窗高度重叠，一条长错句产生许多正窗口。报告整答和定位指标、题组数与阳性数，并按主体/事件组给区间；不能只用总窗口量证明数据很大。若风险边界有多个合理画法，应另给边界敏感性分析，不能为提高 F1 改金标。

## 6. 其他现成数据的用途

RAGBench 有 question/documents/response，但其大规模标签主要为 GPT-4 自动句级支持判断；HalluRAG 为自动句级标注和小规模人工核验，更适合句级方法参考或弱监督扩充。两者都不能直接替代“全量人工词元风险金标”。“RAGtelligence”此次未找到可确认官方来源，暂不作为已存在的数据集推荐。规模、许可与引用见 [外部数据比较](EXTERNAL_DATASETS.md)。

执行顺序：先完成 QA 回放定义与源/事件隔离；固定训练与校准口径，使用人工 span 训练；同时审查新事件备用源。只有方法冻结后才开启最终测试。开发 F1 达到约0.75可以作为迭代目标，是否具备独立泛化能力必须由密封测试另行回答。

本轮机器可核验产物：[来源统计及哈希](source_inventory_summary.json)、[QA元数据](ragtruth_qa_metadata_index.jsonl)、[分区提案清单](ragtruth_qa_split_proposal_manifest.json)。本报告未声称 312 个候选均可用，也未宣称原始 Mistral 精确回放已解决。
