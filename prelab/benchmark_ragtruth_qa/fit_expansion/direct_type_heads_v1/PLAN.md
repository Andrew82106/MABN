# 两类型直接输出：固定 CPU 对照

复用 `probe_v1` 的原 hidden64 / hidden64_risk 窗口输入、原 PCA、scaler、原 binary 训练权重。仍为 3,680 fit 回答／653,979 窗口及 159 cal 回答／42,241 窗口，来源组不变，不访问测试。

每种输入固定三个 C：0.00001、0.0001、0.001。每个候选用同一 C 训练两个独立 LR，分别预测无依据、冲突；同窗允许两个标签为 1，其 OR 必须逐窗等于原风险。每头完整复用原二分类 loss 权重，不加类型权重、不重估类别因子或 PCA/scaler。两个输入共 12 次新 LR 拟合，不做两头 C×C 组合。

每窗总风险固定为两头分数最大值，再按原窗口取整答最大值。原两级阈值和单一候选选择规则不变，仅 cal 选择，全部候选与两头分数保留。max 是检测分数，不声称是校准的风险联合概率。

控制每个 C 直接复用同一旧 binary LR 两次，max(p,p) 精确等同原结果，无新拟合。两个相同输出不增加信息或有效容量，不称为强容量控制；新候选两个类型边界不同，这个差别要保留说明。

与以前的类型加权实验不同，这次改变目标及实际推理输出，而非仅改变 binary 损失权重。与原辅助类型头也不同，这次两类型直接决定最终风险。它仍可能提升冲突召回而增加误报，不保证总体改善。

当前只运行 `run_direct_type_heads.py prepare`、`check`，核完整旧六个模型及全部窗口／整答分数、阈值和计数，再交根代理审阅。`fit` 为独立入口，需要后续授权；不操作 GPU 或改动 NLI/FAVA 队列。
