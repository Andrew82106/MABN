# OSINT 场景事实性幻觉监测：实验总览（合作者草稿）

版本：v1（供论文初稿使用）  
数据与结果口径：2026-09-13  
结果状态：**开发集统一评测，尚非独立盲测**

## 1. 研究问题

研究目标是在“资料＋问题＋大模型回答”的开源情报汇总场景中，判断回答是否包含**相对于已提供资料无依据或与资料冲突的事实性陈述**，并定位到回答中的较粗风险区域。

现实动机是：检索系统可能只找到部分主体或部分证据，模型随后用自身知识补全缺失信息。监测器应先告诉使用者“这份回答是否值得复查”，再指出回答中哪一段更可疑。

本文研究的是证据约束下的事实性风险，不能把标签解释为“陈述在世界上一定为假”。例如，陈述即使可能真实，只要提供的资料没有支持，也按本任务定义标为风险。

## 2. 数据集与金标

### 2.1 数据来源

数据来自 RAGTruth QA 的公开人工标注回答，原回答文字、问题、三段检索资料和人工字符区间均保持不变。生成器重放使用公开的 Llama-2-7B-chat 检查点做教师强制重建；这不是历史生成轨迹的逐 token 精确恢复。

正式开发划分如下：

| 分区 | 回答数 | 资料组数 | 用途 |
|---|---:|---:|---|
| fit | 3,680 | 615 | 训练、特征选择和模型冻结 |
| calibration | 159 | 154 | 选阈值和开发评测 |
| 合计 | 3,839 | 769 | 资料组在两区间不重叠 |

其中最初的人工 Llama 回答为 634 条 fit＋159 条 calibration；fit 扩充的 3,046 条来自同一资料来源的其他生成器回答，经固定 Llama 教师强制重放后用于增加训练覆盖。因此，3,680 不是 3,680 个完全独立事件。

calibration 中有 100/159 条回答含人工事实风险，按固定 4-BPE 窗口规则共有 42,241 个可评窗口，其中 5,984 个为风险窗口。

### 2.2 标签与评测单位

1. 保留 `quality=good` 的回答及原始人工 span；不根据模型分数、错误数量或难度删样本。
2. 将字符级人工 span 按固定字符偏移映射到原始回答 BPE。
3. 使用长度 4、步长 1 的原始 BPE 滑窗；只评估覆盖至少一个字母或数字的窗口。
4. 窗口内有一个风险 BPE 即为正窗口。
5. 回答级标签是“回答内存在至少一个人工风险 span”；回答级分数取全部可评窗口分数的最大值。
6. 窗口和回答分别在 calibration 上按“F1 最大、precision 更高、阈值更高”选择阈值。

4-BPE 是**粗粒度风险区域**，不是精确到单个字符的定位。

## 3. 本文候选检测器

最终候选名为 `semantic_claim__old_tree__large_weight0.4`，由两条互补支路组成：

### 3.1 生成阶段内部信号支路 `p_old`

- Lookback 注意力比例：模型在生成当前回答时，更依赖输入资料还是已经生成的回答；
- token NLL：模型对所选 token 的生成不确定性；
- MiniCheck 的语义隐状态和句级风险；
- TCN、同陈述风险传播和 MiniCheck 末两层风险头；
- 用已冻结的深度 2 单调树得到窗口风险 `p_old`。

这一支路保留了生成模型内部轨迹，同时加入了证据语义核查信号，所以不能称为纯白盒探针。

### 3.2 全上下文语义支路 `p_large`

ModernBERT-large 同时读取资料、问题和完整回答，输出每个 4-BPE 窗口的风险分数。模型使用 3,680 条 fit 回答训练，冻结第 3 轮检查点。

### 3.3 融合

窗口最终分数为：

```text
score_window = 0.6 × p_old + 0.4 × p_large
score_answer = max(score_window)
```

没有重新训练 Llama-2 基座；树、语义头和 ModernBERT 均在评分前冻结。最终独立审计对数据分母、分数重放、阈值、回答 max 和基线身份共检查 288 项，全部通过。

## 4. 正式基线

外部方法按论文结构、特征、公式和原生模型输出迁移到同一数据与评测口径；不为基线加入本文的融合模块，也不故意压低基线分数。

- **Lookback Lens（EMNLP 2024）**：8 原始 BPE 注意力窗口＋默认逻辑回归；
- **GHOST**：论文四维特征＋最终随机森林；原方法没有局部输出，统一窗口结果采用冻结整答分数的零参数广播；
- **LUMINA**：固定作者的 IPR−MMD 公式；
- **ReDeEP（ICLR 2025）**：固定论文的逐 token 公式和 K/层/权重；
- **RAGognizer**：官方 Llama-2 检查点、LoRA 和 `hallu_head_neg_16`，使用原生 token 概率。

所有正式基线都覆盖同一 3,839 条回答；主分数仍只在 calibration 159 条回答上报告。

## 5. 主结果

F1、AUROC、AP 均为越高越好。下表是统一 4-BPE 窗口和整答 max 口径。

| 方法 | 窗口 F1 | 整答 F1 | 窗口 AUROC | 整答 AUROC |
|---|---:|---:|---:|---:|
| **本文候选** | **0.690281** | **0.891089** | **0.913367** | **0.906102** |
| Lookback Lens | 0.600882 | 0.845455 | 0.872400 | 0.848814 |
| RAGognizer | 0.507511 | 0.806867 | 0.824938 | 0.706949 |
| LUMINA | 0.331299 | 0.785047 | 0.691406 | 0.702203 |
| ReDeEP | 0.329560 | 0.772358 | 0.669274 | 0.590678 |
| GHOST | 0.320361 | 0.772201 | 0.632713 | 0.588983 |

相对最强正式基线 Lookback Lens，本文候选：

- 窗口 F1 高 0.089399；
- 整答 F1 高 0.045635。

候选的 calibration 混淆矩阵为：窗口 TP/FP/FN/TN = 3,839/1,300/2,145/34,957；整答 TP/FP/FN/TN = 90/12/10/47。

需要注意，calibration 中 100/159 条回答为风险回答，因此“所有回答都报风险”的整答 F1 已经是 0.772201。候选的 0.891089 不能只靠 F1 解读；其整答 AUROC/AP 为 0.906102/0.946840，说明在这批开发数据上确实有区分能力，但仍不能替代盲测。

## 6. 主要消融发现

以下结果用于解释模型为什么有效，不替代正式基线表：

| 实验方向 | 典型窗口/整答 F1 | 结论 |
|---|---:|---|
| 初始 hidden64 白盒探针 | 约 0.619/0.844 | 仅靠低维内部状态可以学到部分风险，但局部定位有限 |
| `semantic_claim` | 0.650/0.860 | 语义状态与生成信号互补 |
| ModernBERT 完整上下文 | 约 0.673/0.864 | 直接比较资料、问题和回答有效 |
| NLL 单独 | 约 0.291/0.772 | 生成概率不能单独作为事实风险判据 |
| NLI/语义融合最佳对照 | 约 0.685/0.873 | 语义核查有帮助，但仍低于最终融合 |
| FAVA 辅助数据最佳组合 | 约 0.688/0.870 | 自动辅助数据有小幅帮助，未超过最终候选 |
| 来源匹配、类型头、关系作用域等 | 无稳定提升 | 当前瓶颈是关系反转、条件和来源归属，而不是简单的词面覆盖 |

一个重要诊断是：人工原子切分的 oracle 窗口 F1 可达约 0.889，而当前模型为 0.690，说明主要困难不是窗口几何，而是模型没有稳定识别“主体—关系—条件—来源”之间的事实关系。

## 7. 论文可以怎样表述

### 可以主张

在资料约束的开源情报汇总任务上，融合生成阶段内部信号和证据语义信号，可以同时完成整答风险筛查与粗粒度风险区域定位；在统一开发评测中，候选点估计高于五个已完成的正式方法迁移基线。

### 暂时不能主张

- 已证明真实联网搜索部署有效；
- 已解决“检索不全后靠猜”的问题；
- 精确逐 token 或逐字符定位；
- 纯白盒探针；
- 独立测试领先或 SOTA。

原因是 calibration 已被多轮用于模型、轮次、融合权重和阈值选择。旧官方 test 已永久退出最终无偏评测，当前结果必须写成“统一开发集结果”。

另外，候选在 fit 上的窗口 F1 约为 0.808，而在 calibration 降到 0.690；这提示融合树使用训练内上游分数，存在过拟合风险。该问题也是下一轮分组交叉拟合和新 holdout 必须检验的重点。

## 8. 下一步正式验证

建议论文初稿把当前结果定位为方法可行性实验，并补一轮真正的 OSINT 盲测：

1. 预先冻结模型、阈值、代码和基线身份；
2. 新建约 200 个事件组，给同一问题构造“资料完整”和“缺少部分主体资料”两种条件；
3. 用固定模型一次生成回答，保存真实白盒轨迹；
4. 三人独立标注事实风险 span，第三人裁决；
5. 建模方只拿无标签输入，评分方最后一次解封 gold；
6. 报告窗口 F1、整答 F1、AUROC、AP，以及按事件组 bootstrap 置信区间。

这一步完成后，才能判断当前开发集优势能否迁移到真正的开源情报搜集场景。
