# Semantic source attribution 扩充可行性审计

结论：**可以扩到新增 3,046 份回答，并与原生 634 份 fit 合并为去重后的 3,680 份 fit。** 本次只读 fit 数据、只跑 CPU；没有打开 calibration/test，没有启动模型或 GPU，也没有改正在运行的 v1 提取器。

## 已验证的数据接口

| 项目 | 新增 3,046 | 合并 fit 3,680 |
|---|---:|---:|
| 可评分原子微主张 | 25,864 | 34,919 |
| 标点-only、应排除的微主张 | 16 | 22 |
| 正微主张 | 2,183 | 3,474 |
| 词面 BPE | 420,782 | 560,300 |
| 风险 BPE | 30,239 | 47,398 |
| 可评 4-BPE 窗口 | 485,856 | 653,979 |
| 正窗口 | 36,956 | 58,433 |

- 3,680 个 `response_id` 唯一，`source_id + exact answer` 也全部唯一；新增与保留 ID 无交集，标签冲突文件为空。
- 新增回答覆盖原来的全部 634 个来源、615 个来源连通组，问题、提示、检索材料及其分句在同一来源内完全一致。
- 逐条重算了 653,979 个可评窗口和 692 个纯标点窗口；token ID、绝对位置、4-BPE 边界及风险标签全部与冻结文件一致。

## 字符到 token 的映射

新增回答共有 43,867 个“回答 × 来源句”实例，每份回答有 3–48 句，平均 14.40 句。所有来源句的非空白字符和字母数字字符都被原始完整字符串的 tokenizer offset 覆盖；所有来源 token 都在回答之前，并属于冻结的 context 坐标。

全部 25,864 个可评分微主张都能从回答字符区间精确映射到回答 BPE，再映射到 Llama replay 的绝对 token 位置。420,782 个新增词面 BPE 均有且只有一个微主张归属。本轮发现的 26,810 个跨句首边界 BPE 已按原 offset 保留；这类 SentencePiece 边界现象不是映射失败。

## 边数、存储和时间

- 新增部分：390,683 条“微主张 × 来源句”边。
- 合并 fit：523,930 条边。
- 按 v1 当前输出 schema 精确计算，新增数组解压后约 **0.91 GiB**，合并 fit 约 **1.22 GiB**；为新增缓存预留 2 GiB 足够。
- 正在进行的原生 v1 提取只作为只读计时样本。结合冻结的 2.044 倍 query-work 比例，新增 3,046 份预计约 **50–70 GPU 分钟**。这是规划值；应在原生 v1 完成后用最终耗时再更新。

## 还缺的转换步骤

目前缺少一个**无标签的扩充布局转换器**，不缺原始数据。它需要：

1. 用 `new_token_plans.jsonl` 固定新增 3,046 个 replay 输入。
2. 从 `microclaims_fit3680.jsonl` 只取这些回答的微主张，并排除其中 16 个纯标点记录。
3. 对原始 `retrieved_passages` 使用现有冻结分句规则，把来源句字符范围平移到 `rendered_reference_character_range`，再与完整输入 offset 相交。
4. 写出 label-blind layouts 和 CSR 索引，随后复用 v1 原算法提取新增缓存。
5. 训练时复用原生 634 份缓存并拼接新增缓存；直到评分阶段才打开 `tokens_fit/windows_k4_fit` 接标签。

提取阶段不应直接读取 `results/atomic_microclaim_relation_expanded_v4/examples.jsonl`：它同时含 fit/calibration 且带 `gold_label`、`risk_bpe_indices` 等标签字段。

主要限制仍然是：新增 3,046 份回答来自另外五个生成模型，但内部状态是把它们统一 teacher-force 到 Llama-2-7B 得到的，因此属于**共同检查模型的 replay 表征**，不是各原生成模型的原生内部轨迹。

机器可读的全量统计、输入哈希和断言见 `REPORT.json`；可重复审计入口为 `audit.py`。
