# CERP-v1.1 fit-only CPU 门禁报告

## 决策

**停止 v1.1，不进入 NLI、GPU 或模型融合。** 生成器覆盖面够大，但没有选择性，
而且冻结抽样中的修复质量很差。继续评分只会让核查器替低质量候选收拾残局。

## 覆盖与污染

无标签生成阶段处理 3,680 个 fit 回答、34,919 个可评原子主张，得到 115,483 个
候选；22,808 个主张至少有一个候选。候选生成后 SHA256 已冻结，随后才打开 fit
标签做以下审计。

| 指标 | 结果 | 预注册门槛 | 通过 |
|---|---:|---:|:---:|
| Evident Conflict span 覆盖 | 204/271 = 0.7528 | >=0.60 | 是 |
| EC+SC span 覆盖 | 228/301 = 0.7575 | >=0.60 | 是 |
| 冲突窗口触达 | 3,199/7,006 = 0.4566 | >=0.50 | 否 |
| 干净回答窗口触达 | 176,632/403,265 = 0.4380 | <=0.25 | 否 |
| 冲突/干净触达富集 | 1.0425 倍 | >=2.0 | 否 |

另外，风险回答内部的正常窗口也有 79,026/191,270 = 0.4132 被候选碰到。
因此“存在可替换文字”几乎等同于一种常见文本现象，不能直接当作报警信号。

## 冻结质量样本

按 `sha256("cerp-qc-v1.1"|candidate_id)` 每类固定抽 10 条，共 60 条。当前复核是
**研究代理代理审查，不冒充人工金标**；正式人工门禁因此也没有完成。但代理结果已
足以说明不应继续：11 clear、2 ambiguous、47 reject，即 clear 0.1833、reject
0.7833，远未达到 clear>=0.80、reject<=0.10。

| 类型 | clear | ambiguous | reject |
|---|---:|---:|---:|
| citation | 4 | 1 | 5 |
| number | 2 | 0 | 8 |
| temporal | 0 | 0 | 10 |
| negation_direction | 0 | 0 | 10 |
| entity | 0 | 0 | 10 |
| aligned_relation | 5 | 1 | 4 |

典型污染包括：把情态动词 `may` 当成五月；把同一资料句中不同角色的数字互换；
把句首普通词当实体；把 `with`、`before` 等跨词类替换；以及仅因检索到某 passage
就更改引用编号，而该句并不支持剩余陈述。

## 根因

1. v1.1 的同类型槽位交叉组合过宽；“值来自资料”不等于“值在同一事实角色中”。
2. 局部 SequenceMatcher 有锚点，但没有要求修复后陈述成为证据句的近重复关系，
   一个长句内不同位置的词仍会串位。
3. 候选出现率被当成 CPU 先验检查时，正常文本也大量产生候选。真正可用的单位应是
   “银标校准器认为该修改显著提高证据支持的有效候选”。

## 审计边界

- prepare 和 audit 均 exit 0；模型加载 0、GPU 0、训练 0、baseline 修改 0。
- v1.1 只使用物理独立的 634 native fit 与 3,046 expanded fit 文件。
- 更早的 v1 尝试在混合上游文件解析到第一条无标签 calibration 布局后 assert
  中止；没有候选产物。中止冻结保存在 `FREEZE_ABORTED_V1.json`，没有与 v1.1
  结果或 QC 盐混用。

机器结果见 `PREPARE.json`、`AUDIT_AUTOMATIC.json`、
`QC_REVIEW_AGENT_SUMMARY.json`；逐条审查保存在 `QC_REVIEW_AGENT.jsonl`。
