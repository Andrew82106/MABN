# Conflict head 目标预算审计

**这是 gold 算术诊断，不是模型成绩。** 只读当前正式 cal159 incumbent 和 expanded-v4 的 fit held-fold-0；未读 official test，未训练/选择模型或阈值，未修改 baseline。

## 结论

- **cal159：冲突专头在数学上足够，但门槛很高。** 必须在当前漏报中独有补回至少 **532 TP**；若只做 EC/SC，这等于补回 829 个冲突 FN 的 **64.17%**，且在最低点最多容忍 **1 个新增 FP**。
- **fit fold0：冲突专头在数学上不够。** 到 F1=.75 至少需独有补回 **2,374 TP**；全部冲突 FN 只有 863 个。即使零 FP 完美修复所有冲突，窗口 F1 也只有 **0.67188**。
- 因此，`.75 window F1` 不能被当作一个“只补冲突”的稳定目标。cal 上可达来自该切分冲突 FN 占比更高；fit fold0 证明它不是跨切分的充分修复集。

## 精确边界

设现有预测与新专头取并集；`x` 是专头命中且 incumbent 未命中的独有 TP，`y` 是新增 FP。命中 incumbent 已抓到的 TP 不改变并集指标。

`F1 >= 3/4` 等价于：

```text
5x - 3y >= 3(2TP + FP + FN) - 8TP
```

| 数据 | 当前 TP / FP / FN | 当前 F1 | 精确条件 | 零 FP 至少独有 TP |
|---|---:|---:|---:|---:|
| cal159 incumbent | 3839 / 1300 / 2145 | 0.69028 | `5x-3y >= 2657` | 532 |
| fit fold0 v4 | 7259 / 4321 / 4475 | 0.62272 | `5x-3y >= 11870` | 2,374 |

Overlap 会让专头单独看的 recall 虚高。例如 cal 冲突最低点需要 532 个独有 TP：若完全不重复 incumbent，专头自身冲突 recall 是 48.23%；若同时重复全部 274 个已有命中，则是 73.07%，但两者给并集带来的收益完全相同。应验收 `miss recall` 和增量 precision，不能只看专头自身 recall。

## Gold conflict oracle 上限与整答影响

Oracle 操作固定为：保留全部现有预测，只把 gold EC/SC 漏报置为正；不删 FP，不补 baseless-only。

| 数据 | 窗口新增TP / FP | 窗口 F1 | 当前整答 TP/FP/FN/F1 | Oracle整答 TP/FP/FN/F1 |
|---|---:|---:|---:|---:|
| cal159 | 829 / 0 | **0.78112** | 90/12/10/0.89109 | 97/12/3/**0.92823** |
| fit0 v4 | 863 / 0 | **0.67188** | 148/47/82/0.69647 | 170/47/60/**0.76063** |

cal 的 35 个 conflict 回答中已有 28 个被整答判正，oracle 只新增 7 个 answer TP；fit0 的 44 个中已有 22 个判正，新增 22 个。整答提升远小于窗口补回数，因为同一回答含多个 conflict 窗口，且部分回答已被其他窗口触发。
