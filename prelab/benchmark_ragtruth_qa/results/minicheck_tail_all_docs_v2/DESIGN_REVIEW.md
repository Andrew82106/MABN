建议改为“全部资料块共同接受原标签”，不能继续默认句级选中的单个块足够。v1 已完成的都是 CPU 原型、梯度与权重检查，没有真实训练；其源码和检查记录保留，`minicheck_tail_v1/STATUS.json` 已标记不启动该单块训练。

Luna §3.2 确实说明资料分块会使支持依据分散。但需准确区分：论文训练时会依据每个窗口实际包含的证据调整逐词元标签；跨窗口逐词元最大支持概率是其推理聚合规则。我们现有 RAGTruth 标注是相对于全部资料的错误范围，缺少逐资料块的支持标注，因此不能声称直接复现了 Luna 的训练流程。[Luna 原文 §3.2](https://aclanthology.org/2025.coling-industry.34.pdf)

可执行的适配是只在聚合后计算原标签损失。对原回答词元 j、资料块 d，先把该块条件下的 MiniCheck token logits 按非空白字符映回原 Llama BPE，得到风险 logit `z[j,d]`；然后：

```
total_risk_logit[j] = min_d z[j,d]
loss = unchanged_weight[j] * BCEWithLogits(total_risk_logit[j], original_risk_label[j])
```

sigmoid 单调，所以这等价于“各块支持概率取最大值”。一份资料支持词元 A、另一份支持词元 B 时，两者可以分别获得支持。没有给任何资料块伪造标签，也不以 gold 决定选哪一块。固定使用按 document_index 排序后的 `torch.min(dim=doc)`，同值取首块；预测与阈值仍只用聚合总风险。

每个真实资料块都必须具备该回答全部 claim 的缓存。先按 `(claim_index, document_index)` 验证完整笛卡尔积，再为每个 doc 单独映射整份回答的字符坐标，最后跨 doc 取 min。不能把某个真实缺缓存的块视作 padding；缺一对就停止。批处理中的虚拟 doc 才能用 `+inf` risk logit 屏蔽。这样也可正确处理一个原 BPE 跨自动分句边界的情况。

这个训练属于只有全资料标签的多实例监督适配：有依据词元由当前最支持它的块获得梯度；幻觉词元则先惩罚当前错误地给予最多支持的块。硬 min 的梯度较稀疏，初始赢家也可能并非真实证据块，不能预先保证效果。该规则表示“存在某块支持”，也不能完整解决必须联合多个块推导才能成立的关系，或资料彼此矛盾的问题。这里修复的是输入范围与监督范围不一致的风险，不是证明原来低 F1 全由该风险造成。

两个对照必须同时改为上述聚合，再比较后两层微调收益：

| 对照 | 输入 | 可训练参数 | 固定预算 |

| 微调最后两层 | 每个 doc 的完整序列 encoder22 入口，重放层22/23和同一 token 头，再同样聚合 | 25,193,473 | GPU，3轮，尾层lr2e-5、头lr1e-4 |

其余预算沿已讨论方案：单 seed 20261004，AdamW weight_decay .01，梯度裁剪1；每次1答、最多2个完整序列，非重入 checkpoint，累积8答。只在原159 cal按既定总风险F1规则选阈值和轮次，不按类型、来源或生成器选。编码器前22层、原生成模型均冻结。冻结缓存对照使用 eval 状态；微调尾层使用原0.1训练 dropout，故对比是实际微调流程的收益，不是对优化机制的唯一因果证明。
