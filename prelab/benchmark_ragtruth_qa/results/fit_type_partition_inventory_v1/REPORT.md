# 原训练词元的两类风险盘点

已核完原 3,680 份 fit 回答：634 个 source_id、615 个资料组。全部类型均来自原人工 span；两类并集与原 binary risk 在 665,708 个 raw BPE 上逐词元完全一致，原 span→token 映射、回答风险及来源组身份也完全一致。没有重标或训练，没有读取 cal/test 原文或标签。

词元共 560,300 个，风险 47,398 个；另有 105,408 个非 lexical raw token，不计作训练负例。四种原类型词元数分别为：显性无依据 30,712、隐性无依据 11,402、显性冲突 4,900、隐性冲突 420。

两类在同一词元上重叠的 36 个位置来自 3 份回答；82 份回答同时含两种风险，不意味着每个风险词元重叠。含冲突的总词元为 5,320，分布于 249 份回答、182 个资料组；含无依据的总词元为 42,114，分布于 960 份回答、450 个资料组。存在不平衡，但这些数量本身不能证明它是主要失败原因。

此前 `type_balanced_v1` 仍只输出一个风险分数：只是提高冲突样本对同一二分类损失的贡献。实际冲突损失质量约从 10,156 提高至 21,701，两个输入的开发窗口 F1 却从 0.6156→0.5956、0.6200→0.6061。因此“提高冲突权重”已经试过，不能作为新方案或承诺。

此前还有原 634 fit 的 `semantic_multitask_v1`：训练时加两个辅助类型头，推理仍只用总风险头。窗口约 0.638→0.641、整答约 0.860→0.857，显性冲突命中反从 273/997 降至 248/997。这说明“有类型辅助监督”也已试过；它没有检验让两个类型输出直接决定最终风险的方案。这里仅引用已完成报告，不重新读取或计算 cal 标签。

可考虑的一项小对照是：待既定 NLI/FAVA 完成，用同一冻结表示训练两个独立二值输出，分别预测无依据、冲突，预先固定总分为两者最大值；两级阈值仍只从这一个总分选。不能用互斥三分类，因为同词元确有两类重叠。与之匹配的容量控制也用两个头，但两头都预测原 binary risk；两边保持输入、训练顺序、原词元权重、平均两项损失及选型预算一致。这样能区别“类型分工”与“仅加头/加容量”，不再同时改变类型权重。

这仍只是未训练候选：分头可能允许不同判断边界，但不会凭空补证据，也可能增加总分误报。风险标签是“未得到给定资料支持”，不等于世界事实必然错误；本盘点没有重新裁定该边界。

逐回答、来源及资料组计数见同目录 JSONL；原标签、坐标、数据和现有模型保持不变。首次只读脚本把 source_id 数误写成组数 615，实际是 634/615，已修正计数断言并保留 `PRE_RUN_FAILURE_01.json` 及修复前脚本/冻结记录；未修改任何输入或映射。
