# FAVA synthetic auxiliary → human QA control

Prepared only. No production model has been fitted and no GPU operation has run in this branch.

Start from the same generic ModernBERT-base initialization and seed 20261005 as the QA-only v2 baseline. Train one complete epoch of the isolated FAVA set, then three complete epochs of the original QA training set. All encoder parameters and the fresh binary token head are trainable. This is an additional semantic detector with synthetic auxiliary supervision, not a probe of the original generator.

The auxiliary input is the five original numbered References, separator, empty question, separator, and original corrupted answer. Its 7,482 answers retain 19,729 exactly aligned synthetic spans. Labels outside those spans are noisy silver negatives; they are not verified true statements. No correction text, edit projection or label type enters the encoder input. The checking-prompt metadata is not an original factual question or native model trace. The frozen tokenizer stage repairs only eight proven consumed combining marks across six answers, without changing original text or gold spans.

Auxiliary loss weights give each of 7,408 material groups equal mass, then divide equally across its answers and lexical raw tokens. Binary class factors are estimated only from auxiliary labels, followed by equal group loss renormalization. Total mass is 854,011. Groups can be linked by distractor references; they are not claims of independent events. The original QA weights, all 3,839 rendered fit/calibration inputs and the first three training orders are reused exactly. The QA loss retains its original/added-answer weighting and mass 560,300.

Each answer contributes `sum(weight × token_BCE) × phase_answer_count / (actual_answers_in_accumulated_batch × phase_mass)`. Effective batch size is 8, with the final auxiliary batch of 2. The same AdamW object continues through the transition: learning rate 1e-5, weight decay .01, gradient clip 1, no scheduler. There are 936 auxiliary updates and 460 per QA epoch, 2,316 total. CUDA forward and checkpoint recomputation use BF16; parameters, gradients, Adam state, logit differences, character mapping and loss remain FP32. No auxiliary calibration, checkpoint selection or optimizer/RNG reset is allowed.

After each QA epoch, save the model, optimizer/RNG state, full fit/calibration predictions and original 4-raw-BPE/answer-max metrics. Select among QA epochs 1–3 using the existing calibration rule: maximize the smaller of the two F1 scores, then window F1, window precision and earlier epoch. Thresholds remain separately calibrated for the two original evaluation units. No official-test answer or label is opened.

The complete budget is 18,522 answer presentations and 11,160,661 logical training input tokens, plus 5,572,614 QA evaluation input tokens. The auxiliary maximum length is 1,481; QA maximum is 979. This is not compute-matched to six QA-only epochs. Wall time, memory and checkpoint recomputation cost must be measured. Before future training, an explicitly scheduled GPU smoke must check the longest full input with a synthetic zero target, repeated inference difference at most 2e-6, finite nonzero gradients and actual memory; a failure is retained without silent truncation or tolerance changes.
