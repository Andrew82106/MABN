# 最终测试解封方案（尚未解封）

本方案只确定身份和执行顺序，不读取测试回答、人工标签、质量字段或预测。身份清单为 [test_release_identity_manifest.json](data/test_release_identity_manifest.json)。

## 哪些来源属于最终测试

- 固定使用现有 `data/source_index.jsonl` 中 `partition=sealed_official_test` 的 **150个官方test source**，对应150个 `llama-2-7b-chat` 原回答，当前归于147个来源关联组。
- 与测试有关联的31个官方train source继续隔离，不加入训练、校准或正式测试分母。其身份保留供隔离审计，不读取其回答/标签来增大测试集。
- 同一source的其他五模型回答不进入本次Llama2结果；它们仍遵循同一分区，不能另拿来训练后再评价同源Llama2回答。
- 当前完成的是来源及已识别关联组隔离，不宣称穷尽全部实体别名和事件关系。部分词面候选未逐对审完，局限见README；不得把结果命名为严格新事件情报泛化。

## 解封前必须固定的开发产物

负责人写入不可变的开发freeze清单，至少包含：793个开发/校准回答及源分组哈希，gold协议/映射/manifest哈希，固定checkpoint、分词器、完整模板、NF4配置与特征代码，最终保留的方法、拟合参数、scaler/PCA等变换和模型文件、校准阈值及选择依据、随机种子、主指标和分组区间算法。所有选择只能来自fit/calibration。

应同时写清最终比较的模型数、整答与4词元定位两项主结果。若比较多个方法，不在test上挑最高者再当唯一预先指定方法。开发达到约0.75不是改变最终test标签或阈值的条件。

当前本方案不是解封授权；根代理确认开发freeze完成后，再启动以下一次性步骤。

## 固定的解封执行顺序

1. 按身份清单及原始文件哈希读取150个source和指定模型原回答，逐条核对ID、模型名、官方split。保留原prompt、3段资料、原回答、完整官方标签和quality，不重生成、不改写，不读取其他模型回答作额外证据。
2. **质量规则沿用开发端：只以官方 `quality == good` 决定主数据资格。** 非good项保留完整排除审计与原始原因。good数量现在未知，不用开发比例猜测；不按有无幻觉、span多少、回答长度或难度重新抽样。
3. 用冻结的分词和回放定义生成test布局；用相同gold算法映射全部四类span（含implicit_true/due_to_null），原字符边界不变。无标签的quality-good拒答保留整答0和可评负窗口；仅无lexical窗口排除。不能套回R16拒答窗口排除口径。
4. 在读取test检测效果前，完成身份、质量、词元/字符覆盖和特征对齐检查。零长度/非alnum span等边界只报告，不自行补标。若有源损坏、固定模型无法处理的长度或缺失特征，记录并停止完整主评分；不临时删题、补0或更换模型。纯实现修复须保留改动与重跑记录，不改变学习结果或阈值。
5. 对全部合格test回答一次性使用已冻结变换、权重和阈值。保存逐token、逐窗口和整答预测，再统一计算结果；test没有fit、阈值选择或候选筛选步骤。

计划输出身份、质量和结果应分开：`test_inputs.jsonl`、`test_quality_excluded.jsonl`、`feature_preparation_test/`、`tokens_test.jsonl`、`windows_k4_test.jsonl`、`windows_excluded_test.jsonl`、`answers_test.jsonl`、test输入/gold/特征冻结清单及最终预测。此处只是文件约定，目前不创建含测试内容的文件。

## 最终报告口径

报告150个原始来源经官方质量过滤后的实际回答数、关联组数、阳性整答/窗口数、无lexical窗口排除量和所有技术缺失；不能只展示高分案例。整答和4个rawBPE滑窗均用校准阶段固定阈值，给TP/FP/FN、precision/recall/F1；区间按关联组重采样，不能把相邻窗口当独立样本。

结果解释区分人工QA基准与R16控制场景：任务、模型、原提示中的拒答指令、回答长度与拒答计分都不同，跨数据F1差不直接证明算法优化或旧标签错误。测试一旦被用于错误分析或方法修改，就登记为已暴露开发材料；后续新方法需要另留独立测试，不继续用这150题反复选最优结果。
